# U51: edits apply without a Keep step

Geno now saves the agent's edits as they are made and offers one Undo per turn, as Claude Code does. The hunk-by-hunk Keep and Undo review of phase 6 is still there, behind a setting.

## What the edits did before

Edits were already on disk before U51. `writeTextFile` in `packages/extension/src/chat/bridge.ts` applies each edit through a `WorkspaceEdit` and saves the document at once. The one exception is a buffer that already had unsaved edits of the user's: the agent's edit joins them there, unsaved. Keep only logged a decision (`_gcode/review`); it never wrote anything. Undo put the hunk's old text back and saved. So the review step was bookkeeping over files that had already changed. Each hunk also got a decoration, a gutter marker and two CodeLens, and stayed `pending` until someone clicked.

## The setting

`gcode.review.mode` takes two values:

| Value | What happens to an edit |
| --- | --- |
| `auto` (default) | It is saved as before. No hunk is tracked, so no decoration, gutter marker, CodeLens or Changes row appears. A finished turn that changed files ends in one line, "N files changed · Undo". |
| `review` | Exactly the phase 6 behavior: Keep and Undo on every hunk, in the editor and in the chat. |

The approval modes (Ask, Auto, Plan) are unchanged. They decide what the agent may do. `gcode.review.mode` decides what happens after it has done it.

Changing the setting takes effect at once. The panel redraws its turns, and the review controller drops its hunks and, in `review`, rebuilds them from the session log. So a switch to `review` puts every edit of the session that was not undone under review, the ones made in `auto` included, since auto logs no decision.

## The turn's line

- **Undo** restores the checkpoint taken before the turn, through the engine's existing `rewindTo`. The engine logs `restored` as it always has, so the hunks of that turn and of every later turn read as undone, live and after a reload. When a later turn also changed files, Undo asks first, because the restore takes those changes back too.
- **A file name** (a chip in compact detail, the file name of an edit card in full detail) opens `vscode.diff` between the file at that checkpoint and the file now. The left side is a read-only `gcode-checkpoint:` document.
- After Undo the line reads "N files changed · Undone".
- History and replay show the same line, since a replayed turn carries the same diffs and statuses.

## Lanes and Arena

A lane's Apply, and an Arena pick, already ran as a chat turn whose writes go through the same bridge. In `auto` they land whole, with the same line and Undo. A conflict still applies nothing and lists each conflicting file in the turn's text, as before. An Arena graft still lets the user tick the hunks to graft. That is a choice of what to bring over, not a review of what landed.

The apply text no longer ends in "Keep or undo each change.", and the lane and Arena copy no longer says "for review". Both hold in either mode.

## Data shapes

- `ReviewMode` (`packages/extension/src/review/mode.ts`): `'auto' | 'review'`.
- `CheckpointRef` (`packages/core/src/review.ts`): `{ before: changeId }`. A change id is the hash of an edit's before and after text, the one name the editor and the engine already share. `checkpointBefore(events, ref)` finds the first checkpoint after the prompt of the latest turn that logged that change, or, for a lane apply, the checkpoint the apply takes just before it writes.
- `TurnChanges` (`packages/extension/src/review/summary.ts`): the files with lines added and removed, the `CheckpointRef`, and `undone`.
- The Undo request: the webview posts `{ type: 'undo-turn', checkpoint, later }`. The extension sends `_gcode/rewind { sessionId, before }`. `_gcode/checkpointText` takes the same optional `before`. Without `before`, both mean the session's first checkpoint, as Undo all always did.

The chat's edit controls are one table, `CONTROLS` in `packages/extension/src/chat/render.ts`, keyed by `ReviewMode`. It says what each hunk shows, what the pending hunks of a turn offer, and where a file name opens.

## Decisions

- Undo takes the engine's checkpoint, not text the extension kept, so it survives a reload and restores what bash commands changed in the turn as well as the edits.
- An edit into a buffer with the user's unsaved text still stays unsaved, as before. Saving it would write the user's own unsaved text without asking. Checkpoints snapshot the disk, so that buffer is the one case Undo does not cover.
- The turn's line counts only the turn's own edits. Edits a subagent made show under the subagent. The parent's Undo restores the workspace, so it takes those back too.
- A change id names a turn. If a later turn makes exactly the same edit, for example one redone after an Undo, the id names the later turn.
- The engine gained only an optional `before` on two existing methods. `rewind.ts` and `checkpoints.ts` are untouched, which leaves them to U50.

## Tests

- `packages/extension/test/auto-review.integration.test.ts`, with no review setting, so on the default. One turn edits `a.ts` and `b.ts`. The test checks there are no CodeLens, no decorations and no dirty buffers, and that the disk holds the edits. It checks the line reads "2 files changed · Undo", the file chip opens the checkpoint diff, and Undo restores both files byte for byte. A lane Apply lands whole with "1 file changed · Undo", and its Undo takes it back. As a control, the test switches to `review` and the same probes find the lenses and decorations, and switching back clears them. A reload then shows every turn's line, Undone where it was undone, and no lens comes back.
- The review, panel, arena, lanes and backends suites run under `gcode.review.mode: "review"`, with their assertions unchanged.
- Unit tests cover `checkpointBefore`, `turnChangesOf`, and the engine serving and rewinding to a turn's checkpoint.
