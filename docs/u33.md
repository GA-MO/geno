# U33 and U15: external ACP agents as backends

A Geno session can now run on another coding agent instead of Geno's own loop. Cursor is the first backend, through its `agent acp`. Claude Code is the second, through its ACP adapter, which this machine does not have, so its row says how to get it. Geno is the ACP client toward the agent and stays the ACP server toward its panel. The panel talks only to Geno's engine, so lanes, tasks, approvals, history and the Arena work as they do for Geno's own sessions.

The briefs are the U15 and U33 entries of `research/competitors-2026-10.md` section 5, `research/cursor-backend-2026-10.md` and section 5.3 of `research/t3code-2026-10.md`.

## Data shape

`packages/core/src/backends.ts` holds the registry, the binding, the translated events, model detection and the panel protocol. `packages/core/src/backend-permissions.ts` holds the permission table; it is a file of its own so the webview, which bundles `backends.ts`, gets no `node:path`.

- **Registry.** `EXTERNAL_BACKENDS` has one `ExternalBackend` per id: `label`, `plan` (what the cost slot says), `mention` (the `@` name), `binaries`, `args`, `keyEnv`, `install` and `sandbox`. `sandbox` holds the hosts the agent needs, the paths under home it writes its state to, and the arguments that turn its own sandbox off. Undefined means it has not been shown to run inside Geno's sandbox.

  | Id | Command | Key variable | Sandbox |
  | --- | --- | --- | --- |
  | `cursor` | `agent acp` (or `cursor-agent acp`) | `CURSOR_API_KEY` | `*.cursor.sh`; writes `~/.cursor/{projects,acp-sessions,ai-tracking,plans,agents,workers}`, `statsig-cache.json`, `agent-cli-state.json`; runs with `--sandbox disabled` |
  | `claude-code` | `claude-agent-acp` (or `claude-code-acp`) | `ANTHROPIC_API_KEY` | none measured, so it runs in its lane unsandboxed |

- **Binding.** `Session.backend` is `{ id }`, fixed when the session starts. A session without it runs Geno's loop. Two new log events record what the agent did: `backend-start` (`agentSessionId`, `lane`, `sandboxed`, `loadable`) each time an agent session opens, and `backend-model` each time the user picks one of the agent's models. Neither is part of the conversation Geno replays to a model.
- **Availability.** `BackendAvailability` is `ready` with the path, or `missing` with the reason. The engine looks on PATH, in `~/.local/bin`, in Homebrew's folders and in npm's global bin folders (`NPM_CONFIG_PREFIX`, `NVM_BIN`, `~/.npm-global/bin`). It runs nothing to find them.

### Translated events

An agent's `session/update` becomes Geno's own log events, so the rail, the IN/OUT boxes, the dino's poses, replay, tasks and history read an external turn like any other.

| Agent sends | Geno logs | The panel gets |
| --- | --- | --- |
| `agent_message_chunk` text | kept, then logged with the next tool call or at the end, in an `assistant` event | the chunk, live |
| `tool_call` | an `assistant` event with one `tool_use`, named and shaped as Geno's tool (table below) | `tool_call` titled `<tool> <target>` with the ACP kind |
| `tool_call_update` with content | the output, kept for the result | nothing until the end |
| `tool_call_update` `completed` or `failed` | a `tool-result`, `ok` or `error`, `denied` when Geno refused it, with the approval record | the closing update, with `gcode/approval` |
| `usage_update` with a USD cost | the cost, on the turn's last `assistant` event | the turn's usage |
| `config_option_update` of the model | the current model | nothing |
| anything else (thoughts, plans, commands, mode updates) | nothing | nothing |
| the turn ends | a last `assistant` event with the text, `end_turn` | the prompt response with `gcode/usage` `{ model, costUsd, backend }` |

| ACP kind | Geno step | Logged input | Panel kind | Access |
| --- | --- | --- | --- | --- |
| `read` | `read` | `{ path }` | read | read |
| `search` | `grep` | `{ pattern }` (the title) | search | read |
| `think` | `think` | `{ title }` | other | read |
| `edit`, `delete`, `move` | `edit` | `{ path }` | edit | write |
| `execute` | `bash` | `{ command }` | execute | command |
| `fetch` | `fetch` | `{ title }` | other | other |
| `switch_mode`, `other`, unknown | `tool` | `{ title }` | other | other |

Paths come from the call's first location, then `rawInput.path` or `file_path`, relative to the lane. An edit's tool result carries no `FileChange`: the agent's edits are in its lane, and they reach review only through Apply.

### Permissions

`session/request_permission` goes through Geno's approval modes. `externalDenialFor` reads the table, and `settle` (U17's) does the rest, so Auto keeps its 3-in-a-row and 20-total pause.

| Access | Plan | Ask | Auto | Non-interactive |
| --- | --- | --- | --- | --- |
| read inside the lane | allow | ask the user | allow | allow |
| write | refuse | ask the user | classifier | refuse |
| command | refuse | ask the user | Geno's command rules first: a safe command runs, `rm -rf` outside asks, a gray one goes to the classifier | refuse |
| other, or a read outside the lane | refuse | ask the user | classifier | refuse |

In Auto, a classifier `ask` blocks the call and counts toward the pause, exactly as for Geno's own commands. The classifier sees a command as a command, and any other call as an MCP-style call with the agent's label, the ACP kind and the raw input.

`externalAnswer` turns the verdict into the agent's option. Allow picks the `allow_once` option. Deny picks `reject_once`. With no once option the request is cancelled. Geno never picks an `_always` option, which would change the agent's own saved permissions. The card the user sees offers only Allow once and Reject.

### Models and modes

Everything is feature-detected from `session/new` by `agentSetupOf`. Two Cursor builds on this Mac differ, and both are recorded in the unit tests:

| Build | Models in | Approval modes | `loadSession` |
| --- | --- | --- | --- |
| 2026.01.23 (the research appendix) | `modes`, about 245 model ids, no plan mode | none | false |
| 2026.10.01 (now installed) | a `model` config option and ACP's `models` field, 43 models, default `default[]` named Auto | a `mode` config option: `agent`, `plan`, `ask` | true |

A model config option wins, then the `models` field (`session/set_model`), then modes that carry models (`session/set_mode`). Geno keeps its own Plan, Ask and Auto. It sets the agent's mode from them when the agent has approval modes: Plan to `plan`, Ask and Auto to its build mode (`agent`). The session lists the agent's models as one `model` select option, which the composer's menu reads.

### Panel protocol

| Method or key | Does |
| --- | --- |
| `_gcode/backends` | The registry with what the engine found for each. |
| `session/new` `_meta["gcode/backend"]` `{ id }` | Starts the session on that backend. A missing one is refused before anything is written. |
| response `_meta["gcode/backend"]` | `{ id, label, plan, lane }` on new, load and resume; a `session_info_update` repeats it once the first turn has made the lane. |
| `session/set_config_option` `model` | Picks one of the agent's models; an id it does not offer is refused. |
| `_gcode/backendEnv` (engine to editor) | Asked before an agent starts, when the editor advertises `gcode/backendEnv`. Only the backend's `keyEnv` is taken from the answer. |
| `TaskRecord.backend`, `lane` | The Tasks pane names the backend and the lane. |

## Where it runs

`packages/engine/src/external.ts` runs the turn, `backends.ts` starts the process, and `sandbox-host.ts` holds the sandbox around it.

- **One process per session.** `ExternalAgents` keeps each session's agent across turns, because the agent's conversation lives in its process. At `session/new` the engine starts the agent and reads its models from a probe session in an empty temp folder, away from the user's files.
- **A lane by default.** The first turn makes a lane named from the prompt and binds it to the chat. Every later turn, and a restarted agent, works in the same lane. A session whose workspace is already a lane, such as an Arena lane, runs there. A workspace that is not a git checkout is refused with the reason. The edits come back through Apply, as a `gcode/laneApply` turn of the same chat; Apply now lets a chat apply its own lane.
- **Cancel.** Geno's `session/cancel` sends the agent's `session/cancel`. A permission question still waiting is answered cancelled. If the agent does not end its turn within 5 seconds, its process is killed.
- **Crash.** When the process dies, the turn ends with "Cursor stopped: its process exited with code N" and the end of its stderr. The next turn starts it again. A `loadable` agent loads its earlier session; otherwise the turn says it starts a new one in the same lane.

### Sandbox findings

Measured on this Mac with Cursor 2026.10.01, using `initialize` and `session/new` only (`scratchpad/u33/probe.mts`), and with the fake agent in `backend.e2e.test.ts`:

- Cursor starts and answers `session/new` inside Geno's sandbox (sandbox-runtime, Seatbelt) when `*.cursor.sh` is allowed. With no host allowed, `session/new` fails ("Failed to initialize session services"), so the allowlist is what reaches Cursor's servers.
- Cursor must write its state under `~/.cursor`. With all of `~/.cursor` read-only it fails at start (`EPERM ... mkdir ~/.cursor/projects/...`). The list above is the smallest set that worked. `cli-config.json`, `mcp.json`, `sandbox-policies` and the plugin and skill folders stay read-only, so the agent cannot widen its own permissions.
- It prints "failed to copy trust settings of system certificate" many times on stderr and goes on.
- A second Seatbelt profile cannot start inside Geno's: `sandbox-exec` in the sandbox fails with `sandbox_apply: Operation not permitted`. So Geno starts Cursor with `--sandbox disabled`, and Geno's sandbox is the wall. Cursor accepts the flag before `acp`. Whether its commands then run and ask as expected needs a prompt; that is the live smoke's third prompt.
- sandbox-runtime keeps one network allowlist per process, and Geno's own sandbox allows none. The agent's sandbox therefore runs in a process of its own, `sandbox-host`, beside the engine (built as `dist/engine/sandbox-host.js`).
- The sandbox's rules are fixed when it starts. An agent started for the probe, before its lane existed, starts again with the lane writable on the first turn. Its TMPDIR is its own temp folder, and the user's temp folder is not writable.
- The e2e test runs the fake agent in this sandbox: it writes in its lane, and a write into the main checkout fails.
- `GCODE_BACKEND_SANDBOX=off` runs agents unsandboxed in their lane. Claude Code's adapter has no measured sandbox entry, so it always runs that way.

## Subagents and the Arena

- `@cursor <task>` and `@claude-code <task>` are built-in agents (`BUILTIN_AGENTS`), writers that run one at a time. A definition file can say `backend: cursor`; `geno` means Geno's loop, and an unknown name is a note. The child runs `runExternalTurn` in its own session and a lane named from the task. Its report is fenced as any child's, says which lane holds the edits, and shows cost as unknown, not zero. The child's process ends with it.
- An Arena variant can name a backend in `.gcode.json`: `{ "arena": { "variants": [{ "seed": "plain" }, { "seed": "plain", "backend": "cursor", "model": "composer-2.5[fast=true]" }] } }`. That lane's session starts on Cursor with that model. The check, the ranking and the compare are unchanged.

## Claude Code's adapter

The ACP registry lists `claude-acp`, "ACP wrapper for Anthropic's Claude", version 0.86.0, authors Anthropic, Zed Industries and JetBrains, distributed as the npm package `@agentclientprotocol/claude-agent-acp` (it was `@zed-industries/claude-code-acp`). It is not installed here, and running it through `npx` would install it, so Geno does not. The backend row stays, marked missing with the install command. Once `claude-agent-acp` is on PATH, the same `AcpBackend` drives it. It needed no dependency in Geno. Claude Code's `claude` 2.1.291 is installed and signed in; the Agents card now shows it (below).

## In the panel

- **Backend picker.** The composer's model menu opens with a Backend section: Geno, Cursor and Claude Code. A missing backend is shown but inert, with its reason. Choosing another backend starts a new chat on it, and the row says so. In an external chat, the Model section lists the agent's own models and sets them through the `model` config option; there is no effort section. Below 360px the model button drops the backend's name and keeps the model's.
- **Turns.** The head reads "Geno" with a "Cursor" chip. The footer shows the agent's model and, when it reports no price, "Cursor plan" in the cost slot, with no token counts. After a turn that edited files in the lane, the turn offers "Apply changes from lane <name>", which sends the same apply turn the Lanes pane does.
- **Permission card.** An agent's question about an edit reads "Change this file?", one about a command "Run this command?". Both offer Allow (once) and Deny only.
- **Tasks.** A row names the backend in a chip and its lane, "New lane" until the first turn makes one.
- **Keys.** The extension answers `_gcode/backendEnv` from SecretStorage: `gcode.agents.cursor.apiKey` as `CURSOR_API_KEY`, `gcode.agents.claude-code.apiKey` as `ANTHROPIC_API_KEY`. The key never reaches the webview or the log.

Files: `backend-model.ts` (the menu's view model), `backends-host.ts`, `backends.css`, and small hooks in `composer-*.ts`, `chat.ts`, `render.ts`, `transcript.ts`, `messages.ts`, `lanes-*.ts`, `engine.ts` and `webview.ts`.

Media in `docs/media/u33/`, taken in the container: `backends-model-menu`, `backends-cursor-turn` and `backends-tasks`, each in `-dark`, `-light` and `-high-contrast`, at 420px and at 300px (`-300`), and the Claude Code card (`agents-claude-*`).

## Making Cursor ask

Cursor decides whether to ask from its approval mode. Its documented modes are `allowlist`, `auto-review` and `unrestricted`, set by `approvalMode` in `~/.cursor/cli-config.json` (https://cursor.com/docs/cli/reference/configuration). That key is global only: a project's `.cursor/cli.json` takes only `permissions.allow` and `permissions.deny`, where a deny refuses rather than asks. `agent --help` offers `--auto-review` (a server classifier runs what it thinks safe), `--force`/`--yolo` (run everything), and no flag for `allowlist`. ACP itself offers only the `agent`, `plan` and `ask` modes. The smoke's silence fits `auto-review` or `unrestricted`; Geno did not read the user's config to say which.

So Geno starts Cursor with `HOME` set to an overlay home of its own (`overlayHome` in `packages/engine/src/backends.ts`), in the agent's temp folder:

- Every entry of the user's home is linked in, and so is every entry of `~/.cursor`, except `cli-config.json`.
- In its place Geno writes `{ "version": 1, "editor": { "vimMode": false }, "permissions": { "allow": [], "deny": [] }, "approvalMode": "allowlist" }`: allowlist mode with an empty allowlist, so every command and edit asks.
- Only entry names are read. The user's own `cli-config.json` is never read, linked or changed, and a project's `.cursor/cli.json` still applies on top.
- Measured with `initialize` and `session/new` only: Cursor signs in through the overlay (the login is not in `cli-config.json`), offers its 43 models, and writes two state files into the overlay. With an empty `HOME` instead, `session/new` fails with "Authentication required".
- In the sandbox the overlay is in the agent's writable temp folder. The links lead where the sandbox allows, and reads of the credential folders stay denied, since Seatbelt checks the resolved path.

All three of Geno's modes run Cursor this way, so Cursor always asks, and Geno answers by its own mode: Ask shows the card, Auto lets the classifier answer, Plan refuses writes and also sets Cursor's own `plan` mode. The registry row's `ask` field holds the file and its contents; Claude Code's adapter asks through ACP by default and has none.

`fake-acp-agent.ts` now behaves like Cursor here: it reads `$HOME/.cursor/cli-config.json` and sends `session/request_permission` only under `allowlist`, running the tool unasked otherwise. `backend.e2e.test.ts` gives the test home a user config of `unrestricted` with `Shell(*)` allowed, and checks that the agent saw `allowlist` from another HOME, that every ask step asked, and that the user's file is byte for byte unchanged. With the overlay turned off, two of the tests fail.

Not yet confirmed live: that Cursor 2026.10.01 honours `approvalMode: allowlist` over ACP, and that it asks for edits as well as commands. The confirmation is one prompt after merge, from the same smoke script: prompt 2, "Add the line `export const four = 4;` at the end of a.ts. Change nothing else." It should print one `Allow ... edit ...` question with `allow_once` among its options. If Cursor asks only for commands under allowlist, the edit stays gated by the lane and Apply, and this doc must say so.

## Live smoke (run by the coordinator with the user's approval, 2026-10-06)

`GCODE_LIVE_CURSOR=1 pnpm tsx packages/engine/test/backend-smoke.ts` with Cursor CLI 2026.10.01-e373342, signed in, Auto model, in a lane of a temp git repo, inside Geno's sandbox. Three prompts, then a free Apply:

| Prompt | Steps Cursor ran | Answer | Time |
| --- | --- | --- | --- |
| List the files in this folder. Do not change anything. | `bash ls -la` (execute) | `.git`, `README.md`, `a.ts` | 79.7 s (first call, includes start-up) |
| Add the line `export const four = 4;` at the end of a.ts. Change nothing else. | read a.ts, Edit File (edit) | "Added `export const four = 4;` at the end of `a.ts`." | 12.3 s |
| Run `ls -la` in a terminal and tell me only the first line of its output. | `bash ls -la` (execute) | `total 24` | 6.6 s |

- 43 models were offered through the config option; the current one was `default[]` (Auto).
- Usage came back as `{"model":"Auto","costUsd":null}`, so the panel shows "Cursor plan".
- Apply wrote `a.ts` in the main checkout, which then held exactly the four lines.
- **Gap found: no permission was asked.** The session ran in Geno's Ask mode, yet Cursor ran `ls -la` and edited `a.ts` without one `session/request_permission`. Cursor's own approval mode decided, so Geno's Ask and Auto gated only what Cursor chose to ask. The lane and Geno's sandbox still held the edit until Apply. Fixed since; see "Making Cursor ask".
- Cosmetic, fixed since: tool call ids carried a newline (Geno now gives such a call an `ext_<hash>` id of its own), and the smoke printed the Apply path relative across `/private/var` and `/var` (the smoke now resolves its temp folder).

## Deferred

- Mentions and attachments are refused in an external session; the agent gets the prompt's text only.
- The agent's own thoughts, plans and slash commands are not shown.
- Cursor lanes are not capped at one, and nothing warns before a parallel Arena spends the plan.
- The overlay home and probe folders an agent leaves in the temp folder are not removed when it exits.
- `session/load` is used only after a crash or engine restart, and only when the agent says it can.
