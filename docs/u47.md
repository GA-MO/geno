# U47: context compaction

Before U47, a session whose context filled the model's window failed with an `overflow` error, and the context ring told the user to start a new chat. Now Geno summarizes the older turns and goes on, as Claude Code does. It does this on its own before a model call that would pass 80% of the window, once after a call the provider refuses as too long, and when the user asks with `/compact` or the ring's Compact action. The brief is the U47 line of "Harness ideas" in [plan-u19-on.md](plan-u19-on.md), with Pi's cut rule and summary sections from P4 in [plan-next.md](plan-next.md).

## Data shape

`packages/core/src/compact.ts` names it, with types and pure functions only, so the webview can import its types.

- **The compaction event.** `CompactEvent` is one line appended to the session log:
  - `trigger` is `auto`, `overflow` or `manual`.
  - `keptFrom` is the seq of the first event the model still reads as it was. The summary stands for every conversation event before it.
  - `summary` is the model's text, with the sections Goal, Progress (Done, In progress, Blocked), Decisions and Next steps. `focus` is the text after `/compact`.
  - `kept` is what the compaction carries word for word, as of its cut: the user's own messages and the parent agent's steers (`KeptMessage`, newest first within 40,000 characters, each cut at 8,000), the todo list, the definitions `tool_search` loaded, and the files read and changed.
  - `tokensBefore` is the context before: the last call's measured usage plus an estimate of what was queued after it. `tokensAfter` is an estimate until the next call measures it.
  - `usage`, `costUsd` and `model` are the summary call's own spend.
- **The context view.** `contextView(events)` is what the model's context is built from. Without a compaction it is every event. With one it is the session start, the latest compaction, then every event from `keptFrom` on, without earlier compactions. `replayMessages` builds the request from this view and renders the compaction with `compactedText`, which opens the first user message after the loaded project instructions. The log itself never changes.
- **The ACP mark.** The engine sends a compaction as an `agent_message_chunk` whose `_meta["gcode/compact"]` is a `CompactMark` (`seq`, `trigger`, `tokensBefore`, `tokensAfter`, `summary`, `files`, `focus`). Its text says the same in words, for a client that does not read the mark.

`packages/core/src/compaction.ts` holds the rules, also pure:

- **The cut.** `planCompaction(events, keepTokens)` cuts the context view at a prompt, a steer or a model turn. It never cuts between a tool call and its result: no result at or after the cut answers a call made before it. At least one model turn must lie between the previous compaction and the cut. Of the cuts whose tail is at most `keepTokens`, the oldest wins, keeping the most; when none fits, the newest. A cut inside a long turn is allowed, so a turn of 50 tool rounds can still compact. The turn's prompt is then kept in `kept.messages`.
- **What is kept.** `keptOf(view)` folds over a context view, starting from the kept state of the compaction the view opens with. A second compaction so carries the first one's messages, list, tools and files on.
- **When to compact on its own.** `autoCompaction(events, compactAt)` returns the plan to run before the next call, or nothing. It runs when the context would reach `compactAt` tokens, a model call ran since the last compaction, and the plan would bring the context back under `compactAt` (`plannedTokens`, with a 2,000-token guess for the summary).
- **The thresholds.** `COMPACT_AT` is 0.8 of the window. `compactAtTokens(window, setting)` gives the token count. `KEEP_TAIL_TOKENS` is 20,000, Pi's default, or a quarter of the threshold on a small window (`keepTailTokens`).
- **The summary request.** `summaryPrompt(plan, focus)` is one user message: the summarized region as a transcript (`transcriptOf`), then the instructions. `SUMMARY_SYSTEM` is the call's own system prompt, which says the transcript is data.
- **Token estimates.** `eventTokens` estimates each event at 3.5 characters a token (`CHARS_PER_TOKEN`, from U46) and 1,600 tokens an image. `contextTokens` adds the newest measured usage to the estimate of what came after it.

`spendOf(event)` in `session.ts` is the one place that says which events cost money: a model turn and a compaction. The session cost in History, the turn's usage in a replay, the CLI totals, the panel's turn cost and the run's `--max-cost` budget all read it. A compaction counts toward the budget and not toward `--max-turns`.

## Decisions

| Question | Choice | Why |
| --- | --- | --- |
| Where the summary lives | In the log as an event; the context is a view over the log | Rewind and fork already work on the whole log through `cutView`. A cut before the compaction drops it (`KEPT_BY_CUT`), so the context is rebuilt from the full history with no new rule. |
| Which events stay word for word | The user's own messages and steers, the parent's steers, the todo list, loaded tool definitions, the files touched | The user's text is the one trusted instruction (`isUsersOwn`), so a summary must not paraphrase it. The todo list and the tools are state the model acts on. Memory and the system prompt are outside the messages, so a compaction never touches them. A child's report and a wake notice are data, so the summary covers them. |
| Kept state: frozen in the event or derived at render | Frozen in `kept` | The view replaces the events before `keptFrom`, so a later render could not see them. A fold that starts from the previous `kept` makes the second compaction correct with no look back. |
| The summary call's shape | A fixed system prompt, no tools, the region as a transcript | A call with the agent's tools could answer with a tool call. The transcript also lets Geno cut results to fit a budget. The cost is no cache hit on the agent's prefix. |
| Cutting tool results | Whole while the transcript fits 60,000 tokens (`SUMMARY_INPUT_CHARS`); past that, the longest first, never under 3,000 characters | A first version cut every result to 2,000 characters. The live summary then said the deadlines in a 23 KB read were still unread. Whole results fixed it. The budget bounds a summary call at about $0.01 on `qwen3.8-flash`. |
| Auto compaction that cannot help | Skipped | A live run with a 5,000-token threshold compacted before every call: the system prompt and tools alone were about 3,900 tokens, so no cut got under it, and each call paid for a summary. |
| Threshold setting | `GCODE_COMPACT_AT` (tokens) | `qwen3.8-flash` has a 1,000,000-token window, so 80% is 800,000 tokens a call. A cost-conscious user may want it lower. A model with no known window compacts only on overflow or `/compact`. |
| `/compact` | An engine built-in that holds the session's turn lock | No prompt starts while the summary is written, and Stop stops it. It runs no agent turn. A replay shows it as its own turn, as live, with no seq, so it has no rewind menu. |
| Overflow | Compact once, retry once, and log no error when the retry works | A second refusal is logged as `overflow`, as before. A first turn has nothing to cut, so it fails as before. |

## In the engine

- `packages/engine/src/compact.ts`: `compactAtOf(env, session)` reads `GCODE_COMPACT_AT`. `compactContext(gateway, session, events, request)` plans the cut (or takes the caller's plan), makes the summary call through the session's own gateway, model and effort, and returns the event to log. It logs nothing, and a failed call changes nothing.
- `drive.ts`: before each model call, `autoCompaction` decides, and the compaction is logged before the checkpoint and the call. A call that fails with `overflow` compacts and goes again once. `Watcher.compacting` lets the editor show "Compacting the context" while the summary is written.
- `serve.ts`: a compaction logged in a turn goes to the editor as the divider chunk and a `usage_update` with `tokensAfter`, so the ring drops at once. Its spend joins the turn's usage. `/compact [focus]` runs `compactBetweenTurns`, which replies "Nothing to compact yet" when no cut summarizes anything, and refuses while a turn runs.
- `session-replay.ts`: `compactUpdate` replays each compaction where it was logged. A manual one is a turn of its own, with the prompt `/compact <focus>` and the command chip.
- `sessions.ts`: the log schema accepts `compact`. `gcode show` prints it with its summary.

## Tests

- `packages/core/test/compaction.test.ts`, 31 tests:
  - The cut lands on the model turn whose call the tail answers, and every `tool_result` in the rebuilt request follows its `tool_use`. A steer between a call and its result is never a cut point. The oldest fitting cut wins, and the newest when none fits. A one-turn session has nothing to cut.
  - The user's prompts, the user's steer and the parent's steer are kept word for word, and a child's report is not. The todo list, the loaded tool's definition and the files read and changed are kept, and the tool stays loaded.
  - The view after a compaction is the start, the compaction, then the tail, and is its own view. The request opens with the project instructions and the compacted text, then the kept turns as they were. A JSON round trip of the log, as a resume reads it, gives the same request.
  - A second compaction reads the first one's summary, carries its kept state on, and replaces it. A compaction logged mid-turn that the next one's cut passes over is left out of the context.
  - A rewind to a turn before the compaction rebuilds from the whole log. A fork after it copies it.
  - The threshold, the setting, the kept tail on a small window, the skip when a cut cannot get under the threshold, and one compaction per model call.
  - The summary call's cost counts in the session cost and the budget, not in the turns.
  - The transcript keeps results whole while it fits, cuts the longest first past the budget, and keeps an earlier compacted context at the top. The focus reaches the prompt.
- `packages/engine/test/compact.e2e.test.ts`, through `gcode serve` with a fake model:
  - Auto: with `GCODE_COMPACT_AT=8000`, a turn reads a 20 KB file, and the next turn's second call passes the threshold. The summary call has `SUMMARY_SYSTEM`, no tools and the session's model, and reads the file. The call after it carries the compacted text and no longer the file, and the turn ends normally. The editor gets the divider and a `usage_update` with `tokensAfter`. After a new engine process loads the session, the divider replays and the next request is built from the compaction.
  - `/compact keep the parser notes` sends the focus, reads the first summary, reports its usage in the prompt response, and replays as its own turn. The next request carries only the second summary. A conversation rewind to the turn before both compactions rebuilds from the whole log, while the file keeps both compaction lines.
  - Overflow: a refused call compacts and goes again, and logs no error. A second refusal after a compaction is not retried again.
  - A refused first call has nothing to compact and logs `overflow`. `/compact` then says "Nothing to compact yet" with no model call.
- `packages/engine/test/compact.test.ts`: the default threshold, an unknown window, the setting, and a bad setting.
- Each test was checked against a defect put in on purpose: the pair rule removed, the parent's steer dropped, the compaction's spend left out, the view turned off, the once-per-call guard removed, the todo list or the tools not kept, the cut keeping the compaction, the newest cut instead of the oldest, the earlier compaction left in the view, no auto compaction, no overflow retry, a second overflow retry, no live divider, no replayed divider, and `/compact` replayed inside the previous turn. Each one failed a test.

## Live smoke

`pnpm tsx packages/engine/test/compact-smoke.ts` runs `qwen3.8-flash` on Model Studio through serve, with `GCODE_COMPACT_AT=9000` and a 23 KB `notes.md` that holds three dated deadlines. The model reads the notes and lists the deadlines, then reads `config.md` for the port. The user sends `/compact keep the deadlines and the port`. A new engine process loads the session, and the user asks for the deadlines and the port without reading a file again. It passes when Geno compacted on its own, the next call read less, `/compact` was logged, the answer has the three dates and the port, and no tool was called for it.

The last run, on 2026-10-07, passed. The auto compaction ran before the second turn's first call and kept from the first turn's answer, so the reads of the notes went into the summary. The context was 12,286 tokens before (the last call's measured context and answer, plus the prompt queued after it; that call read 11,752), about 5,158 after by the estimate, and the next call measured 5,088. The summary kept the three deadlines and the port. The answer after the reload was "Beta ships: 2026-11-03, Docs freeze: 2026-11-17, 1.0 ships: 2026-12-01, Dev server port: 4317", with no tool call. The editor got both dividers live and both again on the reload. The run cost $0.0127 by the engine's estimate. The five runs of U47 cost $0.0478 together, under the $0.10 cap. The estimates price cache reads at the full input rate (U19), so the bill is lower.

The two earlier runs showed the problems that two decisions above fix: the cut results, and the compaction before every call.

## Deferred

- A summary call that returns no text still cost money, and nothing logs that cost.
- The summary call does not reuse the agent's cached prefix. On a large compaction a call through the agent's own tools and messages would read mostly from the cache. It needs `tool_choice: none`, or a check that Model Studio accepts history with tool calls and no tools.
- `GCODE_COMPACT_AT` is an environment variable only. A setting in the settings page would suit this user better.
- The summary records what the agent said as well as what it did. In a live run `qwen3.8-flash` invented a request to follow an `AGENTS.md` in a folder that did not exist, and the summary repeated that as something the user asked. The user's own messages are kept word for word next to it, so the model can tell them apart, but the summary does not.
- `tokensAfter` is an estimate at 3.5 characters a token. In the live run it was 1.4% over the next call's measurement. The ring shows it until that call.
