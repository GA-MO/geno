# U38: ask_user v2, several questions in one card

`ask_user` now asks one to four questions in one card. Each question is a tab. Each option has a title, a description, an optional "Recommended" tag and an optional preview. Every question also offers Other, for an answer in the user's own words. One Submit answers sends every answer, and Esc or Skip declines the card. The brief is the U38 section of `docs/plan-u19-on.md`.

## Data shape

`packages/core/src/ask-user.ts` names it.

- `AskUserRequest` is `{ questions }`, one to four `AskUserQuestion`s: `{ id, header, question, multiSelect, options }`. The header is the tab label, 12 characters or fewer. Each question has two to four `AskUserOption`s: `{ label, description, recommended?, preview? }`. A preview is short markdown or a code block, 2,000 characters at most.
- `AskUserAnswer` is `answered`, with a `QuestionAnswer` per question id (`{ picked, other? }`: the labels picked, and the user's own words under Other), or `declined`. `AskUserReply` adds `unshown`, for an editor that could not show the form.
- `parseAskUser(raw, source)` is the one validator. The model's input (`source` `model`) must hold every limit, may recommend at most one option per question, and must not list Other. The message names the question and option at fault, such as `question 1, option 2 is "Other". Do not list Other: the card always offers it`. The engine's executor runs it, so the model reads that message as the tool error.
- U13's `{ question, options? }` still parses, as one question with the id `choice`, the header "Question", and bare labels. Older calls and session logs keep working, and a U13-style answer `{ choice: "SQLite" }` still maps.
- The editor reads the engine's copy of the request with `source` `wire`, which allows that U13 shape: bare labels, and zero to six of them.

## ACP mapping

The channel is still ACP `elicitation/create` in form mode, scoped to the session and the tool call. The installed SDK's form schema has primitive properties only: a string with `oneOf` of `{ const, title, description }` for a single choice, and an array whose `items.anyOf` lists the same for several. `askUserForm` maps each question onto it as far as it allows:

| Request | Form |
| --- | --- |
| question id | the property key |
| header | the property `title` |
| question text | the property `description` |
| single-select | `type: "string"` with `oneOf` |
| multi-select | `type: "array"` with `items.anyOf` |
| option label | `const`, and the `title` |
| option description | the option's `description` |
| recommended | " (Recommended)" appended to the option's `title` |
| Other | a string property `<id>.other` |
| preview | no place in a form |

The elicitation's `message` is the question, or "Geno has 3 questions: Button, Targets, Layout". The answer is the form content: a label, or a list of labels, under the question id, and the user's words under `<id>.other`. `askUserAnswerOf` keeps only labels the question offered.

`_meta["gcode/ask_user"]` carries the request itself. A form cannot carry previews, cannot say which Other field belongs to which question, and does not promise the order of its properties. Geno's panel reads the request from `_meta` with the same parser the engine runs on the model's input, so there is no inverse mapping to drift. Another ACP client gets a working form from the schema alone.

When the editor advertises forms but the request fails, the engine treats the form as unshown. The tool result then tells the model to end its turn and ask in plain text, and gives it the questions and options as numbered text (`askUserText`). The user answers in the next prompt. A client without `elicitation.form` is still never offered `ask_user`, as in U13.

## What the user sees

- **Tabs.** A row of question headers, with a green dot on each answered tab. A card with one question has no tab row.
- **Options.** The question, then the options as rows: a radio or checkbox, the number key, the title, a quiet "Recommended" tag, and the description under it.
- **Other.** The last row is Other, a text field. Typing in it chooses Other. In a single-select it replaces the option picked; in a multi-select it adds to them.
- **Preview.** The focused option's preview shows beside the list when the card is 460 pixels wide or more, and below it otherwise. It goes through the panel's markdown renderer, which builds every node as text, so model-written markup shows as text. The CSP is unchanged.
- **Actions.** Submit answers is enabled once every question has an answer. Skip and Esc decline. A hint line names the keys.
- **Folded turns.** While it waits, the card is a permission-style attention item, so U17 keeps it in view. Answered, a compact turn shows it as one line, "Answered 3 questions: Button, Targets, Layout", or "Answered: SQLite" for one question. A skipped card shows "Skipped". Opening the turn lists each question with its answer.

## Keyboard

The map is `onKey` in `packages/extension/src/chat/question-model.ts`, a pure function that the unit tests drive.

| Key | On an option | In the Other field |
| --- | --- | --- |
| Up, Down | Move between options; Down from the last option enters Other | Up at the start of the text moves to the last option |
| 1 to 4 (to 5 with Other) | Single-select: pick and go to the next question. Multi-select: toggle. The number after the last option opens Other | Typed as text |
| Space | Multi-select: toggle. Single-select: pick and stay | Typed as text |
| Left, Right | Previous or next question | Move the caret |
| Tab, Shift-Tab | Next or previous question. Past the last question, the focus goes to Submit answers. Before the first, it leaves the card | Same as on an option |
| Enter | In a single-select, pick the option. Then go to the next question, or on the last question submit when every question has an answer, or go back to the first unanswered one | The same, without a pick; Shift-Enter is a new line |
| Esc | Decline the card | Decline the card |

When the card opens, the focus lands on the first option. `answerControl` in `webview.ts` now prefers the control a card marks with `data-keyboard`, so the focus fix of `bb922dd` gives the waiting card the keyboard, and the card does not lose it to the composer. A click picks an option. A card with one single-select question is answered by that click, as U13's card was.

## Check

- `packages/core/test/ask-user.test.ts` covers the limits, a listed Other, the other rejections, the old shape, the wire copy read back, the form mapping, the content round trip, and the model's result text and plain-text fallback.
- `packages/engine/test/memory-serve.e2e.test.ts` covers a two-question round trip (one answered under Other, one multi-select), a cancelled card, the plain-text fallback, a listed Other refused before asking, and the replay of an old single-question call under its question.
- `packages/extension/test/question-model.test.ts` covers the keyboard map, clicks and the settled line. `fold.test.ts` covers the answered card kept in view as one line.
- `packages/extension/test/question.integration.test.ts` drives the real panel: a three-question card by keyboard, a two-question card by clicks, and a one-question card declined with Esc. It checks what the model receives for each. `context.integration.test.ts` still passes unchanged, with U13's single-question shape.
