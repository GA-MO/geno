# U63: skills and agents from a catalog

The user can now add skills and agent definitions without a terminal. Settings has a new section, **Skills and agents**. It lists what Geno loads in the workspace and from `~/.g-code`, and it searches the catalogs the user lists. An entry opens read-only first: its files, and its main file checked against the catalog's hash. Install copies the entry into `~/.g-code` (for the user) or into the workspace's `.g-code` folder (for the project). Uninstall removes only the files Geno wrote. Nothing in an entry runs at install. The contract is the U63 row in the table at the end of [plan-u19-on.md](plan-u19-on.md).

## Data shape

The shape is pure and lives in `packages/core/src/catalog.ts`. The engine parses each index with zod at its boundary (`packages/engine/src/catalog.ts`), and the schemas are checked against the core types with `satisfies`.

- **`CatalogIndex`** is `{ version: 1, name?, entries }`. A local catalog keeps it as `catalog.json` in its folder. A remote catalog is the index's own https URL.
- **`CatalogEntry`** is `{ kind: 'skill' | 'agent', name, description, version, files }`.
- **`CatalogFile`** is `{ path, sha256, size?, url? }`. `path` is where the file goes inside the entry. `url` is where it comes from: an https URL, or a path relative to the index. Without `url`, the file is `path` beside the index.
- **`CatalogSource`** is the catalog as the user wrote it: `{ kind: 'url', url }` or `{ kind: 'folder', dir }`, with the original `text`. `catalogSourceOf` makes one from a line of `gcode.skills.catalogs`.
- **`InstallPlan`** is what an install would write: the target, the folder it owns, and one `PlannedWrite` (`file`, `origin`, `dest`) per file. `planInstall` returns a plan, `installed` (this very entry is already there), or `refused` with the reason.
- **`InstallRecord`** is one install in the manifest: kind, name, version, scope, the workspace for a project install, the catalog, the target, the folder it owns, each file's absolute path and sha256, and when.
- **`InstallManifest`** is `{ version: 1, installs }`. It is one file, `$GCODE_HOME/catalog/installs.json`, written whole through a rename. Nothing about the install goes into the repository. Two VS Code windows run two engines, and both may install at once, so a change holds `installs.json.lock`. This is U62's schedule lock, moved to `packages/engine/src/file-lock.ts` so both use it. The files are fetched and checked before the lock is taken. Under the lock the plan is made again, and the files are written and recorded.
- **`UninstallPlan`** is the files to remove, the files to keep because the user changed them, and the folders to remove once empty.

### Where an install goes

| Kind | For you | This workspace |
| --- | --- | --- |
| Skill | `~/.g-code/skills/<name>/` | `.g-code/skills/<name>/` |
| Agent | `~/.g-code/agents/<name>.md` | `.g-code/agents/<name>.md` |

These are Geno's own roots in the config roots table (`CONFIG_ROOTS` in `core/src/config-roots.ts`, see [config.md](config.md)), which Geno already loads skills and agents from. Project installs first went to `.claude`. An install made there before the move stays where its manifest record says: Settings lists it as installed, a second install of the same entry finds it, and Uninstall removes it from `.claude`.

### Checks before anything is written

`entryProblem`, `fileOriginOf`, `fileProblem` and `planInstall` refuse, in this order:

1. **The entry.** The name must be lowercase letters, digits and single hyphens, at most 64 characters, as the Agent Skills format asks. A skill needs `SKILL.md`. An agent is exactly one file, `<name>.md`. An entry has at most 200 files, each at most 1 MB as listed, and 5 MB in all. A path is listed once, ignoring case, because macOS folders ignore case.
2. **Each path.** It must be relative and use `/`. It may not have a `..` or `.` segment, an empty segment, a backslash, a drive letter, a control character, or more than 240 characters.
3. **Each origin.** A URL must be https on a public host. A relative source stays inside the catalog: `../other/SKILL.md` is refused. In a remote catalog, a relative source resolves against the index's URL and is checked again.
4. **The name.** A skill or agent of the same name that Geno already loads is a clash, wherever it is: in the workspace, in the user's home, or a built-in command or agent. Plugin skills carry a namespace (`pstack:how`), so they never clash.
5. **The target.** If something is already at the target, Geno refuses, unless the manifest says Geno put it there. The same entry installed again is a no-op. Another version must be uninstalled first.

Then the engine fetches every file and refuses the whole install on the first of these:

- the bytes do not match the listed sha256, or the listed size;
- a file is larger than 1 MB, or all of them more than 5 MB;
- a local file's real path is outside the catalog folder, which catches a symlink that leads out;
- the main file's frontmatter names another `name`, or a `SKILL.md` has no `description`, which Geno needs to load it;
- the folder the install writes in resolves outside the user's Geno home or the workspace, as a symlinked `.g-code` folder could.

### Writing

The files are written into a temp folder beside the target (`.geno-install-<uuid>`), with mode `0644` and `wx`, so no file gets an executable bit and none is overwritten. The folder (for a skill) or the file (for an agent) is then renamed into place. A failure halfway leaves no partial skill, and the temp folder is removed either way.

### Uninstall

`planUninstall` removes a file only when all three hold:

- the manifest lists it;
- it lies inside the folder the install owns (or, for an agent, it is the agent's file);
- its sha256 still matches the one Geno wrote.

A file the user changed stays, and Settings names it. The folders the install made are removed deepest first, and only when empty. An agent's file sits in the shared `agents` folder, which stays. A forged manifest line that names `~/.zshrc` removes nothing; a unit test covers this.

## Nothing runs

Install reads bytes and writes bytes. No code path spawns a process, sources a file, or runs a package manager. An entry's `install.sh`, or a `package.json` with `preinstall` and `postinstall` scripts, is copied as a data file with no executable bit. The engine test puts a `touch <marker>` in both and checks that the marker never appears.

## Fetching a remote catalog

The fetch runs in the engine, outside the bash sandbox, with U53's guards (`docs/u53.md`):

- **https only.** `catalogUrlOf` refuses `http:`, `file:` and any other scheme, credentials in the URL, `localhost` and the other local names, and private, loopback and link-local address literals. A catalog on this Mac is a folder, not a URL.
- **DNS.** `guardedResolve` resolves the name, refuses it if any address is not public, and pins the connection to those addresses.
- **Redirects.** At most 5, and each hop goes through `catalogUrlOf` again.
- **Limits.** 20 seconds per file, 2 MB for an index, 1 MB for a file.

`get` in `packages/engine/src/tools/web.ts` now takes the `Accept` header, the byte cap and the user agent as options, so web_fetch and the catalog share one guarded GET. Geno ships with no remote catalog. The user adds one.

There is no approval card. The user typed the catalog into Settings and clicks Install after seeing the preview, so a second question would add nothing.

## Engine

Five extension methods. Each takes a folder (`cwd`), not a session, as U52's do, so opening Settings starts no session.

| Method | Request | Answer |
| --- | --- | --- |
| `_gcode/skills` | `cwd` | `items` (`InstalledItem`: kind, name, description, `workspace` or `user`, path, the install if Geno made it, whether it loads) and `pluginSkills`, a count |
| `_gcode/catalogSearch` | `cwd`, `catalogs`, `query` | `hits` (`CatalogHit`) and `problems`, one per catalog that failed |
| `_gcode/catalogPreview` | `cwd`, `catalog`, `kind`, `name` | the hit, the main file's frontmatter as pairs, and its body |
| `_gcode/catalogInstall` | the same and `scope` | the record, `already`, and a fresh `skills` listing |
| `_gcode/catalogUninstall` | `cwd`, `id` | the files kept, and a fresh `skills` listing |

A refusal is an invalid-params error whose message is the reason. Search reads each catalog in turn, and a catalog that fails leaves the others' hits. Every word of the query must appear in the entry's name or description. An entry with a problem is still listed, with its problem, so a catalog author can see what to fix.

The installed list comes from `loadCommands` and `loadAgents`, so it shows exactly what the `skill` tool and the `agent` tool see. An install whose files no longer load stays in the list with "Not loading", so the user can still uninstall it.

## In the panel

Settings, after Permissions, has **Skills and agents** (`packages/extension/src/chat/skills-panel.ts`, `skills-host.ts`, `skills-model.ts`):

- **Installed.** Each row has a Skill or Agent chip, the name, Workspace or You, the description and the path, relative to the workspace or under `~`. A row Geno installed adds the version and the catalog, and an Uninstall link. One line counts the Claude Code plugin skills, which Claude Code installs.
- **Catalogs.** The lines of `gcode.skills.catalogs`, each with Remove, and a field to add one. The setting is application-scoped, so a workspace's `.vscode/settings.json` cannot add a catalog.
- **Search.** A search field, searched as the user types, with a 250 ms pause. Problems show under it in the error color.
- **An entry.** A card opens to show its files with sizes, then its main file once the engine checked it: the frontmatter as a table and the body as plain text in a `<pre>`. The body is never parsed as HTML or markdown. Under it are a scope menu ("For you, in ~/.g-code" or "This workspace, in .g-code") and Install. Install stays off until the preview is in, and for an entry already installed in that scope. A line under Install says that the files are copied as data with their hashes checked, and that nothing runs.

The section asks the engine through the shown chat's folder, as Permissions does.

## Model-facing change

None to the tools. A skill installed from Settings loads with the `skill` tool by its name, because `~/.g-code/skills` and `.g-code/skills` were already skill folders. `docs/geno-tools.md` gains one row: installing a skill, an agent or a plugin is not available to the model, and it should tell the user what to look for in Settings. No tool is added, so the roster numbers in the earlier units' docs do not change.

## Tests

- `packages/core/test/catalog.test.ts` has 63 tests:
  - 16 path rows: `..` at the start and in the middle, `.`, absolute, a drive letter, a backslash, empty segments, control characters, and a path too long.
  - The sources: https on a public host, an absolute folder and `~/`; and 11 refused, among them `http:`, `localhost`, `127.0.0.1`, `10.0.0.1`, `169.254.169.254`, `[fe80::1]`, credentials, `file:` and a relative folder.
  - The origins: a relative source against a folder and against a URL, and refused ones that climb out, are absolute, or point at a private host.
  - The hash: other bytes of the same size, another size, and a file over the cap whose hash matches.
  - 16 entry rows: no `SKILL.md`, `skill.md` in the wrong case, an agent of two files, an upper-case name, a name with a slash, a traversal, a path twice in two cases, a bad hash, and the size and count caps.
  - The plan: the targets, a name clash (and that an agent of the same name is no clash), a target Geno did not install, the same entry again, another version, and a traversal and a private URL refused before any fetch.
  - The uninstall: edited files kept, folders deepest first, and a forged manifest line outside the owned folder removing nothing.

  - Search, with the query matched across words. Preview of a skill and of an agent's frontmatter, which writes nothing. Install for the user: the files are on disk, `install.sh` has no executable bit, the list shows the install, and a second install is a no-op. The same skill for the project is refused as a clash. Install of the agent for the project.
  - A session then loads the installed skill with the `skill` tool, and the fake model's next request holds its body.
  - Uninstall keeps a file the user edited, removes the rest, and keeps the shared `agents` folder. The manifest ends empty, and `git status` is clean. The `touch <marker>` in `install.sh` and in `package.json`'s scripts never ran.
  - Refused: a file whose bytes changed after the index was written (same size, other hash), in install and in preview; a symlink out of the catalog folder; a `../../.zshrc` path; an unknown entry. Nothing is written to the workspace or the Geno home.
  - A missing folder, an `http:` URL and a relative folder each give a problem while the good catalog still answers.
  - Two catalog services on one Geno home, standing in for two engines, install at once, and the manifest keeps both records.
  - A remote URL whose name resolves to `10.0.0.8` is refused by the DNS guard before any connection.
- `packages/extension/test/webview/skills.webview.test.ts` runs the section in headless Chromium under the panel's real CSP (3 tests): the list, Uninstall only on Geno's installs, the plugin count, the catalog problems, adding and removing a catalog, search; opening an entry sends one preview request, Install waits for the preview, a `<img onerror>` in the body stays text, the scope menu, the install message, a refusal shown in the error tone, and an unusable entry that is never fetched; and at 300px nothing runs past the section's edge.

## Decisions

- **A section in Settings, not its own view.** The section reuses Permissions' rows and the provider cards, so it costs no new view, command or route.
- **Project installs go to `.g-code`.** See "Where an install goes".
- **A clash anywhere refuses.** A user skill named like a workspace skill would be shadowed in that workspace, which reads as a broken install. Refusing is clear, and the user can uninstall the other one.
- **No update in place.** Another version needs an uninstall first. Uninstall keeps edited files, so an update would need a merge rule, and none was asked for.
- **The manifest is under the Geno home.** A marker file inside each skill would land in the repository for a project install.
- **Agents and skills only.** Geno reads Claude Code plugins in place from `installed_plugins.json` and never writes there, so an entry kind for a whole plugin is left out.

## Follow-ups

- **A catalog builder.** `gcode catalog index <folder>` could write `catalog.json` from a folder of skills, with the hashes. Today the author writes it, or uses `writeCatalog` in `packages/engine/test/fake-catalog.ts` as the model.
- **Update.** Replace an install with a newer version when none of its files changed.
- **Plugin bundles.** An entry that installs several skills and agents at once.
