# U66: share a page

Save as page turns a widget or an answer into one standalone HTML file, to show someone who does not use Geno. The file goes in the workspace, in `geno-pages/` by default. It opens from a disk, a mail attachment or a phone the same way, because everything it shows is inside it and it loads nothing. Nothing is uploaded. The contract is the U66 row in the table at the end of `docs/plan-u19-on.md`.

## What the user does

- **An answer.** Each message's menu (U50, with U58's chapter items) ends with a separator and "Save as page". It saves that turn's answer. The item shows only once the turn has ended and its answer has text or a drawn widget, so a turn that only ran tools offers nothing.
- **A widget.** The widget's `⋯` menu has "Save as Page" in place of U37's Download as HTML. It saves the widget alone.
- **Where it goes.** `<first workspace folder>/geno-pages/<name>.html`. The name comes from the title: letters and digits of any script, Thai included, joined by dashes, at most 60 characters. The `gcode.pages.folder` setting names another folder inside the workspace. A path that is absolute or climbs out of the workspace falls back to `geno-pages`. With no folder open, the save dialog asks.
- **A name already taken.** A modal asks "`geno-pages/x.html` already exists. Replace it?" with Replace, Keep Both and Cancel. Keep Both saves the page as the first free `x-2.html`, `x-3.html` and so on. Cancel, or closing the modal, writes nothing.
- **After the save.** A notice says "Saved the page to `geno-pages/x.html`." with Open in Browser and Reveal in Finder (Reveal in File Explorer on Windows, Open Containing Folder on Linux). Open in Browser hands the file to the system's default app for HTML.

## What the page shows

- **The title.** An answer's page is named for the first line the user asked, else the answer's first heading, else "Answer". When the request is longer than that one line, the whole request shows under the title in a box. A turn Geno started by itself has no request. A widget's page is named for the widget.
- **The answer.** The turn's text and widgets in order, without its tool steps. Markdown is rendered by `markdownHtml` in core: headings, lists, task lists, tables, quotes, links and code. Code is colored with the panel's grammars, under a caption naming the language.
- **Images.** An image the answer shows from the workspace (PNG, JPEG, GIF, WebP or SVG, at most 5 MB each and 20 MB in all) is inlined as a data URI. A web image becomes a link to its address. Any other image shows as its alt text.
- **Diagrams.** A mermaid diagram the panel drew is saved as that drawing, an SVG inside an `<img>` data URI, so its SVG can run no script and load nothing. It keeps the surface of the scheme it was drawn in, white for light and `#232326` for dark, whichever scheme the reader's browser uses. A diagram the panel had not drawn, such as one in a folded step, shows as its source.
- **Widgets.** Each widget runs in the same sandboxed frame it has in the panel. Its script runs, and its frame takes its content's height.
- **Colors.** Geno's glass colors for light and dark are baked in. The dark ones apply under `prefers-color-scheme: dark`, for the page and inside each widget's frame. The reader has no VS Code theme, so the page does not follow the user's.
- **Fonts and width.** System fonts only. The column is at most 46rem with a 16px gutter. Code, tables and wide diagrams scroll inside their own boxes, so nothing scrolls sideways at a phone's 390px.

## The data shape

`packages/core/src/share-page.ts` owns it, and `renderPage` is pure.

- `PageDocument = { title, parts, images, diagrams, theme, nonce }`.
- `PagePart` is a union: `{ kind: 'request', text }`, `{ kind: 'markdown', text }` and `{ kind: 'widget', title, html }`.
- `images` maps a markdown image's address to a `DataUri`, a branded string that only `dataUri(type, bytes)` makes. `diagrams` maps a mermaid source to `PageDiagram = { svg, scheme }`.
- `PageTheme = { light, dark }`, each a `PageTokens` record: the widget variables (`--bg`, `--fg`, `--chart-1` and the rest) and the page's own (`--link`, `--code-bg`, `--diagram`, `--tok-*`). `PAGE_THEME` holds the glass values.
- The CSP is `pageCsp(nonce)`, which is the widget frame's own `frameCsp(nonce)`.

The extension side:

- `PageSource` (`packages/extension/src/chat/page-model.ts`) is what the panel posts in `{ type: 'save-page', page }`: `{ kind: 'widget', toolId }`, or `{ kind: 'answer', turnId, diagrams }` with the panel's drawings as `DrawnDiagram = { source, svg, scheme }`.
- `pageDraft(page, transcript)` turns it into the title and parts. `offersPage(turn)` decides whether the message menu shows the item.
- `page-files.ts` holds the file rules: `pagesFolderOf(setting)`, `imageFile(href, roots)` and `chooseName(name, taken, ask)`.
- `page-host.ts` reads the images, renders the page, asks about a taken name, writes the file and offers Open and Reveal.

`widget-frame.ts` moved from the extension to `packages/core/src/widget-frame.ts`, so the panel and the page build the same frame. `themeCss` takes a single theme as before, or a `WidgetSchemes` pair, which it writes as the light rule and the dark rule under `prefers-color-scheme`. The Prism grammar table moved to `packages/core/src/code-tokens.ts` as `codeTokens(code, label)`, which the panel's `highlight` and the page's code blocks both use. `prismjs` moved from the extension's dependencies to core's, and core gained `marked`.

## Security

- **No network.** The page's policy is `default-src 'none'; script-src 'nonce-…'; style-src 'unsafe-inline'; img-src data:; font-src data:; media-src data:; form-action 'none'; base-uri 'none'; frame-src 'none'; worker-src 'none'`, first in the head. A `srcdoc` frame is not a fetch, so `frame-src 'none'` does not stop the widget frames. Each frame inherits the page's policy and adds its own, the same one. The page also turns off DNS prefetch and sends no referrer.
- **Model text is never markup.** Every node of the markdown is built from marked's token fields as escaped text. Raw HTML in an answer shows as its text. A link opens only for `http:`, `https:` and `mailto:`. The title and the request are escaped the same way.
- **One script.** The page runs one script, with a fresh nonce. It sizes each widget frame to the height the frame reports, clamped to 24 to 2400px. It opens a link the reader clicked inside a widget in a new tab, only while that frame has the focus and the click's user activation. Every script in a widget needs the nonce, which the frame's bootstrap gives it, as in the panel.
- **The sandbox.** A widget's frame is `sandbox="allow-scripts"`, never `allow-same-origin`, so it cannot reach the page, storage or the reader's files. The bootstrap removes WebRTC before the widget's script runs, as in U37.

### A panel fix found on the way

The chat panel handled every `message` event as a message from the extension. A widget's frame posts to the same window, so a widget could post `{ type: 'reset', … }` and clear the transcript, or post a `permission` message and draw a card the extension never sent. Height reports also reached the transcript reducer, which threw `REDUCERS[action.type] is not a function` on each one. The panel now drops a message whose source is a frame inside the panel, at any depth (`fromOwnFrame` in `webview.ts`), before it reads it. In VS Code 1.141 the extension's messages arrive with a source that is neither null nor the page's parent, so the check walks the panel's own frames rather than trusting either. `test/webview/widget-messages.webview.test.ts` failed before the fix (the forged reset left no turn) and passes after it.

The panel also drew a task item's box as the text `[x]` in a paragraph, because marked puts the checkbox among the item's blocks. Both the panel and the page now render it as a box.

## Decisions

| Question | Choice | Why |
| --- | --- | --- |
| Where an answer's action lives | The message menu, after the chapter items | The answer has no menu of its own, and the message menu is already the turn's menu. |
| Who renders the markdown | Core, from the transcript's text | The page then depends on the session's data rather than on what the panel happens to show, and core can unit test the escaping. The panel's DOM renderer stays as it is. The cost is a second token table of about 60 lines. |
| Diagrams | The panel's drawing, as an SVG image on its own surface | Mermaid needs a DOM, so only the panel can draw. An `<img>` makes the SVG inert. Drawing a second copy for the other scheme was left for later. |
| Answer title | The first line asked, then the first heading | A page reads as a question and its answer. Using the heading as the title showed it twice. |
| Colors | Glass light and dark, fixed | The reader's browser picks the scheme. The user's VS Code theme means nothing outside VS Code. |
| A model tool | None | Saving a file the user did not ask for would need the approval model, a roster entry and its token cost. The user saves with one click. The deferred roster and its per-mode numbers are unchanged. |
| Download as HTML | Removed | Save as Page replaces it. The old download ran the widget's scripts unsandboxed in the page, with `script-src 'unsafe-inline'`. `standaloneDocument` is gone. |

## Where it lives

- `packages/core/src/share-page.ts`, `code-tokens.ts`, `widget-frame.ts`.
- `packages/extension/src/chat/page-model.ts` (pure, webview safe), `page-files.ts` (pure, Node paths), `page-host.ts`.
- `packages/extension/src/chat/rewind-view.ts` (the menu item), `webview.ts` (`saveAnswer`, `fromOwnFrame`), `diagram-view.ts` (`drawnDiagrams`), `widget-view.ts`, `markdown.ts`.
- `packages/extension/package.json`: the `gcode.pages.folder` setting.

## Tests

- `packages/core/test/share-page.test.ts` (15): one policy first in the head and equal to the frame's, one script with the nonce, no `src`, `srcset`, `url()`, `@import` or `<link>` that names a web address, every `src` a `data:image/` URI, web addresses only as links, the widget's `srcdoc` equal to `frameDocument` with the page's nonce, both schemes in the page and in the frame, escaping of the title, the request and inline and block HTML, a bad nonce refused, highlighted code, diagrams as SVG data with their width, images inlined or linked, tables and task lists, image addresses found in lists and tables, titles and file names. Making inline HTML render raw fails the escaping test.
- `packages/core/test/widget-frame.test.ts` moved from the extension. The downloaded-widget test went with `standaloneDocument`.
- `packages/extension/test/page-model.test.ts` (10): the answer's parts and order, the title and request rules, nothing to save, the widget page, the folder setting, the name choice for Replace, Keep Both and Cancel, and which images may be inlined.
- `packages/extension/test/webview/share-page.webview.test.ts` (2): the message menu ends with Save as page and posts `save-page` with the turn's id and the drawn diagram, in dark and again in light. The widget menu lists Copy as Image, Save as Page and Open in Editor and posts `{ kind: 'widget', toolId }`. A turn with only tool steps offers no item. Task items show their box.
- `packages/extension/test/webview/widget-messages.webview.test.ts` (1): a widget's forged `reset` and `permission` messages change nothing.
- `packages/extension/test/share-page.integration.test.ts` runs the real engine against a fake model in VS Code. The turn draws a widget that tries a remote image, a fetch, an image made in script, a stylesheet and a font, then answers with a heading, a link, a workspace SVG chart, a mermaid diagram, code and a table. The suite saves the widget from its menu and the answer from the message menu, and checks both files under `geno-pages/`, the notices and their two buttons, and the answer page's two SVG images (the chart file and the panel's drawing). A second save of the widget meets the modal, which VS Code refuses to show while extension tests run, so it stands for Cancel: the first page is unchanged and nothing is saved beside it. `chooseName`'s unit tests cover Replace and Keep Both. Then the launcher opens both pages in headless Chromium at 390px, in light and in dark, with every request but the page's own file intercepted. Each page makes zero requests, shows its title, runs the widget's script, sizes its frame, decodes its images, has the scheme's background, and does not scroll sideways. A control page without a policy shows that the interception does see a remote image.
- `test/suite/rewind.ts` expects "Save as page" after "Mark a chapter here". `test/suite/widget.ts` expects Save as Page in the widget menu and no longer saves through a dialog.

## Follow-ups

- A diagram drawn in one scheme keeps that scheme's surface on a page shown in the other. Drawing it for both schemes would need the panel to render it twice.
- A session on an external agent has no message menu (`offersRewind`), so its answers cannot be saved as pages yet.
- A diagram in a step a compact turn folded is saved as its source, since the panel never drew it.
