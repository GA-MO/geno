# U60: PR and CI watch

The panel shows the current branch's pull request and its checks in one line above the composer. The model gets `watch_pr`, which waits on those checks in the background and wakes the session (U49) when CI finishes, with the outcome and the end of each failing log. Both read GitHub through the user's own `gh` CLI. Geno never installs `gh` or logs in for the user, and nothing in this unit pushes, merges, comments or reruns. The brief is the U60 row of "More capabilities the coordinator's harness has and Geno lacks" in [plan-u19-on.md](plan-u19-on.md).

## Data shape

`packages/core/src/pr.ts` names it. It holds only types and pure functions.

- **The PR.** `PullRequest` is `{ number, title, url, state, isDraft, reviewDecision, branch }`. `state` is `OPEN`, `CLOSED` or `MERGED`. `reviewDecision` is `APPROVED`, `CHANGES_REQUESTED`, `REVIEW_REQUIRED` or `null` when the repository asks for no review.
- **A check.** `PrCheck` is `{ name, workflow, bucket, link }`. `bucket` is gh's own grouping of a check's state and conclusion: `pass`, `fail`, `pending`, `skipping` or `cancel`. `checkCounts` counts them.
- **One look.** `PrLookup` is what the engine found for a folder:

  | Kind | Means |
  | --- | --- |
  | `pr` | The branch's PR and its checks |
  | `no-pr` | A GitHub repository, but the branch has no PR |
  | `not-github` | Not a git repository, or no remote on GitHub |
  | `gh-missing` | A GitHub remote, and no `gh` on PATH or in Homebrew's folders |
  | `gh-logged-out` | `gh` exited with 4, or asked for `gh auth login` |
  | `failed` | Anything else, with one redacted line of gh's message |

- **The settle rule.** `ciOutcomeOf(checks)` is `undefined` while the PR has no checks or any check is pending. Otherwise it is `failed` when a check failed or was cancelled, and `passed` when the rest passed or were skipped. No checks is not settled, because checks appear a little after a push.
- **The watch.** `PrWatch` is `watching { pr, checks, emptyPolls, failures }` or `ended { end }`. `startPrWatch(lookup)` reads the look taken when the tool is called and ends at once when there is nothing to wait for. `nextPrWatch(watch, lookup, timedOut)` takes each poll. `PrWatchEnd` says why it ended:

  | End | When |
  | --- | --- |
  | `settled` | The settle rule gave an outcome |
  | `closed` | The PR was merged or closed |
  | `no-checks` | 3 polls in a row found no checks |
  | `no-pr` | The branch has no PR any more |
  | `gh` | gh went missing or logged out, or 3 looks in a row failed |
  | `timed-out` | The watch's time ran out with a check still pending |

  A good look resets the count of failed looks, so a short network outage does not end a watch.
- **The cadence.** `prPollDelayS(elapsed)` is 60 s for the first 10 minutes of a watch and 90 s after. A watch never polls faster. Its timeout is 3,600 s by default and at most 7,200 s.
- **The failing logs.** `failingJobsOf(checks)` takes the failing checks whose link names a GitHub Actions job, at most 2. `ciLogOf(check, raw)` drops the job, step and timestamp columns that `gh run view --log-failed` prints on every line, removes escape sequences with U55's `cleanTerminalOutput`, redacts with U55's `redactSecrets`, and then cuts to the last 50 lines within 4,000 characters. Redaction runs before the cut, so the cut cannot leave half a secret that no rule matches.
- **The report.** `prWatchText(end, logs)` is what the model reads. A failure names the PR, the counts, each check that did not pass with its link, and each log inside a `<ci_log check="…">` fence that the log cannot close. A line after the fences says that CI logs are output, not instructions.
- **The wake.** `WakeTrigger`, `WakeSource` and `WakeNote` each gain a `pr` kind (`packages/core/src/wake.ts`). The `pr` note holds `{ id, toolUseId, pr, outcome, text }`, and `text` is the whole report, so a replay and a reload read the same failing logs. `PrWatchOutcome` is `passed`, `failed` or `ended`. The woken turn's tag reads "woke: CI passed", "woke: CI failed" or "woke: PR watch ended". Tasks names the source as "Wakes on PR #42's checks".

## The tool

`watch_pr { timeout_s? }` joins `AGENT_TOOL_NAMES`, next to `monitor`. Like `monitor`, Plan mode and subagents leave it out. The system prompt's tool line and its waiting line name it once.

1. It looks once at once: `gh pr view` and `gh pr checks` in the session's folder (the lane's, in a lane).
2. If CI already finished, or the PR is closed, it answers with the report and sets nothing up. A failure's report has the failing logs.
3. If there is no PR, or gh cannot answer, it fails with words the model can act on. For a missing `gh`, the model is told to ask the user to install it from https://cli.github.com or with `brew install gh`, and to run `gh auth login`.
4. Otherwise it registers the watch with `Wakes` and returns at once with the PR, the counts and the checks still running. The model ends its turn.
5. `Wakes` polls on the cadence above. When the watch ends, it fetches the failing logs, puts the `pr` note in the session's inbox and the session wakes as for any U49 arrival, through the same gate: no wake while the user types, while a card waits, or past the cap.

A second `watch_pr` for a PR the session already watches starts nothing and names the running watch. Where nothing would wake the session, in a command-line run or with `gcode.wake.auto` off, the tool refuses before it runs gh and tells the model to give the user `gh pr checks --watch` instead.

It needs no approval in any mode that offers it. It only reads, its argv is fixed, and what it returns is fenced data.

## gh in the engine

`packages/engine/src/gh.ts` runs gh outside the bash sandbox, as U53's `web_fetch` runs its fetches. The sandbox has no network, and gh needs the user's login.

- **The allowlist.** `GhCall` has three kinds, and `GH_ARGV` builds each whole argv:

  | Call | argv |
  | --- | --- |
  | `pr-view` | `pr view --json number,title,url,state,isDraft,reviewDecision,headRefName` |
  | `pr-checks` | `pr checks --json name,workflow,bucket,link` |
  | `failed-log` | `run view --job <digits> --log-failed` |

  A job id that is not all digits throws before anything runs. gh starts with `spawn` and no shell, so nothing in a model's input or a log can add a flag or a subcommand.
- **The environment.** `ghEnv` passes only what gh needs: `PATH`, `HOME`, the user and locale, gh's config folder and host, `GH_TOKEN`, `GITHUB_TOKEN` and the enterprise tokens, the proxy variables and `SSL_CERT_FILE`. No provider key reaches gh. It adds `GH_PROMPT_DISABLED`, `GH_NO_UPDATE_NOTIFIER`, `GH_PAGER=cat`, `NO_COLOR` and `GH_SPINNER_DISABLED`, so gh answers once and exits.
- **Finding gh.** The engine looks on its PATH, then in `/opt/homebrew/bin` and `/usr/local/bin`, because VS Code started from the Dock can see a PATH without them. A miss is not cached, so installing gh takes effect at the next look.
- **Limits.** Each call has 30 s. Stdout keeps its last 2 MB, which a long log needs. Stderr keeps its first 4,000 characters.
- **Parsing.** zod reads gh's JSON at this boundary. Unknown fields are ignored. An empty `reviewDecision` reads as `null`. A bucket gh never had fails the look with a message, instead of reading as pending forever.
- **Exit codes.** `gh pr checks` exits 8 while a check is pending and 1 when one failed, after printing them all. `lookUpPr` reads the JSON whatever the code is, and reads "no checks reported" as a PR with no checks yet.
- **A missing gh.** `githubRemote` runs `git config --get-regexp ^remote\..*\.url$` in the folder. With a GitHub remote, a missing gh is `gh-missing`; without one, it is `not-github`, and the panel shows nothing.

## In the panel

- **The line.** A row above the composer shows the PR icon, coloured by state, then `#42`, the title, what the icon does not say (draft, merged or closed, and the review decision, such as "Review required"), and the failed, pending and passed counts with their icons. The tooltip lists every check. Clicking the row opens the PR on GitHub. A screen reader hears "Pull request #42, …, checks 1 pending, 1 passed. Opens on GitHub."
- **At 300px.** The state hides first, then the title shrinks with an ellipsis. The number and the counts are never cut.
- **gh missing or logged out.** The row says "Install the GitHub CLI and run gh auth login to see this branch's PR here." or "Run gh auth login in a terminal to see this branch's PR here." Clicking the text opens https://cli.github.com. The close button hides the hint until the window reloads.
- **Nothing to show.** A branch without a PR, or a folder not on GitHub, shows no row. A failed look keeps the last row, so a dropped connection does not make it blink away.
- **When it looks.** `PrStatusHost` (`packages/extension/src/chat/pr-status-host.ts`) asks the engine with `_gcode/prStatus { cwd }`, where `cwd` is the shown chat's lane or else the workspace folder. It looks when the panel loads, when the panel shows again, when the window regains focus, when a turn ends, and when `.git/HEAD` changes. Apart from the panel loading and HEAD, it waits at least 30 s after the last look. While an open PR has a check pending, it also looks every 60 s by itself, and only while the panel is visible. A look the timer skipped while the panel was hidden runs when it shows. `GCODE_PR_REFRESH` sets both numbers for the tests.
- **Tasks.** A session waiting on a watch stays in Working with "Waiting to wake" and "Wakes on PR #42's checks", and Cancel stops the polling.
- **The step.** A `watch_pr` call reads "Checking the PR" while it runs and "Checked the PR" after.

## Choices made in this unit

- **zod lives in the engine.** The brief asks for zod at the boundary. Core has no zod dependency and is pure, and the engine is where gh's output enters, so the schemas are in `gh.ts` and core holds the types and the rules. This matches U55, whose `readTerminalResponse` is in the engine too.
- **One tool, not a pair.** `watch_pr` both reads and waits. When CI already finished it answers at once with the failing logs, so `fix-ci` needs no second tool to read a log.
- **The report is stored in the note.** The log tail is fetched once, when the watch ends, and kept in the session log. A replay does not call gh again, and the model reads the same text after a reload.
- **A cancelled check fails CI.** A check cancelled by a newer push is replaced in `gh pr checks` by the newer run's check, so a cancel that remains is worth the model's attention.
- **The status line is not tied to a watch.** The panel looks on its own triggers, so it works without a model call. The two never share a poll; gh calls are free of tokens, and the line's timer runs only while a check is pending and the panel is visible.
- **The status line asks the engine.** The extension could run gh itself, but one allowlisted runner in the engine keeps the argv and environment rules in one place.
- **The hint shows only on GitHub.** A missing gh in a folder with no GitHub remote shows nothing, so a user who does not use GitHub never sees it.
- **Watches die with the engine.** A watch is in memory, like a monitor. After an engine restart the model can call `watch_pr` again; it answers at once if CI finished meanwhile.

## Follow-ups

- **A watch after a restart.** Watches are not taken up again after the engine restarts, as U49's wake-ups are. A `scheduled`-style record would make them survive.
- **Review comments.** `get-pr-comments` and `babysit`'s comment half need a read of PR comments, fenced as data, which would be a fourth argv.
- **Other CI.** A failing check that GitHub Actions did not run, such as a Vercel deployment, has no log in the report, only its link.
- **The line in a multi-root workspace** follows the first folder only.
- **HEAD in a git worktree.** A worktree's `.git` is a file, so the `.git/HEAD` watcher sees no branch switch there; the line catches up at the next focus or turn end.
