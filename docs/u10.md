# U10: sessions and projects

The chat panel names its project and session, starts new chats, and lists, opens, renames and deletes old ones.

## In the panel

- **Header.** A line above the transcript names the workspace folder and the session's title. The title is the first prompt, on one line and cut to 80 characters, until the user renames the session. Clicking it opens the history.
- **New chat.** The `+` action in the Chat view's title (`gcode.chat.new`) starts a session through ACP `session/new`. The old session stays on disk. A chat with no turns yet counts as new already, so the action does nothing there.
- **History.** The clock action (`gcode.chat.history`) puts the list in the transcript's place. It lists this project's sessions, newest first, with their title, how long ago, the turn count and the cost. Search matches every word against the title and project. **All projects** lists every other project's sessions too, each labeled with its project. Sessions whose workspace is a temporary directory (`/tmp`, `/var/folders` and the system temp dir) never show there. Escape or the back arrow closes the list.
- **Opening a session.** Choosing one loads it through ACP `session/load`. The engine replays its turns, and the panel draws them as they looked live: the prompt, the text, the steps with their files, the edits with their review status, the duration and the footer's cost. The chat continues from there. A session from another project opens in a new window for that folder, since its tools run in that workspace. The window picks it up from a handoff in the extension's global state.
- **Rename and delete.** Each row has Rename and Move to trash on hover or focus. Rename edits the title in place. Delete asks first, then moves the log to `trash/` under the app home. Deleting the open session starts a new one.
- A window reopened on a project loads its last session, so its transcript comes back too, not only its review state.

## In the engine

- `SessionSummary` (`packages/core/src/history.ts`) is what a listing shows of a log: id, workspace, title, created and last-active times, turn count and cost. `inScope` decides what a listing shows. The current project shows its own sessions wherever it lives. Every project's list leaves out temporary workspaces. Neither shows a session with no prompt.
- A `title` event in the log names a session. `_gcode/renameSession` appends one and answers with `session_info_update`.
- `gcode serve` advertises `loadSession`, `sessionCapabilities.list` and `sessionCapabilities.delete`.
  - `session/list` with `cwd` lists that project; without it, every project. The engine filters, since it owns the logs. `SessionInfo._meta["gcode/summary"]` carries the turn count, the cost and the creation time.
  - `session/load` refuses a session from another workspace. It replays each prompt as `user_message_chunk`, with how the turn went under `_meta["gcode/turn"]`. Then come the agent text, `tool_call` and `tool_call_update`, with the time and any edit under `_meta`, and last `session_info_update` with the title.
  - `session/delete` moves the log to `trash/`.
  - The first prompt of a session sends `session_info_update` with the title it gives.
- `gcode session list [--all]` prints the same listing as the panel's.

## Media

All in `docs/media/u10/`, as Dark Modern glass (`-dark`), Light Modern glass (`-light`) and Dark High Contrast (`-high-contrast`, native).

- `header-*.png`: a finished first turn, with the project and the session's title in the header and the New Chat and History actions in the view title.
- `history-*.png`: this project's sessions, the current one marked.
- `history-all-*.png`: every project, with another project's session labeled and marked as opening elsewhere.
- `rename-*.png`: renaming a session in place.
- `loaded-*.png`: an older session loaded, its turn replayed with its step, duration and cost.
- `delete-*.png`: the confirmation before a session moves to the trash.

`GCODE_SCREENSHOTS=<dir> pnpm vitest run packages/extension/test/sessions.integration.test.ts` reruns the test and retakes every capture.
