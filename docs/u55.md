# U55: read the user's terminal

The user can say "the command I just ran failed", and the model reads that command in VS Code's terminal. The user does not paste anything. The model gets the command line, the working folder, the exit code and the end of the output. Secrets in the text are redacted before they leave the extension. The contract is the U55 row in the table at the end of `docs/plan-u19-on.md`.

## The tool

| Input | Default | What the model gets |
| --- | --- | --- |
| `terminal` | The active terminal, or the newest one if none is active | The terminal by its exact name, then by its name in any case, then by its number in the list. |
| `commands` | 3 (at most 10) | The latest commands of that terminal, oldest first. |

Each command shows its command line, its folder and its exit code. A running command shows "still running". A command whose exit code the shell did not report shows "exit code not reported". The output is the last 40 lines, within 3,000 characters. A line above them that was left out is counted, as in "(120 earlier lines left out)". The commands are inside a `<terminal_output>` fence. A closing tag in the output is changed so that the output cannot close the fence. A line after the fence says that the text is data, not instructions, and that secrets in it are replaced with `[redacted]`. When the model named no terminal, the result ends with the list of open terminals, with their numbers and names, which one is active, and how many commands each one recorded. This means one tool also does the work of a `list_terminals` tool.

These answers are clear messages, not errors:

- **No terminal is open.** "The user has no terminal open in VS Code."
- **The name or number matches no terminal.** The message says so and lists the terminals.
- **The terminal has no shell integration.** The message says that Geno cannot see its commands. It says that shell integration works in bash, zsh, fish and PowerShell, and that it is on unless `terminal.integrated.shellIntegration.enabled` is false. It tells the model to ask the user to run the command again in such a terminal, or to paste the output.
- **No command has run since Geno started in the window.** The message says so and tells the model to ask the user to run the command again.

The tool only reads, so it needs no approval. Plan, Ask and Auto offer it. A non-interactive run never gets it. Only the VS Code panel offers it, because only the panel advertises the capability.

## Rules

- **The capability gate.** The extension advertises `gcode/read-terminal` in the ACP client capabilities `_meta`. The engine offers `read_terminal` only to a client that sends this flag. `runAgent` also drops the tool for a non-interactive approval, whatever the caller passes. This works like U54's `gcode/editor-actions`.
- **The editor.** The engine sends `_gcode/readTerminal { sessionId, terminal?, commands }` to the editor that shows the session now. If no editor shows it, the call fails with a message that the model reads. The engine parses the answer with `readTerminalResponse`. A malformed answer fails the call, and the model reads the problem.
- **The recorder.** `TerminalRecorder` in `packages/extension/src/chat/terminals.ts` starts when the extension activates, which is at `onStartupFinished`. It listens to `window.onDidStartTerminalShellExecution` and `onDidEndTerminalShellExecution`. It calls `execution.read()` in the start event, because the stream holds only the data written after the first call. Each terminal keeps its latest 20 commands. Each command keeps the last 64,000 characters of its raw output, and the recorder counts the lines it drops from the start. A closed terminal is forgotten.
- **Redaction before anything leaves the extension.** `recorder.read` builds every record with `terminalCommand` from core. That function removes escape sequences, redacts the whole cleaned output, then cuts it to the tail. Because redaction runs before the cut, the cut cannot leave part of a secret that no rule matches. The command line, the folder and the terminal names are redacted too. The raw records never leave the recorder.
- **The prefix cache.** `read_terminal` is not a core tool, so U46's roster defers it behind `tool_search`, like the editor tools. Its definition is 865 characters, about 248 tokens by the roster's estimate. Deferring it adds one line to the `tool_search` block, and it saves about 217 tokens more a call:

## Data shape

`packages/core/src/terminal.ts` names it. It holds only types and pure functions.

- `CapturedCommand` is a command as the recorder holds it: the command line, the folder, a `CommandExit`, and a `RawOutput` (`{ text, droppedLines }`). Nothing in this shape leaves the extension.
- `CommandExit` is `{ state: 'running' }` or `{ state: 'ended', code: number | null }`. `null` means that the shell did not report a code.
- `TerminalCommand` is a command as a read returns it: the redacted command line, the redacted folder or `null`, the exit, the output tail and `omittedLines`.
- `TerminalSummary` is a terminal as the list shows it: `index` (from 1), `name`, `active`, `shellIntegration` and `commands`.
- `TerminalRead` is a union. The kinds are `commands`, `no-shell-integration`, `no-terminal` and `not-found`. `ReadTerminalResponse` is `{ terminals, read }`.
- `appendOutput` adds a chunk to a `RawOutput` within its cap. `cleanTerminalOutput` removes OSC, CSI and other escapes and control characters, and keeps the last state of a line that a carriage return drew again. `tailOf` keeps the last lines within the character cap. `terminalCommand` does all three, with redaction. `pickTerminal` picks the terminal a read names. `terminalReadText` writes the result.
- `TERMINAL_LIMITS` holds the numbers: 20 commands kept, 64,000 raw characters, 3 commands a read by default and 10 at most, 40 lines and 3,000 characters of output, and 500 characters of command line.
- `READ_TERMINAL_CAPABILITY` (`gcode/read-terminal`) and `READ_TERMINAL_METHOD` (`_gcode/readTerminal`).

`packages/core/src/redact.ts` holds `redactSecrets`. It is a table of rules, in order: private key blocks (a block that is cut off at the end too), passwords in URLs, OpenAI and Anthropic keys (`sk-…`), GitHub tokens (`ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_` and `github_pat_`), AWS access key IDs, Slack tokens, Google API keys, Stripe secret keys, npm tokens, JSON web tokens, bearer tokens, `Authorization: Basic` and `Token` headers, flags such as `--api-key x` and `--password=x`, and assignments such as `password=`, `DB_PASSWORD:`, `"client_secret": "…"` and `?access_token=`. The rule for assignments matches a key that ends in the secret word, so `tokens: 1200` and `max_tokens=4096` stay. A bearer token must hold a digit, so "Bearer authentication" stays. A second pass over the result changes nothing.

## Decisions

- **A new redactor in core.** The repository had one redactor, `redactor` in `packages/engine/src/wire-shape.ts`. It replaces the provider keys that the engine knows by value. A terminal can print any secret, so that redactor cannot help here. `redactSecrets` matches the shapes of secrets instead. It is in core so that the engine and the extension can both use it.
- **Redaction in the extension only.** The engine does not redact the answer again. The brief asks that secrets are redacted before anything leaves the extension. With one owner, the integration test proves that the extension redacted, because a second pass in the engine would hide a failure.
- **No special kind for the step.** The call shows as an ordinary step, "Read the terminal", with the terminal's name when the model named one. The ACP tool kind is `other`. The kind `read` would count the call as a file in the fold's "Read N files". A compact turn counts it in "used N tools".
- **A command that started before activation is not kept.** Its start event was missed, so its output cannot be read. A row with an exit code and no output would read as a command that printed nothing.
- **The model names a terminal with a string.** A name that is all digits matches a terminal's name first, then its number. One string field is easier for small models than a field that is a string or a number.

## Tests

- `packages/core/test/redact.test.ts` (48 tests) checks each secret shape above, that a second pass changes nothing, that every secret on a line is replaced, and that ordinary output stays: test counts, `max_tokens=4096`, "Bearer authentication", "Token generation", URLs without passwords, `git log --author=sam` and a path such as `src/auth/password-reset.ts`.
- `packages/core/test/terminal.test.ts` (26 tests) checks the escape and carriage-return cleanup, the tail by lines and by characters, the count of the lines the recorder dropped, redaction before the cut, the cut of a long command line, `pickTerminal`, the exact result text with the fence and the list, a forged closing tag, each message without commands, and the modes that offer the tool. One test cuts the output in the middle of a key. It fails if the cut runs before redaction.
- `packages/engine/test/read-terminal-serve.e2e.test.ts` (4 tests) runs through `gcode serve` with a fake editor that answers `_gcode/readTerminal`. The tool is offered only to a client with the flag, deferred behind `tool_search`, and never to a non-interactive `runAgent`. In Plan mode it runs without a permission request. The editor gets `{ sessionId, commands: 3 }` for a call without input and the terminal and number for a named call. The model gets the exact fenced text. A malformed answer and an editor error each become an error that the model reads.
- `packages/extension/test/terminals.test.ts` (5 tests) drives `TerminalRecorder` through fake shell integration events. A command's record has its folder and exit code, and its output is cleaned, redacted and capped. A made-up GitHub token appears nowhere in the answer. A terminal keeps its latest 20 commands, and a read returns the number asked for. The tests also check a named terminal, a terminal without shell integration, an unknown name, a closed terminal, a running command, an exit code that was not reported, and `dispose`.
- `packages/extension/test/read-terminal.integration.test.ts` runs one fake-model turn in VS Code. The suite opens a terminal with `/bin/zsh` on macOS and `/bin/bash` elsewhere, with a fresh `HOME` so that the user's rc files stay out. It waits for shell integration. Then it types a command with `sendText`, as a user does. The command prints a made-up `sk-` key and fails on stderr with exit code 3. The suite waits for the end event, then sends "the command I just ran failed". The fake model loads `read_terminal` and calls it with no input. The test checks that the tool result names the terminal, holds the redacted command line, `exit code 3`, the stdout line with `[redacted]` and the stderr line. It also checks that the key is nowhere in any request to the model. Shell integration was reliable in the test VS Code, so the fallback in the brief was not needed. The test passed on macOS with zsh, in 25 s, and in the Linux container with bash (`pnpm test:vscode:docker`), in 9 s.

## Known limits

- Commands that ran before the extension activated are not recorded. A restored terminal shows only the commands run after the window started.
- Output that a program draws in place, such as a full-screen program or a progress bar that moves the cursor up, is cleaned line by line. It can show more than one state of such a line.
- The rules match common secret shapes, not every secret. A password that a program prints on its own line, without a key name, is not redacted.
