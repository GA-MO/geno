# U42: wait out a lost network or a rate limit, then resume

Before U42, a turn whose model call lost the network for more than about 7 seconds failed, and the user had to send the prompt again. A 429 with a `retry-after` past 20 seconds failed at once. Now the call waits and then goes out again by itself. The turn keeps everything it did before the wait, and no tool runs twice, because the loop resumes from the session log. The composer's running row and the Tasks list show the wait, with Retry now and Stop.

## Data shape

All of it is in core and pure.

- **Failure classes.** `FailureClass` in `packages/core/src/model-error.ts` is a discriminated union: `offline`, `limited` with a `resetAt` (ms since the epoch, or undefined), `transient`, `overflow`, `quota` and `fatal`. `classifyModelError` reads the table below, and `classifyFailure` adds the reset time through `resetAtOf`. `ModelFailure` now carries `streamed`, the lowercased `headers` and the parsed error `body`.
- **The wait.** `Waiting` in `packages/core/src/waiting.ts` is `{ kind, since, retryAt, resetAt, message }`. `retryAt` is the next automatic try, or null when the wait holds for the user.
- **The log event.** `WaitEvent` is `{ kind: 'wait', seq, at, wait, by }`. The loop logs one when a wait begins or changes course (`changesCourse`): a new kind, a new start, a new reset, or a switch to holding. A rescheduled probe is not logged. `by` is `{ pid, cwd }` of the engine process that waits. `openWaitOf(events)` finds the wait a log ends in.
- **The schedules.** `WAIT_POLICY` and the pure `planWait(policy, clock, now, resume, jitter)` give each step: `at` a time, `hold`, or `give-up` with a message.
- **The setting.** `ResumeAfterLimit` is `short`, `always` or `off`, the values of `gcode.resume.afterLimit`.
- **The task.** `TaskStatus` gains `waiting`, and `TaskRecord` gains `waiting`. `NEEDS_ATTENTION` marks `needs-input` and `waiting` for U43 to sort by.

### Classification table

First match wins.

| Rule | Kind |
| --- | --- |
| Billing or quota text (`insufficient_quota`, `credit balance is too low`, …) | quota |
| Rate-limit text (`rate limit`, `too many requests`, `free-models-per-day`) | limited |
| Context-overflow text | overflow |
| 402 | quota |
| 429 | limited |
| 408, 5xx | transient |
| Any other status | fatal |
| No status, nothing of the answer streamed, connection-error text (`ECONNREFUSED`, `ENOTFOUND`, `EAI_AGAIN`, `ECONNRESET`, `ETIMEDOUT`, `Connect Timeout Error`, `fetch failed`, `Connection error.`, `other side closed`, …) | offline |
| No status, overload, server or connection text | transient |
| Anything else | fatal |

A connection that breaks after the answer began streaming is `transient`, so it keeps the three quick retries. If the next try cannot connect, that try is `offline`.

`resetAtOf` reads, in order: `retry-after-ms`, `retry-after` (seconds or an HTTP date), the bucket headers (OpenAI's `x-ratelimit-reset-<bucket>` durations such as `6m0s`, and Anthropic's `anthropic-ratelimit-<bucket>-reset` times), and `x-ratelimit-reset` (OpenRouter's epoch ms). A bucket at zero remaining decides, the latest of them. The body is read the same way at `error.metadata.headers`, where OpenRouter copies the upstream limit's headers. Model Studio's 429 bodies carry no reset time.

### Schedules

| Wait | Next try | Gives up |
| --- | --- | --- |
| offline | a probe after 5s, doubling to every 60s | 30 minutes after the wait began |
| limited, reset known | the reset plus up to 3s of jitter | never; it waits for the reset |
| limited, no reset | 15s, doubling to every 5 minutes | 15 minutes after the wait began |

A limit whose reset is more than 15 minutes after the wait began resumes by itself only when `gcode.resume.afterLimit` is `always`. With `short`, the default, such a wait holds. With `off`, every limit holds. A held wait shows "Limited until 14:05" with Retry now and Stop, and waits for the user. An offline wait always resumes by itself.

## Engine

- **Gateway.** `gatewayFor` takes `WaitOptions` (policy, setting, jitter source), read from `GCODE_WAIT_POLICY` and `GCODE_RESUME_AFTER_LIMIT`. On an offline or limited failure it plans the wait, tells `onWait`, and sleeps (`nap` in `waits.ts`) until the next try, Retry now, or Stop. Offline, it then probes. The probe is `Wire.probe`: a HEAD request to the provider's base URL that costs no tokens. Any HTTP answer, even a 404, means the host is reachable. When the probe succeeds, the same model call goes out again. A short limit still pauses the shared model-call slots, as U26 did.
- **Timing.** `StreamMarks.waitMs` is the time a call spent waiting. `turnTimings` reports it as `waitMs`, apart from `overheadMs`.
- **Loop.** `drive` logs each `wait` event and passes the wait a log ends in to the gateway as `waiting`. A limited wait from the log keeps its resume time, and an offline one probes at once.
- **Serve.**
  - Each wait goes to the editor as a `notice` session update. Its title is the plain words, and `_meta["gcode/waiting"]` holds the `Waiting`, or null when the call goes out.
  - The task reads `waiting`.
  - `_gcode/retryNow { sessionId }` wakes the wait and answers `{ retried }`.
  - A load during a wait sends the wait after the replay.
- **Restart.** On its first connection, an engine calls `waitsLeft(store, cwd)`. It looks for logs that end in a wait whose `by.cwd` is this engine's folder and whose `by.pid` no longer runs, and runs a turn with no prompt on each one. The loop resumes from the log. A live engine keeps its own waits, so two engines on one folder never both run a session, as after a changed setting. A subagent's log is skipped, because its call waits inside the parent's tool call. Logs whose last 64 KB name no wait are not parsed.
- **Lanes and Arena.** Background lanes and Arena lanes run through the same `runTurn`, so they wait the same way and show in the Tasks list. Their badge in the Lanes pane reads "Waiting".

## In the panel

- **Running row.** While a call waits, the clock gives its place to the wait: an icon (`debug-disconnect` offline, `watch` limited), "Offline, retrying in 12s" or "Limited until 14:05", and Retry now. Stop is the row's usual Stop. The row's title holds the failure. No model call goes out during a wait, so below 460px the row drops the model and the context ring. Below 360px it also drops the mode's name, the `/` button and the wait's icon, and Retry now keeps its icon and its accessible name but drops its label. The wait's words stay whole, and at a 300px panel everything fits.
- **Rail.** A waiting turn shows no Thinking step, since no model is thinking.
- **Clock and cost.** The clock and the turn header ("worked for …") leave waits out (`workedMs` in `transcript.ts`). The cost counts only the calls that answered, because a call that never reached the provider costs nothing.
- **Tasks list.** A waiting task's badge reads the same words in the `wait` tone.
- **Turn header.** While a call waits, the turn header reads "waiting for the network" or "waiting for the rate limit".
- **Setting.** `gcode.resume.afterLimit` (`short`, `always`, `off`) reaches the engine as `GCODE_RESUME_AFTER_LIMIT`. A change restarts the engine connection, as the other engine settings do, and applies to turns that start after it. The `always` text warns that unattended use can break a plan's interactive-use rule, as `research/t3code-2026-10.md` section 3.2 notes for the Coding Plan.

## ACP

There is no ACP session update for a wait, so Geno uses the existing `notice` with `_meta["gcode/waiting"]`. A client without notices hears nothing until the turn ends, as with a retry.

## Choices made in this unit

- A no-status connection failure counts as `offline` only when none of the answer streamed. After the stream began, a break is `transient`, and the next try decides.
- A 429 is always `limited`, so a short `retry-after` waits too. The quick-retry path now serves only 408 and 5xx, and overloads.
- OpenRouter's daily free-model cap (`free-models-per-day`) moved from `quota` to `limited`, because it resets.
- Billing errors stay `quota` and fail at once, because waiting cannot fix a bill.
- With no known reset, the limit backs off from 15s to 5 minutes and gives up 15 minutes after the wait began.
- A limit longer than the setting allows holds for Retry now rather than failing, as T3 Code's "Limited" state does.
- The engine takes up waits through the log's `by` field and a pid check, with no separate index file.
- The setting reaches the engine through its environment, like the other engine settings.
- A waiting task raises no notification. It shows in the running row and the Tasks list.

## Deferred

- An Arena run whose engine stopped does not rank its lanes after the lanes resume, because the run's bookkeeping lived in the old process. This is true of any engine restart, not only one during a wait.
- Claude Code's `rate_limit_event.resetsAt` and Codex's `account/rateLimits/updated` come with the ACP backends of U15 and U33. The `limited` class and the `resetAt` field are ready for them.
- A subagent's wait shows in its parent's task. Retry now wakes only the parent's own call.
