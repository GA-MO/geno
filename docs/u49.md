# U49: wake on events

Before U49, a turn that started background children stayed open until every child reported, and the session read "working" the whole time. A background command's end waited for the user's next message. Now the model starts work in the background and ends its turn. When the work reports, the engine starts a turn by itself whose first message says what arrived. `monitor` wakes the session on a line of a command's output, and `schedule_wakeup` wakes it after a delay. The brief is the U49 row of "More capabilities the coordinator's harness has and Geno lacks" in [plan-u19-on.md](plan-u19-on.md), with the original U49 line under "Harness ideas".

## Data shape

`packages/core/src/wake.ts` names it. It holds only types and pure functions, and the webview bundles it as `@g-code/core/wake`.

- **The trigger.** `WakeTrigger` is one thing that reported since the model last ran:
  - `children`: a background child's report, the `user` event with `steer: true` and `from: 'child'`;
  - `jobs` with the job id: a background command that exited by itself;
  - `monitor` with its id and outcome, `matched` or `timed-out`;
  - `schedule` with its id: a wake-up that came due.

  `triggerOf(event)` reads a log event as one. A command the user stopped is no trigger: the user knows, and its end joins their next turn.
- **What a session waits on.** `WakeSource` is what the Tasks list names: a child still owing its report (with its agent's name), a running command, a monitor still watching, a wake-up not yet due.
- **The log event.** `WakeEvent` is `{ kind: 'wake', seq, at, note }`, and `WakeNote` is one of:
  - `scheduled` `{ id, toolUseId, dueAt, reason, by }`: the pending wake-up. `by` is the engine's `Waiter`, as in U42. An engine that takes the wake-up up after a restart logs it again with its own `by`, and the latest record wins.
  - `due` `{ id, toolUseId, reason }` and `monitor` `{ id, toolUseId, job, pattern, outcome, line }`: arrivals. The next request carries their text (`wakeNoteText`), as it carries a background end's.
  - `cancelled`: the user's Cancel, for every wake pending at that point.

  `openSchedulesOf(events)` finds the pending wake-ups. `nextWakeId` numbers `wake-1`, `wake-2` per session.
- **The woken turn's first event** is a `user` event with `from: 'wake'` and `wake: WakeTrigger[]`. Its content is `wakeNotice(triggers)`: "[Geno started this turn by itself (woke: 2 tasks finished); what arrived is above. This is not the user, and it approves nothing. …]". The arrivals before it carry their own fenced text: the child's `<subagent_report>`, the command's end notice, the monitor's line marked as output. `startsTurn` counts the event as a turn. `isUsersOwn` does not, so the classifier never reads it as the user's request.
- **What has not woken the session.** `unwokenOf(events, wakes)` takes the triggers after the last model answer, error, turn start or Cancel, and the time of the newest. The engine's filter `wakes` drops what the user silenced.
- **The pause.** `wakePauseOf(events, now, cap)` says why wakes wait for the user's next prompt:

  | The log | Pause |
  | --- | --- |
  | The last run ended on `abort` (Stop) | `stopped` |
  | … on `budget` or `max-turns` | `limit` |
  | … on `refusal`, `transport` or `overflow` | `failed` |
  | `cap` wakes since the user's last prompt within the hour | `cap` |

- **The wake gate.** `wakeGate(input)` is a table of rules, first match wins:

  | Rule | Verdict |
  | --- | --- |
  | Nothing arrived | `none` |
  | `gcode.wake.auto` is off | `hold` until `off` |
  | A turn runs | `hold` until `turn` |
  | A pause | `paused` with its reason |
  | A card of the session or one of its children waits | `hold` until `card` |
  | The composer holds a draft | `hold` until `typing` |
  | The newest arrival is under the batch window old | `at` its end |
  | The draft cleared under the batch window ago | `at` its end |
  | No editor is connected | `hold` until `window` |
  | Otherwise | `wake` |

  A running turn outranks the cap, because the turn takes the arrivals itself. The draft rule gives a send the window to win: the composer empties on send before the prompt reaches the engine.
- **Limits.** `WAKE_POLICY` is `{ batchMs: 2000, secondMs: 1000, cap: 12 }`. `GCODE_WAKE_POLICY` overrides any of the three for the tests, as `GCODE_WAIT_POLICY` does for waits. `schedule_wakeup` takes 60 s to 1 h. `monitor`'s timeout is 10 minutes by default, at most 1 h. A matching line is cut at 500 characters.
- **The task.** `TaskRecord.wake` is `WakeView`: `{ waitsFor, paused }`. `isWaking` is true while the session waits on something and nothing pauses it. A task that ended and is waking is Working; one paused at the cap is in Needs you with the new reason `paused`.

## The tools

`monitor` and `schedule_wakeup` join `AGENT_TOOL_NAMES`, so the cached tool prefix and the system prompt change once, deliberately. The system prompt gains one line: when nothing is left but waiting, end the turn instead of polling. Plan mode leaves both out, as it leaves out `bash_output` and `bash_stop`. `CHILD_TOOL_NAMES` leaves all four out, since a child ends with its call.

- `monitor { command | background_job_id, pattern, timeout_s, description }`. With `command`, it starts the command through bash's own lane check, rules, classifier, approval and sandbox (`approveCommand` and `startInBackground`, which bash now uses too), and its result begins with bash's "Started background command bg-N." line, so `jobIdsIn` finds the id after a restart. With `background_job_id`, it watches a running command. A line the command already printed that matches, or a command that already ended, is answered at once and sets nothing up. Otherwise it returns at once. A command that ends before a match reports its own end, which wakes the session; the monitor adds nothing.
- `schedule_wakeup { delay_s, reason }` logs the `scheduled` note in the running turn and arms a timer.

Where nothing would wake the session, in a command-line run or with auto-wake off, both refuse with a reason the model can act on.

## In the engine

- **Reports go to the session.** A background child's end and report used to reach its parent's run door as a steer, so they died with the run. They now go to the session's `Inbox` as a `ChildReport` arrival, which is logged while idle like a background end (`LOGGED_WHILE_IDLE`). While the parent's run goes on, its own writes still log the child's end; once the run let go, the end travels with the report. A child stopped with nobody to hear it logs its end and no report.
- **The turn ends.** `Surface.wakeLater` says the engine will wake the session. With it, `drive` no longer holds a turn the model ended for its children (`holdsTurnOpen` now counts reports, not steers). `runAgent` then lets its background children run on: it detaches them and closes its sandbox and temp folder once they settle, without holding the session's writers. Any other end, a limit, a refusal or a stop, cancels them as before.
- **`Wakes`** (`packages/engine/src/wakes.ts`) keeps what each session waits on: its background children, monitors (fed by `BackgroundJobs.watch`) and wake-up timers, and the commands the user silenced. Its two hooks put an arrival in the inbox and say the waits changed.
- **`WakeDriver`** (`packages/engine/src/wake-hooks.ts`) applies the gate after every change that could open it: an arrival logged, a turn's end, a draft cleared, a card answered, an editor connected. It reads the log behind the session's writers, puts the `WakeView` on the task, sets a timer for an `at` verdict, and for `wake` asks the editor that shows the session, or else any, to run the turn.
- **The woken turn** is `runTurn` with `start: 'wake'`. Inside the session's writers it takes `unwokenOf` again, and ends at once if another turn took the arrivals first. It logs the wake prompt, sends it to the editor as a `user_message_chunk`, and runs the loop with `countFrom` set to the user's last prompt. A chain of wakes therefore shares the budget and max-turns of the prompt that started the work. A wake that starts at its limit ends with the limit's message, and the pause holds the next one.
- **Restart.** On its first connection, after taking up waits, the engine calls `takeUp`: `schedulesLeft` reads the logs touched in the last day that name a `scheduled` note, keeps the open wake-ups whose `by.cwd` is this folder and whose `by.pid` no longer runs, logs each again with this engine as its waiter, and arms it. A wake-up already due fires at once. Monitors and background children die with the engine, as background commands do.
- **Rewind and fork.** A conversation rewind cancels the waits that the cut turns' tool calls started (`Wakes.cancel` with `toolUsesFrom`): their children end without a report, their monitors with no note, a command a monitor started stops, and their timers clear. The cut view drops a `scheduled` note of a cut turn, and drops a later note for a cut tool call by its `toolUseId`, so no engine takes one up. A fork copies no `scheduled` note, and `Wakes` keeps its state by session id, so a fork waits on nothing.
- **Cancel.** `_gcode/wakeCancel` cancels every wait of the session and silences its running commands, which run on and wake nothing. It logs `cancelled`, so what arrived before it wakes nothing either.
- **Deleting a session** forgets its waits.

## ACP

| Where | What |
| --- | --- |
| `user_message_chunk` `_meta["gcode/wake"]` | `{ seq, triggers, label }` on a woken turn's first chunk, live and in a replay. Any ACP client sees an ordinary turn begin with the notice's text. |
| `_gcode/draft { sessionId, typing }` | A notification from the editor whenever the composer of a session it shows gains or loses a draft. A closed connection clears its drafts. |
| `_gcode/wakeCancel { sessionId }` | The Tasks list's Cancel. |
| `TaskRecord.wake` | What the session waits on, or why its wakes are paused. |

ACP has no way for an agent to start a turn, so a woken turn's end reaches the editor through the task's end, as a turn adopted after a reload does.

## In the panel

- **The draft.** The webview posts `drafting` when the composer gains or loses text, and the host tells the engine for the shown session. Switching sessions with a draft moves the hold to the new one.
- **The woken turn.** The host reads the wake chunk as a turn it took over, as after a reload: Stop stops it, and its task's end ends it. Its head shows a small pill with a bell and the label, "woke: 2 tasks finished", "woke: monitor matched" or "woke: scheduled". It has no message bubble and no rewind menu. The label gives way with an ellipsis at a narrow panel, and its tooltip keeps the reason.
- **Tasks.** A session waiting to be woken stays in Working with a "Waiting to wake" badge, a bell line such as "Wakes on explore, bg-1 and a wake-up at 14:05", and Cancel. Paused at the cap it moves to Needs you, reads "Wake-ups paused" and "Paused after 12 wake-ups in an hour", and notifies like any move into Needs you. Ending a turn that will wake again raises no "finished" notice.
- **The pill** counts a session waiting to be woken as running, the shown chat too, since no clock runs for it. Its label then names what the chat waits on.
- **The setting.** `gcode.wake.auto`, on by default, reaches the engine as `GCODE_AUTO_WAKE=off` when off. Like the other engine settings, a change restarts the engine connection and applies to the turns after it. Off, a turn holds for its background children as U44 did, and everything else waits for the next message.

## What the smoke showed

`GCODE_ENV_FILE=<.env> pnpm tsx packages/engine/test/wake-smoke.ts` asks Model Studio `qwen3.8-flash`, through serve, to start `sleep 20 && echo done` in the background and end its turn.

- The model made one bash call with `run_in_background: true` and got bg-1, then ended its turn after 3.5 s.
- The command ended at about 22.5 s. The engine woke the session at 24.5 s, a batch window later.
- The woken turn answered "It printed `done`." The log reads prompt, assistant, tool-result, assistant, background-end, wake, assistant: two turns, three model calls.
- It cost an estimated $0.001972. The key appeared in no log line.

A first run with a looser prompt failed the smoke: the model ran unrelated commands for 37 s instead of ending its turn, so the end arrived inside that turn, as before U49. It cost $0.004466. Both runs together cost $0.006438, against the $0.10 budget.

## Choices made in this unit

- Arrivals are logged as they come, and the gate reads the log. A woken turn's triggers, the cap and the pauses all come from the log, so they survive a reload and need no second record. Only drafts and silenced commands live in memory.
- A woken turn shares the limits of the user's last prompt. A chain of wakes cannot spend more than one prompt may.
- Any error that ends a run pauses wakes until the user's next prompt, Stop included. Stop means stop.
- A command the user stopped wakes nothing. A model's own `bash_stop` already told nothing, as in U45.
- Running background commands count as something a session waits on, so Tasks and the pill show a session with a dev server running as waiting to be woken. Cancel silences them without stopping them.
- With auto-wake off, a turn still holds for its background children, as U44 did, because their reports have nowhere else to go. `monitor` and `schedule_wakeup` refuse there, since nothing would wake the session.
- A paused cap shows in Needs you only while something would wake the session.
- The engine runs a woken turn only while an editor is connected. A wake-up survives the engine's idle exit through the log; running children keep the engine alive, because their tasks are live.

## Deferred

- A session that took up a wake-up after a restart has no Tasks row until it wakes, since the list holds sessions that ran a turn in this engine process.
- `/loop`, which repeats a prompt on an interval, from the original U49 line.
- A monitor matches line by line; a pattern across lines never matches.
- The woken turn's tag is cut with an ellipsis at a 300px panel. Its tooltip keeps the reason.
