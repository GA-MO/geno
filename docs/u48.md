# U48: spin-off tasks

While it works, the agent can notice something worth fixing that is outside the current change: dead code, stale docs, a missing test, a TODO it confirmed, or a security issue seen in passing. It calls `spawn_task` with a title, a short reason and a self-contained prompt. Geno starts nothing. The panel shows a card in the turn and in the Tasks pane. One click on Start runs the prompt as a new task in its own lane (U24, U25). Dismiss removes the card. The agent can withdraw its own suggestion with `dismiss_task` once it is stale. The model is Claude Code's `spawn_task`. The brief is the U48 line of "Harness ideas" in [plan-u19-on.md](plan-u19-on.md).

## Data shape

`packages/core/src/spinoff.ts` names it. It imports only types, so the webview bundles it through the `@g-code/core/spinoff` export.

- **The suggestion.** `SpinoffOffer` is `{ id, title, tldr, prompt }`. `Spinoff` adds `toolUseId`, the spawn_task call whose step shows the card, and `state`.
- **The id.** `SpinoffId` is `task_` and 8 hex digits, short enough for the model to copy back. `spinoffIdOf(toolUseId, taken)` hashes the call's id (FNV-1a), so a call gets the same id live and in a replay. On a clash with an earlier suggestion it salts the hash.
- **The states.** `SpinoffState` is one of four:

  | State | Means | Set by |
  | --- | --- | --- |
  | `offered` | The card waits for the user | the spawn_task call |
  | `started` | `{ sessionId, lane }`: a session runs the prompt in its own lane | the user's Start |
  | `dismissed` | The user dismissed it | the user's Dismiss |
  | `withdrawn` | The agent took it back | a dismiss_task call |

  Every move leaves `offered` for good. `moveSpinoff(spinoff, move)` refuses any second move, with the reason, such as "task_1a2b3c4d cannot change: the user already started it as a task in lane remove-x". `openSpinoffNamed(spinoffs, id)` finds an open suggestion or says why there is none.
- **The events.** The offer and the withdrawal ride on the call's own result, as a todo list does (U56): a `tool-result` event carries `spinoff: SpinoffNote`, which is `{ kind: 'offered', offer }` or `{ kind: 'withdrawn', id }`. The user's decision is an event of its own, `{ kind: 'spinoff', id, decision }`. Like a mode switch, one made while a turn runs has no seq. It is not part of the conversation, so the model's prefix never changes because of it.
- **The fold.** `reduceSpinoffs(spinoffs, event)` and `spinoffsOf(events)` give every suggestion in the order offered, with its state. A move that names no suggestion, or one already settled, changes nothing. A refused call moves nothing.
- **The rules.** `parseSpawnTask` needs a title of at most 60 characters, a tldr of at most 400 and a prompt of at most 8,000, and refuses unknown fields. `offerOf` refuses a title that an open suggestion already has, whatever its case, and an eleventh open suggestion (`SPINOFF_LIMITS.open` is 10).

A cut keeps the user's decisions (`KEPT_BY_CUT`), as it keeps review decisions, and drops the cut turns' offers and withdrawals with their results. A fork copies what it copies of the log, so it starts with the suggestions as they stood.

## The tools

- **When they are offered.** `spinoffToolDefinitions(mode, attached)` gives both tools in Plan, Ask and Auto, and only to a client that advertises `gcode/spinoffs` (`SPINOFF_CAPABILITY`). The VS Code panel does. A non-interactive run and the terminal get neither, because nobody would see a card. A subagent gets neither: its tools come from its agent definition.
- **No approval.** Neither tool asks in any mode, Plan included. They change no file and start nothing.
- **Core or deferred.** Both are deferred. U46's rule keeps in full only the tools the loop uses nearly every turn, and a spin-off is rare. `spawn_task` is about 447 tokens in full and `dismiss_task` about 142, so sending them by name saves 531 tokens a call in every editor mode (see below). The tool_search hint is the description's first sentence: "Suggest a separate task for an issue you noticed that is outside the current change."
- **When to use it.** The description names the cases (dead code, stale docs, a missing test, a confirmed TODO, a security issue in passing) and the ones that are not (a vague code-smell impression, a guess not checked, anything small enough to fix in the current change). It says the prompt must stand alone with file paths, because the new task does not see the conversation.
- **The note.** A run that offers the tools adds `SPINOFF_NOTE` after the mode's system prompt, beside U46's note. It is one fixed sentence that names `spawn_task`, so the prefix holds across calls. The live smoke below is why it is there.
- **The results.** spawn_task returns "Suggested task_… "title". The user sees it as a card and can start it in its own lane; nothing was started. Go on with the current task. If it stops being worth doing, withdraw it with dismiss_task." dismiss_task returns "Withdrew task_… "title"; its card is gone." A refusal is an error result with the reason. Both read the suggestions from the session log on disk, so a decision the user made beside the running turn counts.

## In the engine

- `tools/spinoff.ts` holds the two executors. They parse the input by core's rules, and `drive.ts` copies `spinoff` onto the logged result. `sessions.ts` accepts the field and the new event.
- `runAgent` offers the tools when `options.spinoffs` is set, which serve sets from the window's capability.
- The panel learns about a suggestion from `_meta["gcode/spinoff"]` on the call's `tool_call_update`, a `SpinoffShown`. From a spawn_task result it is `{ kind: 'offer', spinoff }`. From a dismiss_task result it is `{ kind: 'move', id, state }`. Live, an offer is open. In a replay, `replayUpdates` folds the whole log first, so each offer carries the state it ended in.
- `_gcode/spinoffs/start { sessionId, id, mode }` reads the suggestion from the log and refuses one that is not open. It makes a lane named from the title with `laneFor`, names the new session after the title, and runs the prompt in the background with `startLaneSession`, in the mode new chats start in. Then it logs the decision and answers with the Spinoff. A second Start of the same suggestion while the first is still making its lane is refused. A workspace that is not a git repository is refused with the lane error, and the card shows it.
- `_gcode/spinoffs/dismiss { sessionId, id }` logs the decision and answers with the Spinoff.
- A decision is logged at once, beside a running turn or between turns, with no seq. The next request reads it, so a second Dismiss is refused rather than logged twice. Only a log with a torn last line falls back to the serial queue.
- `gcode session show` prints the offer, the withdrawal and the decision.
- `session-replay.ts` titles a replayed call `spawn_task <title>` or `dismiss_task <id>`, as it is titled live.

### A replayed turn's end

The live run showed a replayed turn that "worked for 29s" when it took 383 ms. A replayed turn ended at its last logged event, and a decision logged after the turn counted as part of it. A mode switch, an effort change, a rename and a review decision were counted the same way, because each lands in the log between turns. `turnOf` now leaves out `LOGGED_AROUND_TURNS`: the background reports it already skipped, and those settings and decisions. The engine e2e checks that the first turn ends at its answer.

## In the panel

- **The card in the turn.** A spawn_task call that ran draws as a card, not as a call (`rail.ts`, step `spinoff`). The card shows "Suggested task", the title, the tldr, a folded "Prompt it starts with", and Start, Dismiss and "Runs in its own lane". A running or refused spawn_task call stays a call. In compact detail the card stays in view when the turn folds, and the fold's summary does not count spawn_task calls.
- **Started.** The card folds to one row: "Started <title>", "in lane <name>" on its own line, and Open, which shows the lane's session in the panel. While a Start waits, the button reads "Starting…" and both buttons are off. If the engine refuses, the reason shows on the card and the buttons come back.
- **Dismissed or withdrawn.** The card is gone. A withdrawal leaves its dismiss_task call as an ordinary step.
- **The session's list.** The Tasks pane has a "Suggested in this chat" section above Needs you, with the shown chat's open suggestions, newest first, and a count. Each is the same card with Start and Dismiss. The section hides when nothing is open.
- **Where it lives.** The card's state lives on the spawn_task call's `ToolBlock` (`spinoff`). `withSpinoff` in `spinoff-model.ts` applies an offer to its own call, and a move to the card with that id, in whichever turn it is. A Start or Dismiss answer arrives as the `spinoff` action. `spinoff-view.ts` draws the card and `spinoff.css` styles it. High contrast draws the card's edges in the theme's border colours instead of a tint.
- **Width.** Titles, the tldr, the prompt and the lane name wrap. At 300px nothing leaves the transcript and nothing scrolls sideways.

## Live smoke

`pnpm tsx packages/engine/test/spinoff-smoke.ts` gives `qwen3.8-flash` on Model Studio a git workspace where `sub` in `src/math.ts` adds, and the same file has `legacyMul` under "TODO: delete legacyMul once nothing imports it". The prompt asks only to fix `sub` and does not name the tool. The run is in Auto, with the cards advertised. It passes when `sub` subtracts and a suggestion names `legacyMul` and `math.ts`, with a title of at most 60 characters.

| Run | Note in the prompt | Turn cap | Result | Cost |

| 1 | no | 12 | Fixed `sub`, then spent its turns verifying with `node` and `tsc`. Never loaded `spawn_task`. Failed. | $0.0131 |

## Choices made in this unit

- The offer lives on the call's result, as the todo list does, so cut, fork and replay need no rule of their own for it. The user's decision is a separate event, because no tool call makes it.
- A started task runs in a lane, never in the main checkout, so it cannot touch the files the current turn is changing.
- Start names the lane and the session from the title, not from the prompt's first words.
- The new task starts in the mode new chats start in, as Run in a new lane does.
- The session's list is a section of the Tasks pane, not a strip over the composer, which U47 is changing.
- A dismissed or withdrawn card is gone from the turn rather than shown struck through.

## Deferred

- Two spawn_task calls in one model response with the same title both go through: each checks the log, and the batch's results are logged together after it ends.
- A dismiss_task in the same response as its spawn_task finds no suggestion, for the same reason.
- `qwen3.8-flash` reached for the tool only late in a run that verified a lot. A cheaper run with fewer turns may end before it suggests anything.
- A subagent gets no spin-off tools. A forked subagent shares its parent's `tool_search` block, which lists them, but not their executors, so a call gets "unknown tool", as U46 notes for MCP tools.
- A replayed `tool_search` call shows no target, unlike the live one. This is older than U48.
