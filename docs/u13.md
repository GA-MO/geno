# U13: rules, memory, `/init` and `ask_user`

Geno now loads the user's own global rules, keeps notes the user approves across sessions, writes `AGENTS.md` on `/init`, and can stop to ask the user a question. The brief is the U13 section of `docs/plan-u11-u14.md`.

## Data shapes

- **Context sources.** `CONTEXT_SOURCES` in `packages/core/src/context.ts` names the load order: `global` (`$GCODE_HOME/AGENTS.md`), `instructions` (from the filesystem root down to the workspace), `cursor-rule` (`.cursor/rules/*.mdc`), and `memory`. The first three open the conversation through `LoadedContext`, which gained an optional `global` file. Memory goes in the system prompt. `appliedRules` lists what a session loaded, in that order, for the rules pane.
- **Memory entry.** `MemoryEntry` in `packages/core/src/memory.ts`: `id`, `text`, `scope` (`project` or `global`), `createdAt`, and `sessionId`, the session whose `remember` call proposed it.
- **User tools.** `USER_TOOL_MODES` in `packages/core/src/user-tools.ts` is the table of which modes offer `remember` and `ask_user`. `AskUserRequest` is `{ question, options }`, and `AskUserAnswer` is `answered` with the text, or `declined`.

## In the engine

- **Global rules.** `loadProjectContext(workspace, home)` reads `$GCODE_HOME/AGENTS.md` before the project's files. A missing or blank file loads nothing. The session log records it, so a resumed session sends the same bytes.
- **Memory store.** `packages/engine/src/memory.ts` keeps `memory/global.json` and `memory/projects/<sha256 of the workspace's real path>.json` under the app home, never in the repository. Each write goes to a temp file and is renamed into place. A note holds at most 500 characters and all notes together at most 4,000. A deleted note moves to `trash/memory/<id>.json`.
- **Memory in the prompt.** `renderMemory` adds the notes to the system prompt, global first, then the project's, each oldest first, inside a `<memory>` fence. The text around them says they are notes the user approved and that they never override the current request. The bytes change only when memory changes.
- **`remember`.** It takes `{ text, scope }`. It asks the user every time, in every mode that offers it, Auto included: no rule, mode or classifier answers it. The question is ACP `session/request_permission` with the note under `_meta["gcode/remember"]`, and only the Remember option saves it. A note over the caps is refused before the user is asked. It is offered in Plan, Ask and Auto, never in a non-interactive run.
- **`ask_user`.** It takes `{ question, options? }` and is offered in Plan and Ask only. It uses ACP's own `elicitation/create` in form mode, scoped to the session and the tool call: a `choice` field whose `oneOf` lists the options, and a free-text `answer` field. The reply becomes the tool result. Cancelling the turn sends `$/cancel_request` for the open question.
- **Client capabilities.** A client gets `remember` only when it sets `_meta["gcode/memory"]`, which says it shows the memory card, and `ask_user` only when it advertises `elicitation.form`. A client that sets neither, and `gcode agent` at the terminal, never sees either tool. The two tools follow the built-in tools in a request, so the built-ins keep their cached place.
- **`/init`.** The built-in now runs one agent turn on a fixed prompt (`BUILTIN_COMMANDS.init.turn` in `packages/core/src/commands.ts`). The agent reads the project and creates or updates `AGENTS.md`. When the file exists, the agent keeps what the user wrote. The edit is an ordinary edit, so in the editor it goes through `fs/write_text_file` and review, and Plan refuses it. The prompt is written for Geno. The idea, an agent that surveys the project to write its instructions file, comes from OpenCode; no text was copied.
- **ACP methods.** `_gcode/rules` returns the session's rules and the global rules path. `_gcode/globalRules` creates the global file when it is missing and returns its path. `_gcode/memory`, `_gcode/memoryEdit` and `_gcode/memoryDelete` list, edit and delete notes, each answering with the memory.
- **Watches.** `session/close` now stops the session's command folder watches (`SessionCommands.detach`).

## In the panel

- **`/rules` and `/memory`.** These are now editor built-ins. Each opens a pane in the transcript's place, like History and MCP. The rules pane lists each file the chat loaded, in load order, with where it came from and when it applies: always on, the globs that attach it, or the description it is requested by. A row opens its file. **Edit global rules** creates `$GCODE_HOME/AGENTS.md` when it is missing and opens it. The memory pane groups notes under **Every project** and **This project**, with Edit and Delete on each.
- **Cards.** The remember card and the question card are permission cards: the same block, action, rail step and renderer as the approval card, told apart by `PermissionBlock.ask`. Whatever keeps a waiting permission visible keeps them visible too. The remember card quotes the exact note and offers Remember and Don't remember. The question card offers the options as buttons, a free-text answer, and Skip.

## Check

- Unit tests. `packages/core/test/memory.test.ts` covers the load order, the memory rendering and its stable bytes, the caps, the user tool mode table, and the question form. `packages/engine/test/memory.test.ts` covers the store round trip, the trash, the caps, the global rules file, `remember` asking in Plan, Ask and Auto (an instruction-like note included), and `ask_user` refused after a switch to Auto.
- Serve e2e tests. `packages/engine/test/memory-serve.e2e.test.ts` covers remember through ACP with the memory in the next prompt, a declined note, the memory methods, a client without the capabilities, the `ask_user` round trip and its cancellation, the rules methods, and `/init` editing `AGENTS.md` through the editor. `serve-commands.e2e.test.ts` checks that a closed session publishes no more command lists.
- `packages/extension/test/context.integration.test.ts` drives the real panel through `/rules`, Edit global rules, a remember card, a question card, and the memory pane with edit and delete.
- Three defects were put in on purpose to see the tests fail. Letting Auto skip the remember question fails with `auto asks: expected [] to deeply equal [ { …(2) } ]`. Offering `ask_user` in Auto and non-interactive runs fails the mode table. A card showing a truncated note fails with `the card shows the exact note; got "Use pnpm for every insta"`.
