# E7: the review surface

E7 asks which surface you use to review agent edits: in-editor hunks with Keep and Undo, or a side-by-side diff. Phase 6 built both, and E7 cannot be settled without a week of real use. This page lists what exists and what to watch for.

## Surfaces built

**Hunks in the editor.** Every edit the engine writes becomes hunks under review (`packages/extension/src/review/`). Added lines get the diff editor's inserted-line background and a mark in the overview ruler. Removed lines get a red bar in the gutter on the hunk's first line, and hovering it shows the removed text. A `Keep | Undo` CodeLens sits above each pending hunk. Undo puts the old text back through a `WorkspaceEdit`, so Cmd-Z takes the undo back. A file that was saved before the undo is saved after it.

**The Changes view.** It sits under Chat in the g-code side bar. It lists each file the session changed, with counts by status (`2 pending · 1 kept`), and each hunk with its first changed line and status. A file row has inline `Open diff`, `Keep all` and `Undo all`, and a pending hunk row has `Keep` and `Undo`. The view title has `Undo all changes of the session`, which restores the session's first checkpoint through the engine's rewind (`_gcode/rewind`, the same `rewindTo` as `gcode rewind`).

**Diff against the checkpoint.** `g-code: Open Diff Against Checkpoint` opens `vscode.diff` between the file at the session's first checkpoint, served on the `gcode-checkpoint:` scheme from the engine's shadow repo, and the file now. The diff shows everything since the session started, including hunks already kept and your own edits.

**Cmd-K.** `g-code: Edit Selection` (`cmd+k cmd+i`) asks for an instruction and sends the selection's line range, the file through the buffer bridge, and the file's current diagnostics to the engine as a one-shot edit. The model gets the edit tool only and at most four calls. The edit lands through the same applier and comes back as hunks with the same controls.

**State.** The engine logs each edit's hunks on its tool result and each decision as a `review` event in the session log. A rewind marks everything after the restored checkpoint undone. After a window reload, the extension resumes the session (ACP `session/resume`), asks for the review state (`_gcode/review`), and finds each pending hunk's text again near the line where it was written.

## What to watch for during use

- **Which surface you reach for.** Note whether you resolve hunks from the CodeLens, from the Changes view, or by opening the diff. E7's metric is review time, from the end of a turn to no pending hunks, plus hunks you later revert by hand. Neither is logged automatically yet. The `review` events carry timestamps, and the turn's last event carries its end time, so review time can be computed from the session log.
- **Hunks that drift.** A hunk follows edits around it. An edit that overlaps a hunk widens it to cover the new text, and Undo then replaces your edit inside it as well. Watch for undos that take more than the agent wrote.
- **Overlapping agent edits.** Two edits from one turn to the same lines produce two hunks whose spans overlap. Undoing the older one restores text the newer one replaced. If this happens often, merge overlapping hunks when they are tracked.
- **Reload restore.** A pending hunk whose text can no longer be found after a reload is shown as kept, and the engine output channel says so. Watch for hunks that disappear this way.
- **Undo all and unsaved buffers.** Undo all saves the session's touched files that have unsaved changes before it rewinds, because checkpoints snapshot the disk. Unsaved text of your own in those files is saved and then rewound with the rest. The shadow repo keeps a "before restoring" commit, so the text can be recovered from there, but nothing in the UI does it.
- **Saving.** An agent edit to a file with no unsaved changes is saved at once, so the disk and checkpoints match what you see. An open file that already has unsaved changes stays unsaved. Watch whether the immediate save surprises you, for example by triggering a file watcher in the middle of a turn.
- **The keybinding.** `cmd+k cmd+i` replaces VS Code's Show Hover chord when an editor has focus. If you miss Show Hover, rebind one of them.
- **Cmd-K and the conversation.** Inline edits run in the same session as chat, so the next chat turn sees them in its history, and Undo all covers both. If that mixes concerns badly, give Cmd-K its own session.
