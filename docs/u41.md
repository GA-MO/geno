# U41: sign in to Cursor with an API key, and install the CLI yourself

The Agents card for Cursor now signs in two ways: through the browser with `agent login`, as in U40, or with an API key that Geno keeps in VS Code's secret storage. Geno never downloads Cursor's CLI or runs its installer. When the CLI is missing, the card shows how to install it, and Geno looks again when the window gets the focus back.

## Scope, and what changed on the way

The brief first asked Geno to install its own copy of Cursor's agent from the ACP registry. The user then decided that Geno must not download or install Cursor's CLI by any route. That work was built and then removed before it merged, so nothing of it is in the tree: no registry fetch, no `~/.g-code/agents/`, no download or archive code. U40's "Install Cursor CLI" button, which opened a terminal and typed the installer, is gone too, with its `installing` state.

What stays from the registry research: the ACP registry (`https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json`, read 2026-10-06) lists `cursor` at `2026.10.01`, with per-platform `.tar.gz` and `.zip` archives on `downloads.cursor.com`, `cmd` `./dist-package/cursor-agent` and `args` `["acp"]`, and no `sha256`. Some other agents in the registry do publish a `sha256`. Should a later unit want a managed copy, it would rest on HTTPS and a host check alone, because Cursor publishes no checksum.

## What the user sees

| State | The card shows |
| --- | --- |
| Not installed | "Geno needs Cursor's CLI…", the official command `curl https://cursor.com/install -fsS \| bash` with Copy, "Geno looks again when this window gets the focus back", Open the install page and Check again |
| Signed out | The CLI's path, its version with Update, "Signed out" with Sign in, and the "Use an API key" field |
| Signed in by browser | The account `agent about` names, with Sign out |
| Signed in by key | "API key", with Remove key in place of Sign out |
| Signing in, Signing out, Updating, Error | As in U40 |

- Copy puts the command on the clipboard through `vscode.env.clipboard`, and the button reads "Copied". Nothing runs.
- Open the install page opens `https://cursor.com/docs/cli/installation` with `vscode.env.openExternal`.
- Geno finds the CLI as U40 does: Homebrew's folders, PATH, then `~/.local/bin`, named `agent` or `cursor-agent`.
- When the window gets the focus back (`vscode.window.onDidChangeWindowState`), Geno checks again if the CLI was missing. It checks only then, so coming back to the window never reruns `agent about` on a CLI that is already installed.

## API key

- The key goes from the page to SecretStorage as `gcode.agents.cursor.apiKey`. The page clears the field at once and keeps no copy. Nothing sends the key back to the page.
- Geno passes the key only in the env of the CLI's own processes, as `CURSOR_API_KEY` (`agentEnv` in `agents-model.ts`). That covers the status check, sign-in, sign-out and update. The key never goes in argv, the output channel, settings JSON or the engine's env.
- The engine reads only secrets named `gcode.apiKey.*`, now named `ENGINE_SECRETS` in `runtime.ts`. A change to any other secret, such as this key, no longer restarts the engine.
- With a key stored, the card shows the account as "API key", whatever `agent about` says. Sign out is not offered, because the key is not a login the CLI keeps. Remove key deletes the secret and checks again.
- Browser sign-in runs `agent login` on the CLI that was found, as in U40.

## Billing

Next to the field the card says "May bill by usage instead of your plan". Cursor's SDK, started with `CURSOR_API_KEY`, is billed as token consumption (https://cursor.com/blog/typescript-sdk). `research/cursor-backend-2026-10.md` infers from that, without a page that says so for the CLI, that a key may bill as usage rather than against the plan's pools. Browser sign-in is the way to use the plan.

## Data shape

In `agents-model.ts`, pure and shared with the page:

- `AuthSource`: `{ kind: 'browser', account }` or `{ kind: 'api-key' }`. The `signed-in` state carries one.
- `CheckResult` gains `apiKey`, whether a key is stored. The reducer turns a found CLI with a key into signed in by key, and refuses `logout` in that state.
- `ExternalAgent` gains `keyEnv` (`CURSOR_API_KEY`). Its `install` holds only the command to show and the page to link.
- `agentEnv(agent, base, key, extra)` builds a process's env, and adds the key only when one is stored.

`agents-host.ts` holds the effects: SecretStorage, the clipboard, `openExternal` and the focus listener. The page's new messages are `agents-copy-install`, `agents-key` and `agents-remove-key`.

## Checks

- `packages/extension/test/agents.test.ts`: every state transition, signed in by key whatever the browser login says, no sign-out by key, and `agentEnv` with and without a key.
- `packages/extension/test/agents.integration.test.ts` launches VS Code with PATH set to an empty folder and `/usr/bin:/bin` and HOME set to an empty folder. The fake `agent` logs each call's argv, whether NO_OPEN_BROWSER was set and whether `CURSOR_API_KEY` was set. It writes the command to `keyed.log` only when the key equals the one the suite typed, and it never prints the key.
  - Missing: the command, Copy (the clipboard then holds the command), the install link, no install button, no terminal opened, nothing run, and the card's fit at 300px.
  - Focus: the suite writes the fake onto PATH. It opens a second VS Code window, so the test window loses the focus, then closes it over CDP. The card turns signed out without a click. With the focus check broken on purpose, this step times out.
  - Then the U40 flows: browser sign-in with the redacted link, Cancel, sign-in, Update, and Sign out with its confirm (Cancel first).
  - Key: typed into the field, then signed in as "API key" with Remove key and no Sign out. The status check, and later Update, ran with exactly that key in env (`keyed.log` reads `about`, then `about, update, about`). No logged argv holds the key. Neither the page nor any message the page received holds it.
  - Remove key: the next check runs without a key. The call sequence and the NO_OPEN_BROWSER rules are asserted as in U40.
- Also run: the `settings`, `composer` and `modes` integration files, and the `.vsix` clean-install test on the current VS Code and on 1.109.2.
- Not tested: the install link's click and the sign-in link's click. Each would open a real browser on the test machine.
