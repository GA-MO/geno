# U54: editor actions for the model

The model can now point the user at something in the editor. It can open a file at a line, open the diff of a file against a checkpoint, and select a file or folder in the Explorer. The coordinator's harness does this with clickable paths. Geno now does it with three tools. The contract is the U54 row in the table at the end of `docs/plan-u19-on.md`.

## The tools

| Tool | Input | What the editor does |
| --- | --- | --- |
| `open_file` | `path`, `line?`, `column?` | Opens the file as a pinned tab, puts the cursor at the line and column, and scrolls the line into the middle of the editor if it is out of view. |
| `reveal` | `path` | Selects the file or folder in the Explorer. |
| `show_diff` | `path` | Opens `vscode.diff`. The left side is the file at the checkpoint before the current turn, and the right side is the file as it is now. If the turn did not change the file, the left side is the session's first checkpoint. |

The tools change what the user sees. They never change a file, so they need no approval, and Plan, Ask and Auto all offer them. A non-interactive run never gets them, because nobody is there to see the editor.

## Rules

- **Paths.** Each path goes through `resolveInside`, the same check that `read` uses. A path outside the workspace and its readable roots is refused, including one that leaves through a symlink. `reveal` and `show_diff` also refuse a readable root outside the workspace folder. The Explorer cannot show such a path, and a checkpoint holds only the workspace. `open_file` and `show_diff` refuse a folder and name `reveal` in the message. A refused call never reaches the editor.
- **The capability gate.** The extension advertises `gcode/editor-actions` in the ACP client capabilities `_meta`. The engine offers the tools only to a client that sends this flag. A headless `gcode agent` run sends no flag. `runAgent` also drops the tools for a non-interactive approval, whatever the caller passes.
- **The editor.** The engine sends `_gcode/editorAction { sessionId, action }` to the editor that shows the session now. If no editor shows it, the call fails with a message that the model reads.
- **Which checkpoint.** `show_diff` compares the file's text at the turn's first checkpoint with the file's text now. The current text comes from the editor's buffer. This means a change that a `bash` command made counts as a change by the turn. The engine sends the chosen checkpoint's `sha`. The extension's `gcode-checkpoint:` document asks `_gcode/checkpointText` for that `sha`. The engine refuses a `sha` that is not one of the session's checkpoints.
- **The prefix cache.** The three definitions follow the user tools and `show_widget` in every request. They are sorted, and they are built from one fixed table. Adding them changed the cached tool prefix once, and the prefix stays stable from call to call.

## The step

Each call that ran shows as one small row on the rail, for example "Opened `util.ts:45`", "Showed the diff of `a.ts`" or "Revealed `src` in the Explorer". A diff against the session's first checkpoint reads "since the session began". Click the row to do the action again. A compact turn keeps these rows in view when it folds its work, because they are where the model pointed. A call that is still running, or that was refused, shows as an ordinary call step with its error.

The action is logged on the tool result. A reloaded or replayed session draws the same rows, and its rows work when clicked.

## Data shape

- `EditorAction` in `packages/core/src/editor-actions.ts` is a union. The kinds are `open` (a path, and an optional line and column), `diff` (a path and a `DiffBase`) and `reveal` (a path). Paths are absolute real paths. Lines and columns count from 1.
- `DiffBase` is `{ sha, since: 'turn' | 'session' }`.
- `EDITOR_ACTIONS_CAPABILITY` (`gcode/editor-actions`), `EDITOR_ACTION_METHOD` (`_gcode/editorAction`) and `EDITOR_ACTION_META` (`gcode/editor-action`, on the closing `tool_call_update`).
- `ToolResultEvent.editorAction` keeps the action in the session log. Its schema is `editorActionSchema` in `packages/engine/src/tools/editor.ts`.
- In the extension, `RUN` in `chat/editor-actions.ts` maps each kind to the VS Code call that carries it out. `STEPS` in `chat/editor-step.ts` maps each kind to the words on its row. The rail has a new `editor` step kind.

## Decisions

- The engine sends real paths. The extension maps each real path onto the workspace folder's URI through `editorUri`, as the file bridge does. Without this mapping, on macOS a workspace under `/var` opened a second `/private/var` document next to the user's document. The integration test found this.
- `reveal` moves the side bar to the Explorer. If the chat shares the side bar, the chat goes out of view. This is what revealing means. A user who wants both in view can move Geno to the secondary side bar.
- In the fold summary, the three tools count as "used N tools", with the other tools of kind `other`.

## Tests

- `packages/engine/test/editor-actions-serve.e2e.test.ts` checks these behaviors:
  - The tools are offered as one sorted block only to a client with the flag. A client without the flag, and a non-interactive `runAgent`, do not get them.
  - Plan mode runs `open_file` and `reveal` without a permission request. The editor gets the exact actions, and the closing update carries the action.
  - Five refused paths never reach the editor: `../`, an absolute path outside, a symlink out, `/etc/hosts` and a folder for `open_file`.
  - `show_diff` picks the turn's checkpoint for a file the turn changed, and the session's first checkpoint for a file an earlier turn changed. The left sides hold the old text, and an unknown `sha` is refused.
  - A loaded session replays the action.
- `packages/extension/test/editor-step.test.ts` checks the row's words, the `editor` step on the rail, and that a compact turn keeps the row in view.
- `packages/extension/test/editor-actions.integration.test.ts` runs one fake-model turn in VS Code. The turn edits `a.ts`, then calls `show_diff`, `reveal` and `open_file`. The suite checks that the cursor lands on line 45 of `src/util.ts`, and that the line is in view. It checks that a diff tab opens with a `gcode-checkpoint:` left side that holds `a.ts` before the edit, and with `a.ts` itself on the right side. It checks that the Explorer selects `src`. `explorer.autoReveal` is off, so only `reveal` can move the selection. The suite then clicks each row and checks the same three results again.
- Live smoke: `pnpm tsx packages/engine/test/editor-actions-smoke.ts`. In Plan mode, qwen3.8-flash on Model Studio is asked "Where is parseConfig defined? Open it for me." On 2026-10-07 it searched twice with `grep`, tried three files, and called `open_file src/config.ts:31`, the line of the definition. It then looked at four more paths until the run reached its limit of 6 model calls. The run used 6 model calls, with 25,494 tokens in and 633 tokens out. The estimated cost was $0.0043 against a budget of $0.03. Model Studio does not price this model, so the estimate uses the per-token rate of the probe.

The screenshots of the rows in dark glass, light glass and high contrast, and at 300px, are in `docs/media/u54/`, from the macOS integration run with `GCODE_SCREENSHOTS` set. There are two sets, `editor-steps` and `editor-steps-300`, each as the window and as the panel alone (`-panel`).
