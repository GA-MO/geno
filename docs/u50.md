# U50: rewind and fork from the panel

Each of the user's messages in the chat has a menu with Restore files, Restore conversation, Restore both and Fork from here. Before U50, `gcode rewind --session <id> --to <turn>` restored files from the command line only, and nothing forked. The brief is the U50 section of `docs/plan-u19-on.md`. Fork is the first part of U32 in `research/competitors-2026-10.md` section 5. Side chats and handoff stay for later.

## Data shape

`packages/core/src/rewind.ts` names it. It holds only types and pure functions.

- **The rewind choice.** `RewindChoice` is `{ kind: 'files' }`, `{ kind: 'conversation' }` or `{ kind: 'both' }`. `REWINDS` maps each kind to whether it restores files and whether it cuts the conversation.
- **The cut event.** `CutEvent` is `{ kind: 'cut', seq, at, turnSeq }`. `turnSeq` is the event number of the prompt that went back to the composer. The log is never truncated or edited. A rewind of the conversation appends one line.
- **The fork's origin.** `ForkOrigin` is `{ sessionId, turnSeq, title }`, on the fork's `session-start` as `fork`. `title` is the source's title at the time of the fork. History rows (`SessionSummary.forkedFrom`) and task records (`TaskRecord.forkedFrom`) carry it.
- **A turn's name.** The panel names a turn by the seq of its prompt. A replayed turn carries it in `ReplayedTurn.seq`. A live turn gets it from the prompt response's `_meta["gcode/turnSeq"]`. A lane apply has no prompt, so it has no seq and no menu.

### The cut view

`cutView(events)` is the session as of its cuts. `readSessionLog` applies it, so every reader sees the same session: the next request (`replayMessages`), `session/load`'s replay, History's counts, review state, waits and `nextSeq`. A cut drops its prompt and everything logged after it, except these kinds, which hold after the cut:

| Kind | After a cut |
| --- | --- |
| `mode`, `effort`, `backend-model` | kept: they are the user's settings |
| `title` | kept |
| `review` | kept: a decision on an earlier turn's hunk stays |
| everything else, including `checkpoint`, `restored`, `child-*`, `background-end`, `wait`, `lane-apply`, earlier cuts | dropped |

The cut event takes the place of what it dropped, so it holds the highest seq and numbering goes on from it. An event logged later for a tool call the cut dropped is dropped too. This covers a stopped background command's `background-end`. A cut whose prompt is not in the view (a steer's seq, or a prompt an earlier cut dropped) cuts nothing.

### The fork's copy

`forkEvents(events, turnSeq, fork)` takes the cut view up to and including the turn at `turnSeq`, which runs up to the next prompt or lane apply. It writes a new `session-start` with the new id, the source's loaded context and `fork`. It copies every event of those turns in order, but `wait`, which the engine would take up again, and `cut`, already applied. Checkpoints take the fork's session id. Their commits stay in the workspace's shadow repo, so the fork restores files before any of its turns on its own lineage. `promptAt`, `turnEvents`, `checkpointOfTurn` and `toolUsesFrom` answer the engine's other questions about a turn.

### Steers and children

A steer (U44) is a `user` event with `steer: true` inside its turn. `startsTurn` leaves it out, so a steer never starts a turn and never has a menu. A cut at an earlier turn keeps a later turn's steers out with the rest of that turn. A cut at a later turn keeps an earlier turn's steers where they landed. A fork copies the steers of the turns it takes, at the same seqs. A child's `child-start` and `child-end` stay with their turn the same way. The child's own log is not copied. Both sessions point at it.

## In the engine

`packages/engine/src/rewind.ts`:

- `rewindPreview` lists the paths a restore would rewrite or delete: the work tree against the turn's checkpoint, untracked files included. It also lists the paths changed since the session's last checkpoint (`changedSince` in `checkpoints.ts`). No checkpoint holds those edits, so a restore loses them.
- `rewindSession` restores the turn's checkpoint first, if the choice includes files, and logs `restored`. Then it logs the cut, if the choice includes the conversation. In Restore both the cut drops the restore's notice, since the turns it is about are gone. Restore files alone keeps the notice, and the next request tells the model which files changed. It returns the prompt as the user typed it: a command goes back as `/name args`, not its expansion.
- `forkSession` writes the fork's log in one write and copies the source's session folder (attachments and widgets), so the fork's replay shows its images.

An external agent session (Cursor, Claude Code) keeps its own conversation, so the engine refuses a conversation rewind and a fork for one. A subagent's own session cannot be forked.

## ACP

| Method | Does |
| --- | --- |
| `_gcode/rewindPreview { sessionId, turnSeq }` | `{ files, unsaved }`, paths relative to the session's workspace. |
| `_gcode/rewindTurn { sessionId, turnSeq, choice }` | Rewinds. `{ files, prompt }`. Refused while a turn runs. |
| `session/fork { sessionId, cwd, _meta["gcode/forkAt"] }` | Forks up to and including that turn, or every turn without the key. Refused while a turn runs. |

ACP has no rewind, so the rewind methods are ours. ACP's unstable `session/fork` fits fork, so the engine advertises `sessionCapabilities.fork` and implements it. No `_gcode/fork` exists, because the only client is ours and it always sees the capability. The fork's `cwd` is the source's folder. A chat of the main checkout forks into the main checkout. A lane's chat forks in its lane. Running a fork in a new lane is not part of fork. Run in a new lane stays a separate choice.

The answers name paths relative to the workspace. VS Code's own path of a temp folder under `/var` differs from the engine's `/private/var`, so absolute paths did not shorten in the panel.

## Cancelled and stopped work

- **Subagent children.** A rewind or fork is refused while a turn runs. A background child holds its parent's turn open until it reports (U44), so no child of the session runs when a rewind is allowed. The panel shows no menu while a turn runs.
- **Background commands (U45).** A conversation rewind stops, as the user, every background command that a tool call in the cut turns started (`toolUsesFrom`, then `jobs.stop`). Their ends are logged after the cut, and the cut view drops them, so the model never hears of them. A files-only rewind stops nothing, since the conversation that started them stays.

## In the panel

- **The menu.** A small history button sits under the corner of each bubble. It shows on hover and on keyboard focus, and stays while its menu is open. Tab reaches it. Enter, Space or ArrowDown opens the menu on its first item. Arrows, Home and End move, Enter and Space choose, Escape closes onto the button, Tab closes and moves on, as the send menu does. A separator sets Fork from here apart from the three restores. A message offers the menu only once the engine named its prompt, while no turn runs, and in a Geno session (`offersRewind`).
- **Restore files.** The host asks for the preview first. A card under the message names the files, "Restore 2 files to before this message: a.ts, b.ts.". When the work tree has edits no checkpoint holds, the card turns amber and adds "Edits to b.ts are in no checkpoint, and restoring loses them.", and the keyboard starts on Cancel. Without such edits it starts on the restore button. Escape or Cancel closes the card and touches nothing. After the restore, the panel loads the session again, so the restored hunks read "Undone", and the line under the message says "Restored 2 files: a.ts, b.ts.".
- **Restore conversation.** It runs at once, since it deletes nothing. The panel loads the session again as of the cut, and the message goes back into the composer to edit and send.
- **Restore both.** It asks for the files confirm, then does both.
- **Fork from here.** The panel opens the fork in place of the chat, as History's Open does. The original stays in History. A fork's History row has a "Forked from <title>" link that opens the original. Once the fork runs a turn, its Tasks row has the same link.

`rewind-model.ts` (bundled into the webview) holds the messages, `RewindState` (`working`, `confirm`, `restored`, `failed`), the menu items, `offersRewind` and the card's words. `rewind-host.ts` (`RewindHost`) runs the choices against the engine. `rewind-view.ts` draws the menu, the card and the line. `rewind.css` styles them and the forked-from links.

## Deferred

- A restore of files covers the whole workspace, as `gcode rewind` does. VS Code wrote the workspace's `.vscode/settings.json` during the integration test, and the card listed it with the other files to restore and the edits to lose. The card says so before anything changes, but it cannot pick files.
- A restore writes the disk. An editor buffer with unsaved changes to a restored file keeps its own text.
- The fork's origin title is the source's title when the fork was made. A later rename of the source does not reach the link.
- A fork that has not run a turn is in History but not yet in Tasks, which lists sessions that ran a turn in this engine process.
- Side chats (`/btw`) and `/handoff`, the rest of U32.
