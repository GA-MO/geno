# U22: the subagent engine

A subagent is a child session that one call from its parent starts. The child works on its own task with its own tools and hands back a short report. The user starts one by typing `@explore <question>` or `@review` in a chat. In a mode the workspace turns the `agent` tool on for, the model can start one itself. The brief is the U22 section of `research/competitors-2026-10.md` section 5. The design is in its sections 3.1 and 3.2.

## Data shape

`packages/core/src/subagent.ts` names it. It holds only types and pure functions, and the engine does the I/O.

- `AgentDefinition` holds `name`, `description`, `tools` (Geno tool names, sorted), `model`, `effort`, `maxTurns`, `maxCostUsd` (Geno's `maxCost` field), `isolation` (`none` or `worktree`), `prompt` (the Markdown body), `source` (`workspace`, `global`, `plugin` or `builtin`) and `path`.
- `parseAgentDefinition(fields, body, origin)` reads Claude Code's agent frontmatter. It maps Claude Code's tool names onto Geno's: `Read`, `Grep`, `Glob` and `LS` map to the read tools, `Bash` maps to `bash`, `Edit`, `MultiEdit`, `Write` and `NotebookEdit` map to `edit`, and `Skill` maps to `skill`. Geno's own names also work. A tool with no Geno equivalent, an unknown field such as `color` or `permissionMode`, and a value Geno cannot use each become a note. The loader prints each note as `agents: <file>: <note>`. A Claude model alias (`sonnet`, `opus`, `haiku`) and `inherit` run the child on the parent's model. A file without a description is skipped, as Claude Code skips it.
- `isolation: worktree` is read and kept, and reported as not supported yet. A call to such an agent fails with that message. The `worker` built-in runs serially in the main tree.
- A child's session-start carries `child: ChildOf`. `ChildOf` is `{ parentId, toolUseId, role, caps, start }`. `caps` is `{ maxTurns, maxCostUsd }`, and `start` is `fresh` or `fork`. The model and the effort are the child session's own `Session` fields.
- `ChildStatus` is a discriminated union: `running`, `done`, `failed { reason }`, `cancelled` and `capped { cap: 'turns' | 'cost' }`. `settleChild` moves a running child to the first end it gets, and no end after that changes it. `childEndOf(reason, cancelled, error)` maps a run's `DoneReason` onto an end. A cancel always wins.
- The parent's log gets two new event kinds. `child-start` has `{ child, toolUseId, role, model, effort, caps, start }`. `child-end` has `{ child, toolUseId, end, turns, costUsd, summary }`. `childrenOf(events)` rebuilds the parent's children with their status from these events. The child's whole transcript stays in its own session log. Children are left out of the history list. The parent's history row adds the children's cost to its own.
- `childReport` fences a report as `<subagent_report agent=... session=... status=... [partial="true"]>`. A forged opening or closing tag inside the text loses its angle bracket. The fence ends with a line that says the report is data. An end other than `done` marks the report partial and says why the child stopped.
- An `@explore` prompt is logged as the user's own call. It is an `assistant` event with `issuedBy: 'user'`, a single `agent` tool use, zero usage and zero cost. The run ends once that call has run, so the parent model is never called.

## Where definitions come from

`loadAgents` in `packages/engine/src/subagents.ts` copies the precedence of `commands.ts`. The first definition of a name wins, in this order:

1. `<workspace>/.agents/agents/*.md`
2. `<workspace>/.claude/agents/*.md`
3. `~/.g-code/agents/*.md`
4. the `agents/*.md` of each installed Claude Code plugin, read in place and named `<plugin>:<name>`
5. the built-ins

A workspace `explore.md` therefore replaces the built-in `explore`. Read-only status comes from the tools the definition lists, so a replacement that lists `Bash` runs serially and asks before flagged commands.

| Built-in | Tools | Effort | Caps | Answer |
| --- | --- | --- | --- | --- |
| `explore` | read, grep, glob, list | low | 4 turns, $0.02 | path:line per place, then at most 150 words |
| `plan` | read, grep, glob, list | the parent's | 12 turns, $0.05 | a numbered plan |
| `review` | read, grep, glob, list | the parent's | 8 turns, $0.05 | findings with severity and path:line |
| `worker` | every agent tool | the parent's | 30 turns, $0.20 | what it changed and how it checked it |

`@review` with no text reviews `git diff HEAD`. The engine adds the diff to the task, cut at 60,000 characters. The rules reach the child through its session's loaded context, which the child copies from the parent.

## Running a child

- **Fresh** (the default). The child gets a short system prompt (`childSystemPrompt`), only its own tools, and the task as its first message.
- **Fork** (`fork: true`). The child gets the parent's system prompt and tools, byte for byte, and the parent's conversation through the model turn that asked for the fork. `forkOpening` answers that turn's calls, then the task follows with the role's instructions (`forkTask`). The parent's next request repeats every message before those answers, so the two share a cached prefix. The e2e test checks this on the request bytes. A fork always runs on the parent's model. Calls to tools outside the role get the "unknown tool" error.
- **Depth 1.** A child's tools never include `agent`.
- **Parallel.** The `agent` executor reports itself concurrent for a read-only definition, so `drive` runs those calls in one batch. A semaphore holds them to 4 at once. A writing child is not concurrent, so it runs alone in its batch.
- **Caps.** A child's caps are its definition's, else 20 turns and $0.05. The cost cap is held to what the parent run's `--max-cost` still has left for children. Children reserve their cap when they start and give back what they did not spend. When nothing is left, the call fails and tells the model to finish without another child. On a cap hit, the child's loop stops as `gcode agent` does at `--max-turns` or `--max-cost`. The report is every text the child wrote, marked partial.
- **Approval.** A child inherits the parent's approval and mode, so Plan-mode children are read-only. It has no approver of its own. Each question goes to the parent's approver with an `Asker` (`{ name, sessionId }`). Over ACP, the permission request goes on the parent session and on the parent's `agent` tool call. Its title starts with `[worker] `, and `_meta["gcode/subagent"]` names the child. On the terminal, the question starts with the same prefix. A child gets no `ask_user`, memory, widget or MCP tools.
- **Non-interactive.** A non-interactive run starts only read-only children. `gcode agent --non-interactive --allow-worker` lifts that.
- **Turning the tool on.** The model-callable `agent` tool is off by default. `.gcode.json` turns it on per mode with `"agentTool": ["ask", "auto"]`, where the values are approval modes, `non-interactive` included. `@` mentions work in every mode.

`drive` has three small changes. Logging is serialized, and each event takes its number when it is written, so child events logged while a tool runs never share a number with the batch's results. The tool context carries `toolUseId` and `logChild`. `concurrent` now gets the call's input. `runAgent` waits for every child to log its end before it returns.

## ACP mapping

`packages/engine/src/subagent-acp.ts` maps children onto ACP.

| Event | Client advertises `subagents` | Any other client |
| --- | --- | --- |
| Child starts | `subagent_update` on the parent session: `sessionId` is the child's, `title` is the role, `description` is the task's first line, `capabilities: { cancel: {} }`, `state: running` | `_gcode/subagent` notification with `SubagentNotice` and `status: running` |
| Child works | its own `session/update` traffic under the child's session id | nothing |
| Child ends | `subagent_update` with `state: idle` and `stopReason`: `end_turn` for done or failed, `max_turn_requests` for capped, `cancelled` for cancelled | `_gcode/subagent` with the end status, turns and cost |
| Cancel | `session/cancel` with the child's id stops that child alone; the parent goes on with the partial report | `session/cancel` on the parent stops the parent and its children |

`_meta["gcode/subagent"]` on each `subagent_update` carries the same `SubagentNotice`: the parent id, the child id, role, task, model, effort, caps, status, turns and cost. The announcement goes out after every update the parent's turn queued before it, and before any traffic from the child, as the RFD requires. A child's id is not a session the client can prompt: `session/prompt` on it is refused as unknown.

## What the smoke showed

`pnpm tsx packages/engine/test/subagents-smoke.ts` sends one `@explore` question through serve to Model Studio `qwen3.8-flash`, with a client that advertises `subagents`. The question asks about `~/Development/next-15-template`, which the smoke opens read-only. Before and after the run, the smoke compares every file's size and modification time, and the repository did not change.

- Question: `@explore where is createFetcher defined, and which services call it?`
- Answer: `src/plugins/createFetcher/index.ts:28` for the definition, with the default export at `:82`, then `src/services/demo/index.ts:3` (the import), `:11` (`fetchDemoList`) and `:27` (`fetchDemoCreate`). It closed with a short paragraph that said the demo service is the only caller. Each line number matches the file.
- The child ran at low effort and made 3 model calls (grep, then two reads, then the answer). It cost $0.001013 against the $0.05 budget, took 10.3 seconds, and sent `subagent_update` twice. The parent model was never called. The key appeared in no log line.

## Check

- `packages/core/test/subagent.test.ts` covers the frontmatter parsing and its notes, the plugin namespace, precedence in `mergeAgents`, the built-ins, the caps, every status transition, the run-to-end mapping, `childrenOf`, the fence, `@` mentions and the tool definition.
- `packages/engine/test/subagents.test.ts` covers the loader's precedence across both workspace folders, the global folder, a plugin and the built-ins, and the problems it reports.
- `packages/engine/test/subagents.e2e.test.ts` runs serve with a fake model. It covers a parallel explore pair whose times overlap and take about one child's time, a cost-cap stop with a partial report, a cancel by the child's id with the parent going on, a forged fence in a report, a worker's permission prompt with its name on the parent's call, `@explore` with no parent model call, a fork that shares the parent's request prefix, and the non-interactive rule with and without `--allow-worker`.
- `pnpm typecheck && pnpm vitest run --project unit && pnpm build`.

## Deferred

- `isolation: worktree` and parallel writers wait for U24 (lanes). The sandbox's network allowlist is global to the process, so every child shares the parent's allowlist.
- U23 adds the panel: children nested on the rail, opening a child's transcript, and a Cancel button. The engine already sends the data those need.
- Before the model-callable tool is on by default, an eval should show that it helps on small models (section 3.1). P25 ran it on qwen3.8-flash and found no gain, because the model never called the tool ([results/p25-agent-default.md](results/p25-agent-default.md)). The classifier does not yet treat a child's report as tainted input for the parent's next command (section 3.6).
- `~/.claude/agents/`, the user's own Claude Code agents, is not read. The brief names only Geno's home and plugins.
