# U11b: `/` in the composer

Typing `/` at the start of the composer opens a picker of the session's commands. The engine side is U11a (`docs/plan-u11-u14.md`).

## In the panel

- **Picker.** It lists the commands the engine publishes through ACP `available_commands_update`. Each row shows the name, the argument hint and the description, and an icon for who runs it: the editor, the engine, a prompt template or a skill. Typing filters it. Names that start with the query come first, then names that contain it, each group in the engine's order. Before the engine has published its list, the picker shows the built-ins, which every session has. The picker's first opening also opens the session, so a new window lists its workspace commands without waiting for a first prompt.
- **Keys.** These are the `@` list's keys. The arrows move and wrap, Tab or a click puts `/name ` in the draft, and Escape closes the list until the next keystroke. Enter fills in the command too. For a command without an argument hint, Enter also sends it, so `/new` and Enter start a new chat.
- **Routing.** The extension routes what is sent by the command's `_meta["gcode/command"]`.
  - Editor built-ins run the panel's own actions and never reach the engine: `/new` and `/clear` start a new chat, `/history` opens the history, and `/model` opens the model setting.
  - Engine built-ins (`/mode`, `/rules`, `/memory`, `/init`), prompt templates and skills go to the engine as typed.
  - Text that names no listed command, such as `/usr/bin is missing`, is an ordinary prompt.
- **Chips.** A sent command shows in the user bubble as a chip with its name, followed by the arguments as typed, never as the expanded template. A skill's chip names the skill. A loaded session shows the same chips, because `session/load` now replays the logged command under `_meta["gcode/turn"].command`. Engine built-ins are not logged, so a `/mode` turn does not come back on load. The mode it set does.

## Code

- `packages/extension/src/chat/slash.ts` holds the picker's data. `Picker` is `closed`, or `open` with its matching rows and the active one. `pickerAt` recomputes it after each keystroke or caret move and keeps the active row on the same command while it still matches. `SentCommand` is what a turn records for its chip. The webview bundles this file, so it imports only types.
- `packages/extension/src/chat/slash-route.ts` reads the engine's list and routes a sent text. `EDITOR_ACTIONS` is the table of built-ins the panel runs itself.
- `packages/extension/src/chat/slash-view.ts` draws the picker and the chip. The webview hooks it in beside the `@` list.

## Check

`packages/extension/test/slash.integration.test.ts` drives the real panel against a workspace with a `.claude/commands/review.md` template and a `.claude/skills/add-i18n` skill. It checks the list and its order, the hint and descriptions, filtering, the arrows, Escape, Tab, a click and Enter. It then sends `/mode plan`, which the engine answers without a model call, and `/review a.ts`, whose expansion reaches the model while the bubble shows the chip. It sends `/add-i18n th`, whose SKILL.md reaches the model as context. Next `/history`, `/clear`, `/model` and `/new` run in the panel, the first three picked from the list and the last two typed in full. Finally it loads the older session and checks the replayed chips. `packages/extension/test/slash.test.ts` covers the matching, the picker's moves and the routing table. `packages/engine/test/serve-commands.e2e.test.ts` checks the replayed command.
