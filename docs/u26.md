# U26: the Arena, or best-of-N

`/best-of-n 3 <task>` runs one task in 3 lanes at once, each with its own variant. Each lane runs the project check, a `review` child ranks the lanes that passed, and the panel shows the ranking beside a side-by-side compare. The user picks a winner, applies it through the per-hunk review, and grafts single hunks from the other lanes the same way. The brief is section 3.4 and the U26 entry of section 5 in `research/competitors-2026-10.md`. It builds on lanes (`docs/u24.md`, `docs/u25.md`) and subagents (`docs/u22.md`, `docs/u23.md`).

## Data shape

`packages/core/src/arena.ts` holds the types and the pure steps. The engine does the I/O.

- **Variant spec.** `VariantSpec` is `{ seed, model, effort }`. A null model or effort runs the lane on the session's own. `SEEDS` is a table of seed prompts: `plain` (nothing added), `minimal`, `idiomatic` and `test-first`. `variantsFor(n, variety, models, listed)` picks n variants. The variety is `seeds` (the default), `effort` (low, medium, high, xhigh) or `models` (one lane per model from `.gcode.json` `arena.models`, which falls back to seeds with fewer than two models). `.gcode.json` `arena.variants` lists variants explicitly, and `--vary` overrides that list.
- **Cost preview.** `CostPreview` is `{ n, perLaneUsd, reviewMaxUsd, totalUsd, basis }`. `perLaneUsd` is the median cost of Geno's newest 50 sessions that spent anything. With fewer than 3 such sessions, it is `DEFAULT_TASK_COST_USD`, $0.032, which is E5's median task cost, and `basis` says `default`. The total adds the review's $0.05 cap.
- **Arena run record.** `ArenaRun` holds the task, the preview, `status`, the review (`{ sessionId, report, costUsd }`, where `report` is the child's fenced report), the summary and the winner. Each `ArenaLane` holds its letter, lane name, session, variant, status, check result, turns (model calls), cost, rank and the review's reason. `arenaStep(run, event)` is the only way a run changes. A step that does not fit the state it meets changes nothing.

  | Lane status | Moves to | On |
  | --- | --- | --- |
  | `running` | `checking` | the task ended by itself, or at its turn or cost cap |
  | `running` | `failed` | the task failed, including a turn that ended on a model error |
  | `running` | `stopped` | the user stopped it |
  | `checking` | `passed` | the check passed, or the workspace has no check |
  | `checking` | `failed` | the check failed |

  The run is `running`, then `ranking` while the review works, then `ranked`. It is `no-winner` when no lane passed and `stopped` when every lane was stopped. With one passing lane the review does not run, and that lane ranks first.
- **Ranking result.** `Ranking` is `{ order: [{ lane, rank, reason }], summary, source }`. `parseRanking(report, passing)` reads the text inside the `<subagent_report>` fence. It takes the last JSON block of the form `{"ranking": [{"lane", "reason"}], "summary"}`, then falls back to a numbered list, then to start order (`source: 'fallback'`). It accepts a lane by letter, by name or as "Lane B". It drops lanes that did not pass and repeated lanes, puts every passing lane the review left out last, and clips each reason to 400 characters. The report stays data: it is parsed by code, and the panel shows reasons as text nodes only.
- **Compare view model.** `packages/extension/src/chat/arena-model.ts` turns a run and each lane's `FileChange`s since its base (`ArenaDiff`) into a `CompareView`: one column per lane, and one row per file with a cell per lane, so hunks line up by file. A hunk is graftable once a winner is picked, when it is not the winner's and the winner has no identical hunk.

## Engine

`packages/engine/src/arena.ts`.

- `startArena` names the lanes `<task slug>-a` to `-d`, creates them one at a time (two `git worktree add` runs on one repository are not safe in parallel), and starts every lane's session at once. Each lane runs `variantPrompt(task, variant)`, which is the task followed by its seed.
- `checkLane` runs the workspace's `check` in the lane, in the sandbox, because the code it checks is the model's.
- `reviewArena` starts a session in the main checkout and issues a `review` call as the user's own, as `@review` does. `runAgent` takes the call through a new `issued` option, so the parent model is never called. The task (`rankingTask`) holds each passing lane's diff from `laneDiffText`, its variant and its check, and asks for the JSON block. The child can read the lane folders, which sit inside the main checkout.
- The run is saved after each step to `<git folder>/geno/arenas/<id>.json`.
- `laneChanges` gives the compare its hunks. `graftLane` applies some of a lane's hunks: each touched file is merged 3-way as if the lane had made only those hunks (`applyHunks` in core), so a graft over the applied winner merges like an apply, and an overlap is a conflict that writes nothing. `applyLane` and `graftLane` share one merge loop.

ACP, in `serve.ts`:

| Method | Does |
| --- | --- |
| `_gcode/arena/preview` | The variants and the cost preview. Nothing runs. |
| `_gcode/arena/new` | Starts the run. Its lanes are ordinary background lane sessions, so they show in the Lanes and Tasks panes. |
| `_gcode/arenaUpdate` | Notification of each step, to every window that advertises `gcode/tasks`. |
| `_gcode/arenas` | The repository's runs, newest first. |
| `_gcode/arena/compare` | A run and each lane's changes since its base. |
| `_gcode/arena/pick` | Records the winner, only a passing lane of a ranked run. |
| `gcode/laneGraft` in a prompt's `_meta` | `{ lane, hunks }`: a graft as a turn of the shown chat, written through the editor and kept under per-hunk review. The `lane-apply` event records `grafted`. |

The winner applies through U25's `gcode/laneApply` turn unchanged. Every lane shares the process's one network allowlist (`docs/plan-u19-on.md`).

## The model-call limiter

`packages/engine/src/model-slots.ts`. Every gateway of one provider in the engine process takes a slot for each model call, 4 by default (`GCODE_MODEL_CONCURRENCY`). A 429 pauses every call that has not started for the retry delay, so the lanes back off together instead of each retrying alone. The stream clock starts once a call has its slot, so U19's first-token time does not count the queue.

`pnpm tsx packages/engine/test/limiter-bench.ts` measures it against a fake endpoint with 150 ms calls and a 500 ms retry-after. Each cell is the median of 3 runs with the range in brackets. "Per-call backoff only" is the gateway before U26.

| Endpoint limit | Load | Gateway | 429s | Failed turns | Wall s | Peak open |
|---|---|---|---|---|---|---|
| 4 open requests | 4 lanes, 24 calls | per-call backoff only | 0 (0-0) | 0 (0-0) | 0.9 (0.9-0.9) | 4 (4-4) |
| 4 open requests | 4 lanes, 24 calls | shared slots (4) + pause | 0 (0-0) | 0 (0-0) | 0.9 (0.9-0.9) | 4 (4-4) |
| 4 open requests | 4 lanes + a child each, 48 calls | per-call backoff only | 8 (8-8) | 0 (0-0) | 1.9 (1.9-1.9) | 8 (8-8) |
| 4 open requests | 4 lanes + a child each, 48 calls | shared slots (4) + pause | 0 (0-0) | 0 (0-0) | 1.8 (1.8-1.8) | 4 (4-4) |
| 6 requests a second | 4 lanes, 24 calls | per-call backoff only | 24 (24-24) | 0 (0-0) | 3.9 (3.9-3.9) | 4 (4-4) |
| 6 requests a second | 4 lanes, 24 calls | shared slots (4) + pause | 6 (6-6) | 0 (0-0) | 3.8 (3.8-3.8) | 4 (4-4) |
| 6 requests a second | 4 lanes + a child each, 48 calls | per-call backoff only | 94 (91-94) | 12 (12-12) | 6.1 (6.1-6.1) | 8 (8-8) |
| 6 requests a second | 4 lanes + a child each, 48 calls | shared slots (4) + pause | 16 (16-16) | 2 (2-2) | 8.4 (8.4-8.4) | 4 (4-4) |

Against a limit on open requests, the slots remove every 429. Against a request-rate limit, the shared pause cuts 429s by 4 to 6 times and failed turns from 12 to 2. It costs wall time there, because the old gateway's failed turns ended early. One slot at 150 ms is already 6.7 requests a second, so no concurrency limit alone can stay under 6 a second. I also tried halving the slots on each 429 and growing them back. It changed no number in the table, so I removed it.

Live, Model Studio never needed the limiter: 409 calls over the three runs below, at most 3 at once, no call waited for a slot, no pause, and no rate-limit retry in any lane log (`docs/results/u26-arena/limiter-run-*.json`). The account's limits are not known from the console, so 4 slots is a guess that fits one best-of-4 at one call a lane.

## Live run

`gcode eval arena` (`packages/engine/src/eval-arena.ts`) runs best-of-n on eval tasks. Each task is cloned at its base commit into a temp folder and set up, as `gcode eval run` does. The arena runs in lanes of that clone with the E5 settings: non-interactive, `npx tsc --noEmit` as the check, and the check after every edit. Then every lane is scored with the task's hidden check. The user's repositories are never touched.

- **pass@1** is the share of a task's lanes whose code passes the hidden check, which is the expected pass rate of one lane.
- **pass@3** is whether any lane's code passes it.
- **Pick passes** is whether the lane the Arena hands the user passes it. That lane is the review's first, or the only lane whose project check passed.

Model Studio `qwen3.8-flash`, best-of-3 with the seeds variety (A as asked, B minimal change, C idiomatic refactor), at most 30 turns a lane, on 2026-10-06:

| Task | E5 | Lanes: project check, rank, hidden check | pass@1 | pass@3 | Pick passes | Cost |
|---|---|---|---|---|---|---|
| next-base-path | fail | A passed #1 fail; B passed #2 fail; C passed #3 fail | 0.00 | no | no | $0.1736 |
| payload-page-metadata-helper | fail | A failed, fail; B failed, **pass**; C failed, fail | 0.33 | yes | no winner | $0.1541 |
| payload-site-url-runtime | fail | A passed #1 fail; B failed, fail; C failed, fail | 0.00 | no | no | $0.1536 |
| payload-dayjs-bangkok | pass | A passed #1 pass; B passed #2 pass; C passed #3 fail | 0.67 | yes | yes | $0.1037 |
| next-about-translations | pass | A passed #1 pass; B passed #2 pass; C passed #3 pass | 1.00 | yes | yes | $0.0787 |
| next-counter-floor | pass | A passed #2 pass; B passed #1 pass; C passed #3 pass | 1.00 | yes | yes | $0.0953 |
| **E5's failing three** | | | **0.11** | **1/3** | **0/3** | $0.4813 |
| **E5's passing three** | | | **0.89** | **3/3** | **3/3** | $0.2777 |
| **All six** | | | **0.50** | **4/6** | **3/6** | **$0.7590** |

What the numbers say, from one run of each task:

- Best-of-3 found a correct change for one of E5's three failures, `payload-page-metadata-helper`, in lane B. The Arena still handed the user nothing, because that lane failed `tsc --noEmit`, so the review never saw it. The project check is a gate, and here it removed the only correct lane. A run where some lane fails only the check may be worth showing as "close" rather than "no winner". That is a design change I left for the user.
- On the passing three, the review's pick passed every time, and lane C's idiomatic refactor was the one failure (`payload-dayjs-bangkok`).
- Lanes on the failing tasks ran into their $0.05 cap: 15 to 23 model calls each. A lane now costs more than one E5 task did on the same task (`payload-dayjs-bangkok` was $0.0045 in E5 and about $0.03 a lane here), with a first request of about 6,900 tokens, where E5 averaged about 3,000 a turn, and more turns. That is the agent as it is today, not something U26 added. It makes `DEFAULT_TASK_COST_USD` low for today's Geno, but the preview uses Geno's own history once 3 sessions have spent anything.
- Two of the four reviews (`next-base-path`, `next-about-translations`) spent all 8 of the `review` built-in's turns reading lane files and never wrote the ranking. Both fell back to start order. `rankingTask` now says the diffs are the whole change and to read at most 3 files. A rerun of `next-about-translations` (`run-3.jsonl`, $0.0708) then answered in 6 model calls with a JSON ranking. The child still read 7 files. One rerun is weak evidence, so the cap is the real guard, and an `arena-review` definition with more turns is the next step if the fallback recurs.

Spend in all: $0.1037 + $0.6552 + $0.0708 = **$0.8297**, by Geno's price table, which bills cache reads at the input rate and so overstates. `--max-cost` stops the run before a task whose n lanes and review could pass it. The files are `docs/results/u26-arena/run-1.jsonl` (`payload-dayjs-bangkok`, `--max-cost 0.15`), `run-2.jsonl` (the other five, `--max-cost-per-lane 0.05 --max-cost 0.88`) and `run-3.jsonl` (the review rerun). To rerun:

```
gcode eval arena --task next-base-path --task payload-page-metadata-helper --task payload-site-url-runtime --task payload-dayjs-bangkok --task next-about-translations --task next-counter-floor --max-cost-per-lane 0.05 --max-cost 1.00
```

## In the panel

- **`/best-of-n <2-4> [--vary seeds|effort|models] <task>`** is a client-run built-in. It opens the Arena pane, which takes the transcript's place with Back and Escape, as the Lanes pane does. `/best-of-n` with no text reopens the newest run. A bad argument shows its error on the card and starts no turn.
- **Preview.** The pane shows the task, the lanes with their variant labels, a Seeds, Effort or Models choice that asks for the preview again, and the cost in words, such as "About $0.15: 3 lanes at a default of $0.032 a task, plus up to $0.05 for the review." Nothing runs before Start.
- **Race.** Each lane has a track with U23's helper dino in U18b's running pose. The engine reports no progress inside a running lane, so a running dino creeps toward the check by elapsed time and never reaches it by time alone. A lane at its check is at 80%, and a settled lane is at the finish with a passed or failed mark. Stop cancels every running lane. Reduced motion and high contrast hold the dinos still.
- **Ranked.** The ranking shows each lane's rank, the review's reason and its cost. The review's first pick is the primary Pick button. Below it, the compare shows one column per lane, file by file, with the hunks aligned. A container query shows the lanes side by side from 460 px for 2 lanes, 600 px for 3 and 760 px for 4. Below that, it shows one lane at a time with a switcher of letters and ranks.
- **Pick and graft.** Pick records the winner and applies it through the chat's `applyLane`, so its hunks are under review with Keep and Undo. The pane stays open with a note. Each graftable hunk then has a checkbox, and Graft takes the ticked hunks of one lane as a chat turn.
- The host (`arena-host.ts`) keeps the whole state and posts it on every change, so a recreated webview and a reloaded window both get the run back.

## Deferred

- A lane that fails only the project check is never ranked or shown as close (see the live run).
- Stop has no automated test.
- Race progress is estimated from time while a lane runs.
- The account's rate limits are unknown, so the slot count is not tuned to them.
