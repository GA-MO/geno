# U44: steer a running agent

A message for a running session no longer has to wait for the turn to end. It lands at the turn's next safe point: after the current tool batch and before the next model call. The model call that runs is never cut short, and nothing is delivered mid-stream. The same path lets the parent model steer a running subagent, and the user steer a subagent, a lane or a background task. The brief is the U44 entry of the "Harness ideas" section of `docs/plan-u19-on.md`.

## Data shape

`packages/core/src/steer.ts` names it. It holds only types and pure functions.

- **The message.** `Steer` is `{ text, from }`. `SteerSource` is `user`, `parent` (the agent that started this child, through `message_agent`) or `child` (a background child of this session reporting back). Only the user's own text is the user's. The other two are data.
- **Its delivery state.** `SteerState` is `queued`, or a `SteerOutcome`: `delivered { seq }`, logged at that event number in the running turn, or `next-turn`, because the run ended before it could take it.
- **The log marker.** A delivered steer is a `user` event with `steer: true`. A steer from someone other than the user also has `from: 'parent'` or `from: 'child'`. The engine's event schema in `sessions.ts` accepts both fields.
- **Delivery points.** `STEER_AT` maps each loop step onto what a queued steer does there:

  | Loop step | Steer |
  | --- | --- |
  | `call-model` (after a tool batch's results, or after a prompt) | `deliver` |
  | `run-tools` (a tool use still has no result) | `hold` |
  | `done` (the model ended the turn, a limit, a stop) | `next-turn` |

  `steerActionOf(events, run)` applies it to a log. Because `replayMessages` already folds everything after an assistant turn into one user message, with the tool results first, a steer is appended after the results. Every earlier message goes again unchanged, so the cached prefix holds.
- **Who it speaks for.** `startsTurn` is a prompt that starts a turn, `isUsersOwn` is the user's own text. History counts, turn timings, the Arena's last prompt and replay turns use `startsTurn`. The command classifier reads the newest user event without a `from`, so a parent's message or a child's report never becomes the user's request, and never approves a command.
- **The parent's fence.** `parentMessage` fences a parent's message as `<parent_message>…</parent_message>`, with a forged tag inside losing its angle bracket, and a closing line that says it is not the user and approves nothing. A child's report is fenced already by `childReport`.

## In the engine

- **The inbox.** `SteerInbox` in `packages/engine/src/steer.ts` holds one run's steers, from its start to its end. `push` queues a steer and returns a promise of its outcome, or undefined once the run ended. `take` hands every queued steer to the loop, `close` ends the run and settles what is left as `next-turn`. `Steers` keeps every running session's inbox in the engine process, children's included, by session id. `runAgent` opens the session's inbox and the subagent engine opens one per child.
- **The loop.** `drive` takes the inbox on its `Surface`. At a `call-model` step it logs each queued steer, settles it with its seq, and looks at the loop again, so a limit still applies. At `done` it closes the inbox. The steer hook is three lines in the loop and one helper.
- **Background children.** `message_agent` needs a child that runs while the parent model is called. Before U44 the `agent` call blocked the parent's batch until the child ended, so no such child existed. The `agent` tool now takes `background: true` for a read-only subagent. The call returns at once with the child's session id. The child's report reaches the parent as a steer with `from: 'child'`. A turn the model ends while a background child still owes its report stays open (`holdsTurnOpen`): it waits, delivers the report, and calls the model again. A subagent that may change files cannot run in the background, because its edits would race the parent's.
- **`message_agent { agent_session, text }`.** It is offered only where the `agent` tool is, after it in the tool list. It pushes a `parent` steer into the child's inbox and waits for the outcome, so its result is exact: "delivered at next tool round (event N of the subagent's log)", or "child already finished" when the child ended before its next tool round. An id that is not a child of this session is an error.

## ACP

The smallest design reuses `session/prompt`. A prompt whose `_meta["gcode/steer"]` is `true` steers the session's running turn. Without the key, a prompt during a running turn is refused as before.

| Case | What the engine does | The steer request's response |
| --- | --- | --- |
| Delivered | logs the steer, sends a `user_message_chunk` with `_meta["gcode/steer"] = { seq, from }` in order with the turn's other updates | at once: `stopReason: end_turn`, `_meta["gcode/steer"] = { kind: 'delivered', seq }` |
| The turn ended first | waits for the turn's end, then runs the steer as an ordinary prompt | that turn's own response, with `_meta["gcode/steer"] = { kind: 'next-turn' }` |
| A child that finished | nothing | an `invalidRequest` error: "the subagent already finished" |

- A steer is text only. Attachments and mentions are refused with `invalidParams`, and wait in the queue for the next turn instead.
- A subagent's session id takes a steer while the child runs, though it takes no ordinary prompt. Its chunk arrives under the child's session id, with the child's other updates.
- A lane or a background task is an ordinary session, steered by its session id.
- On `session/load`, a steer replays as the same `user_message_chunk` with `gcode/steer` inside its turn, not as the start of a new turn (`steerUpdate` in `session-replay.ts`).

## What the smoke showed

`pnpm tsx packages/engine/test/steer-smoke.ts` gives Model Studio `qwen3.8-flash` a four-step task through serve: read `notes/a.txt` to `d.txt` one at a time, then list the fruits. The editor's file read of `a.txt` sends the steer: skip `c.txt` and `d.txt`, and answer after `b.txt` with the fruits so far in uppercase.

- The steer was delivered at seq 5, between the first read's result and the second model call.
- The model read `a.txt` and `b.txt` only, and answered "APPLE, BANANA", saying it stopped after `b.txt` as instructed.
- The log reads user, assistant, tool-result, steer, assistant, tool-result, assistant: one turn, three model calls.
- It took 7.4 seconds and cost $0.001660, against the $0.05 budget. The key appeared in no log line.

## Check

- `packages/core/test/steer.test.ts` covers the delivery points for every loop step, the background hold, the steer placed after a batch's results with the earlier messages unchanged, the log marker, the parent fence against a forged tag, the classifier ignoring a parent's message and a child's report but reading the user's own steer, history counting one turn, and the `message_agent` results.
- `packages/engine/test/steer.test.ts` covers the inbox (order, outcomes, `next-turn` after close, a closed inbox, the background wait and abort), the replay of a steer inside its turn, and `steerRunning`'s refusals.
- `packages/engine/test/steer.e2e.test.ts` runs serve with a scripted fake model and an editor that holds the file system:
  - a steer sent during a tool batch waits for it, lands after its result, and the next request repeats the earlier messages unchanged, with the steer after the tool result;
  - a steer sent while the model streams waits for the batch, and the streaming call is not aborted;
  - a steer sent during the last call becomes the next turn, which ends after the first;
  - `message_agent` to a running background child puts the fenced message after the child's tool result in its next request, and the child's report reopens the parent's turn;
  - `message_agent` to a finished child says so, and the user's steer to it is refused.

## Deferred

- A background child's report that arrives after its parent's run stopped at a limit or failed is not delivered. The parent's log still has the child's end with its summary.
- `message_agent` waits for the child's next tool round. A child stuck on a long command holds the parent's batch that long.
- The terminal (`gcode agent`) has no way to type a steer.
