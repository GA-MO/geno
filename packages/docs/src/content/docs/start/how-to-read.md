ทุกหน้าสถานการณ์มีทัวร์หนึ่งชุด ทัวร์เดินผ่านระบบทีละขั้นตั้งแต่จุดเริ่มจนจบ

## ส่วนต่างๆ ของทัวร์

- **แผนภาพ swimlane** หนึ่งคอลัมน์คือหนึ่ง lane หรือผู้กระทำ หนึ่งแถวคือหนึ่งขั้นตามลำดับเวลา
  ขั้นที่เกิดพร้อมกันอยู่แถวเดียวกัน เส้นประคือการข้าม process เช่นข้อความ ACP ระหว่าง VS Code กับ engine
- **แผงความคืบหน้า** (ด้านขวา) บอกว่าตอนนี้เป็นตาของใคร turn อยู่ช่วงไหน ขั้นที่เท่าไรจากทั้งหมด
  เรียกโมเดลไปกี่ครั้ง รันเครื่องมือไปกี่ครั้ง และรายการ "AI ทำอะไรไปแล้ว" กับ "harness ทำอะไรไปแล้ว"
  เมื่อถึงขั้นสุดท้าย แผงจะบอกว่า turn จบแบบไหน เช่น `done (end_turn)`
  การรันเครื่องมือนับทีละ call ที่เครื่องมือได้ทำงานจริง จะสำเร็จหรือล้มเหลวก็ตาม call ที่ถูกปฏิเสธก่อนเครื่องมือเริ่มทำงานไม่นับ
- **แถวคำบรรยาย** (ด้านล่าง) อธิบายขั้นปัจจุบันเต็มๆ: ทำอะไร ผู้ใช้เห็นอะไรบนจอ ส่งอะไรออกไป
  และลิงก์ `path:line` ที่เปิดบรรทัดนั้นใน VS Code

เลขบรรทัดในลิงก์คำนวณตอนสร้างเว็บจากชื่อฟังก์ชันหรือข้อความในโค้ด ไม่ได้เขียนไว้ด้วยมือ จึงตรงกับโค้ดเสมอ

## การควบคุม

| ทำอะไร | ปุ่ม | แป้นพิมพ์ |
| --- | --- | --- |
| ขั้นถัดไป / ก่อนหน้า | ▶ / ◀ | → / ← |
| เล่นต่อเนื่อง / หยุด | ▶ เล่น | Space |
| ขั้นแรก / ขั้นสุดท้าย | ⏮ / ⏭ | Home / End |
| กระโดดไปขั้นใดก็ได้ | คลิกกล่องในแผนภาพ | |
| เลือกทางที่ทางแยก | ปุ่มบนกล่องทางแยกหรือในแถวคำบรรยาย | |

การเล่นต่อเนื่องหยุดเองที่ทางแยกทุกจุด เพื่อให้คุณเลือกทาง
ที่อยู่ในแถบที่อยู่ของเบราว์เซอร์ (`#at=...`) ตามคุณไปทุกขั้น คัดลอกไปแบ่งปันได้ คนที่เปิดลิงก์จะเห็นขั้นเดียวกันและทางแยกที่เลือกไว้เดียวกัน

ถ้าปิด JavaScript หรือพิมพ์หน้าออกมา ทัวร์จะเป็นแผนภาพของทางหลักกับรายการทุกขั้น โดยแต่ละทางแยกแสดงทุกทางซ้อนอยู่ในที่ของมัน

## ใครคือใคร

สีบอกว่าเป็นตาของใคร **AI** (ม่วง) **harness** (ฟ้า) **ผู้ใช้** (เหลือง) และ **ระบบภายนอก** (เทา)

| lane | คือ |
| --- | --- |
| ผู้ใช้ | คนที่พิมพ์ คลิก ตอบการ์ด และกด Stop |
| แผงแชท | หน้าบทสนทนา ใน VS Code คือ webview (ช่องพิมพ์ บทสนทนา การ์ด ปุ่ม Stop) ใน CLI คือเทอร์มินัล |
| VS Code | extension host กับหน้าจอของ VS Code เอง เช่น toast, CodeLens, status bar และ buffer ของไฟล์ |
| เซิร์ฟเวอร์ engine | ฝั่ง ACP ของ engine ถือสถานะที่ทุกหน้าต่างใช้ร่วมกัน: ทะเบียน turn, lock ต่อ session, steer และคิว, งานใน Tasks, การปลุก และการส่งคำขออนุญาต |
| ลูปเอเจนต์ | การทำงานหนึ่งรอบของเอเจนต์: `runAgent`, `drive`, `loopStep`, จุดปลอดภัย `deliver()`, gateway และการรันเครื่องมือเป็นชุด |
| เอเจนต์ลูก | ลูปอีกตัวใน session ของตัวเอง เช่น subagent หรือ workflow มีชื่อ session ต่อท้าย เช่น `child@explore` |
| โมเดล | LLM ที่ตอบคำขอ รวมถึงการสรุปตอน compaction และ llama-server ของ Tab |
| เครื่องมือ | ตัวเครื่องมือและสิ่งที่มันแตะโดยตรง เช่น shell ใน sandbox และไฟล์ |
| นโยบาย | ทุกการตัดสิน allow, ask, deny หรือ classify: โหมด กฎ `settle` classifier ของ Auto และ hook ทุกชนิด |
| ระบบภายนอก | ระบบนอก Geno ที่ผลลัพธ์กลับมาเป็นข้อมูล เช่น MCP server เว็บ และ GitHub |

## กฎที่ใช้วาดทุกทัวร์

1. ทุกครั้งที่ข้ามระหว่าง VS Code กับเซิร์ฟเวอร์ engine คือข้อความ ACP และขั้นนั้นบอกชื่อ method เช่น `session/prompt`, `session/update`, `session/request_permission`, `session/cancel`
2. ขั้นที่ลูปขออนุญาตเดินทาง ลูป → นโยบาย → (การ์ด) เซิร์ฟเวอร์ engine → VS Code → แผงแชท → ผู้ใช้ แล้วกลับทางเดิม
3. turn ที่ถูกปลุกเริ่มที่เซิร์ฟเวอร์ engine (ตัวปลุก) หลังจากนั้นเป็น turn ปกติของลูป
4. ทัวร์ของ CLI ไม่มีคอลัมน์ VS Code และเซิร์ฟเวอร์ engine ทัวร์ของ Tab ไม่มีเซิร์ฟเวอร์ engine ลูป เครื่องมือ และนโยบาย
5. การเรียกโมเดลของเอเจนต์ลูกอยู่ใน lane เอเจนต์ลูก ไม่ใช่ lane โมเดล lane โมเดลใช้กับการเรียกของลูปเอง compaction และ Tab

## เมื่อไรใช้ Mermaid เมื่อไรใช้ทัวร์

ถ้ามีขั้นให้ผู้อ่านเดินตาม ให้เขียนเป็นหน้าสถานการณ์ ซึ่งได้ทัวร์แบบโต้ตอบได้
อย่างอื่นที่ไม่มีลำดับให้เดิน เช่น เครื่องสถานะ ความสัมพันธ์ของชนิดข้อมูล หรือโครงสร้าง process
ให้เขียนเป็น Mermaid ใน Markdown ธรรมดา ซึ่งกลายเป็นภาพ SVG ตอนสร้างเว็บ
