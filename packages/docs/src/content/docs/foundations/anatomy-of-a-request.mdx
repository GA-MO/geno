**request หนึ่งก้อนคือ JSON ที่มีแค่ไม่กี่ field** แต่ละ field ตอบคำถามหนึ่งข้อ:
คุยกับ model ตัวไหน ตอบยาวได้เท่าไร model มี tool อะไรให้ใช้ model ควรประพฤติอย่างไร และคุยอะไรกันมาแล้ว
ทุก field ถูกเติมที่เดียว คือ `buildRequest` ใน `packages/core/src/request.ts`

ความยาวทุกอย่างในหน้านี้นับเป็น **token** หน่วยที่ model ใช้นับข้อความ ประมาณหนึ่งคำหรือส่วนหนึ่งของคำ
ผู้ให้บริการคิดเงินตามจำนวน token ที่อ่านและเขียน

## request จริงหนึ่งก้อน

นี่คือ request แรกของรายการ A06 ทั้งก้อน สาม field ใหญ่ (`tools` `system` `messages`) พับไว้ คลิกเพื่อเปิดดูได้

<Payload of={frontmatter.payloads.whole} />

ดูสาม field ที่ไฮไลต์ก่อน

- `model` คือชื่อ model ของ session นี้ ที่นี่คือ `qwen3.8-flash` บน Model Studio (บริการ model ของ Alibaba Cloud)
- `max_tokens` คือเพดานความยาวของคำตอบ 131,072 คือเพดาน output ทั้งหมดของ model ตัวนี้ ไม่ใช่งบที่ Geno ตั้ง
- `output_config.effort` บอก model ว่าให้คิดหนักแค่ไหน (`low` ถึง `max`) ค่ามาจาก effort ที่ตั้งไว้ใน session

## ทุก field และใครเติม

| field | ทำอะไร | Geno เติมจากไหน |
| --- | --- | --- |
| `model` | เลือก model | `session.model` ที่คุณเลือกในแผงหรือในการตั้งค่า |
| `max_tokens` | เพดานความยาวของคำตอบ | `maxTokensFor`: เพดาน output ของ model หรือที่ว่างที่เหลือใน context window (จำนวน token สูงสุดที่ model อ่านได้ในหนึ่ง request) ถ้าน้อยกว่า (หักกันไว้ 1,000 token) |
| `thinking` | เปิดหรือปิดการคิดก่อนตอบ (model เขียนความคิดเป็นบล็อกแยกก่อนคำตอบ) | ปกติส่ง `adaptive` เฉพาะ model ที่ตาราง `MODEL_CAPABILITIES` บอกว่ารองรับ model อื่นเช่น qwen ไม่ส่ง field นี้ ตอนบังคับให้เรียก tool ส่ง `disabled` คู่กัน การบังคับทำได้เฉพาะ model ที่รองรับ คือ qwen และ Haiku Claude Opus และ Sonnet 5.5 ไม่ถูกบังคับ จึงได้ `thinking` แบบเดียวกับการเรียกปกติ |
| `tools` | รายการ tool ที่ model ขอเรียกได้ | ชุดที่ `runAgent` ประกอบ ดู[Tool คือสัญญา](/foundations/tools-are-contracts/) |
| `tool_choice` | บังคับหรือห้ามเรียก tool | ปกติไม่ส่ง ส่ง `{type: tool}` เมื่อบังคับ เช่น subagent (บทสนทนาลูกที่ทำงานย่อย) ที่ต้องส่งรายงาน เฉพาะ qwen และ Haiku (subagent ของ Claude Opus และ Sonnet 5.5 ไม่ถูกบังคับ รอบสุดท้ายของมันได้ `{type: none}` แทน และข้อความที่ตอบคือรายงาน) และ `{type: none}` ในการเรียกครั้งสุดท้ายที่งบอนุญาต (งบคือขีดจำกัดต่อ turn: ค่าเริ่มต้นเรียก model ได้ 40 ครั้ง และใช้เงินได้ราว $0.40 ตามราคาของ qwen3.8-flash ปรับตามราคาของ model ที่ใช้) |
| `system` | system prompt หนึ่งบล็อก | ข้อความคงที่ตามระดับ prompt ของ model ดู[Model รู้ได้อย่างไรว่าต้องทำอะไร](/foundations/how-the-model-knows/) |
| `messages` | บทสนทนาทั้งหมด | `replayMessages` สร้างจาก session log ทุกครั้ง |
| `output_config.effort` | ความหนักของการคิด | effort ของ session ส่งเฉพาะ model ที่รองรับ |
| `stream` | ขอคำตอบแบบไหลมาเรื่อยๆ | wire (ส่วนที่ส่ง request ออกในรูปแบบของผู้ให้บริการ) เติม `stream: true` ตอนส่ง ไม่ใช่ `buildRequest` |

`system` และบล็อกล่าสุดของข้อความ user ล่าสุดมี `cache_control` ติดอยู่ เป็นจุดที่บอกผู้ให้บริการว่าให้ cache ถึงตรงนี้
cache นี้คือ prompt cache ผู้ให้บริการจำส่วนต้นของ request ไว้ request ถัดไปที่ขึ้นต้นเหมือนเดิมจึงคิดเงินส่วนนั้นถูกลง
อธิบายใน[Memory และ context window](/foundations/memory-and-context/)

## สิ่งที่ไม่มีใน request

Geno ไม่ส่ง `temperature` `top_p` `stop_sequences` หรือ `metadata` ใน request ของ chat
ข้อมูลของ session (โฟลเดอร์ วันที่ git status ไฟล์ `AGENTS.md`) ก็ไม่อยู่ใน `system` แต่อยู่ในข้อความแรกของ `messages`
เหตุผลอยู่ใน[Model รู้ได้อย่างไรว่าต้องทำอะไร](/foundations/how-the-model-knows/)

## request หน้าตาไม่เหมือนกันทุกก้อน

field ชุดเดียวกันนี้ประกอบได้หลายแบบ ตารางนี้นับ request จาก `wire.jsonl` ทั้ง 142 ไฟล์ของการรันจริง (ไฟล์ที่บันทึกไบต์ที่ส่งจริง) แยกตาม model: การรันชื่อ `sonnet-1` ใช้ Claude Sonnet 5.5 การรันอื่นใช้ qwen3.8-flash
คำในตาราง เช่น subagent classifier และ compaction มีคำอธิบายสั้นใน[คำศัพท์](/start/glossary/)

| qwen3.8-flash | Claude Sonnet 5.5 | ลักษณะ | คือ |
| --- | --- | --- | --- |
| 1,033 | 165 | ไม่มี `tool_choice` effort `medium` | การเรียกปกติของ agent |
| 13 | 1 | effort `low` | subagent `explore` |
| 12 | 0 | `tool_choice` บังคับ `verdict` `max_tokens` 400 `temperature` 0 | classifier ของโหมด Auto (การเรียก model แยกที่ตัดสินว่าคำสั่งรันได้ไหม) |
| 8 | 2 | `tool_choice: none` | รอบสุดท้ายที่งบอนุญาต model ต้องตอบโดยไม่เรียก tool |
| 2 | 1 | `tool_choice` บังคับ `report` | subagent ถูกบังคับให้ส่งรายงานกลับ |
| 2 | 2 | ไม่มี `tools` | การเรียกเพื่อสรุปบทสนทนาตอน compaction (ย่อบทสนทนาที่ยาวเกิน) |
| 1 | 0 | ไม่มี `tools` `max_tokens` 1,200 | model ตัวช่วยของ `web_fetch` อ่านหน้าเว็บ |

request ที่บังคับ `report` ของ Sonnet หนึ่งก้อนถูกบันทึกก่อนที่ Geno จะเลิกบังคับ tool กับ Claude 5.5 ตอนนี้ Geno ไม่ส่ง request แบบนั้นให้ Claude แล้ว

request ที่บังคับ `report` เป็นแบบนี้: subagent `explore` ใช้รอบจนเหลือการเรียก model ครั้งสุดท้าย Geno จึงส่ง `tool_choice`
ที่บังคับ tool `report` ทั้งที่รายการ `tools` ยังมีครบ model ตอบได้ทางเดียวคือส่งรายงาน

## รูปแบบเดียว สอง wire

ผู้ให้บริการแต่ละรายรับ request คนละรูปแบบ wire คือส่วนของ engine ที่แปลง request เป็นรูปแบบนั้นแล้วส่งออก
request ข้างบนอยู่ในรูปแบบ Anthropic Messages ซึ่งเป็นรูปแบบภายในของ Geno ทั้งระบบ
"Anthropic wire" ไม่ได้แปลว่า Claude: Model Studio (qwen) OpenRouter Bedrock และ Vertex ก็รับรูปแบบนี้
ผู้ให้บริการที่รับแต่ Chat Completions (OpenAI Gemini DeepSeek Ollama และอื่นๆ) ได้ request ที่ `toChatRequest` ใน `packages/core/src/openai.ts` แปลให้
wire นั้นไม่ส่ง `thinking` `effort` `cache_control` และ `max_tokens` เลย ทุกการรันจริงในตัวอย่างใช้ Anthropic wire
