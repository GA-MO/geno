**tool คือสัญญาที่เขียนเป็นข้อความ** มีสามส่วน: ชื่อ คำอธิบายภาษาคน และ `input_schema` ที่บอกว่า input ต้องหน้าตาอย่างไร
model ไม่ได้ต่อสายเข้าเครื่องของคุณ สิ่งเดียวที่ model ทำได้คือเขียนว่า "ขอเรียก tool ชื่อนี้ ด้วย input นี้" เป็น JSON
ส่วนที่เหลือทั้งหมด ตั้งแต่ตรวจ input ขอสิทธิ์ รัน จนส่งผลกลับ เป็นงานของ Geno

## สัญญาหนึ่งฉบับ

นี่คือ tool `read` ใน `tools` ของ request จริง ตรงกับ `TOOL_SPECS.read` ใน `packages/core/src/tools.ts`

<Payload of={frontmatter.payloads.readTool} />

model อ่านคำอธิบายนี้ทุก request เหมือนอ่านคู่มือ ประโยค "a PNG, JPEG, GIF or WebP file comes back as the image itself" คือเหตุผลที่ model รู้ว่า `read` เปิดรูปได้
และ "After a successful edit the file is current, so do not read it again" กันไม่ให้ model เสีย token อ่านไฟล์ซ้ำ
คำอธิบายที่ดีจึงเปลี่ยนพฤติกรรมของ model ได้จริง โดยไม่ต้องแตะ system prompt

## model "เลือก" tool อย่างไร

ไม่มีกลไกพิเศษ model เขียนบล็อก `tool_use` ในคำตอบ มี `id` `name` และ `input`
แล้วจบคำตอบด้วย `stop_reason: tool_use` ซึ่งแปลว่า "รอผลอยู่"
`loopStep` ใน `packages/core/src/loop.ts` เห็น `tool_use` ที่ยังไม่มีผล จึงตัดสินว่าขั้นต่อไปคือรัน tool
ตัวอย่างคำตอบที่ขอ tool สามตัวพร้อมกันอยู่ใน[Model ตอบกลับอะไรได้บ้าง](/foundations/what-comes-back/)

## tool ที่ส่งแค่ชื่อ: `tool_search`

Geno มี tool หลายสิบตัว ถ้าส่ง schema ครบทุกตัวทุก request จะเปลือง token มาก
`toolRoster` ใน `packages/core/src/deferred-tools.ts` จึงแบ่ง tool เป็นสองกลุ่ม

- **core** ส่ง schema เต็มทุกครั้ง: `agent` `ask_user` `bash` `check` `edit` `glob` `grep` `list` `read` `skill` `todo` (`CORE_TOOL_NAMES`)
- **deferred** ไม่อยู่ใน `tools` แต่ชื่อกับประโยคแรกของคำอธิบายอยู่ในคำอธิบายของ `tool_search` ซึ่งเป็น tool ตัวสุดท้าย
  Geno ใช้วิธีนี้เมื่อประหยัดได้อย่างน้อย 300 token หรือเมื่อมี MCP tool (tool จากโปรแกรมภายนอกที่ต่อกับ Geno ผ่าน MCP) ซึ่ง deferred เสมอ
  แต่ MCP tool ไม่อยู่ในคำอธิบายของ `tool_search` Geno บอกชื่อของมันในโน้ต `[Geno]` เมื่อ server ต่อติด
  คำอธิบายของ `tool_search` จึงไม่เปลี่ยนตามจำนวน server แล้ว model โหลด MCP tool ด้วย `tool_search` แบบเดียวกัน

ในรายการ A05 ผู้ใช้ถามหัวข้อของหน้าเว็บ `web_fetch` เป็น deferred model จึงขอโหลดก่อน

ผลที่ได้กลับมาเป็นข้อความธรรมดาที่มี JSON schema ของ `web_fetch` อยู่ข้างใน

<Payload of={frontmatter.payloads.searchResult} />

สังเกตว่า `tools` ของ request ถัดไปไม่เปลี่ยน schema มาถึง model เป็นข้อความใน `tool_result` เท่านั้น
ทำให้ส่วนต้นของ request ที่ cache ไว้ไม่พัง ถ้า model เรียก deferred tool ก่อนโหลด Geno โหลดให้แล้วรัน call นั้นเลย และแนบ schema ไว้หน้าผล (`autoLoadedText`) ถ้า input ไม่ตรง schema Geno ไม่รัน และตอบ error ที่มี schema ให้ model เรียกใหม่ (`unloadedInputError`)
ผลข้างเคียงหนึ่งคือ qwen เขียนตัวเลขและ boolean ของ tool แบบนี้เป็นสตริง Geno จึงแปลงตาม schema ให้ก่อนรัน (`coerceToSchema`)
ดูทัวร์ [โหลด tool ที่เลื่อนไว้ด้วย tool_search](/scenarios/tool/deferred-tool-load/)

## Geno ตรวจ input ก่อนรันเสมอ

model เขียน JSON ผิดได้ ทุก executor (ฟังก์ชันใน engine ที่รัน tool แต่ละตัว) จึงตรวจ input กับ schema ของตัวเองก่อน (`executor` ใน `packages/engine/src/tools/context.ts`)
ถ้าไม่ผ่าน tool ไม่ทำงาน และ model ได้ error ว่า `invalid input: …`

ตัวอย่างจริงจากรายการ A35 รอบที่ 1 model ส่ง `files` เป็นสตริงที่หน้าตาเหมือน JSON array แทนที่จะเป็น array

model ลองอีกสามครั้ง เปลี่ยน path เปลี่ยน caption และลดเหลือไฟล์เดียว แต่ `files` ยังเป็นสตริงทุกครั้ง จึงได้ error เดิมทุกครั้ง
สุดท้าย model เขียน script รวมสองรูปเป็นรูปเดียวแทน
หลังจากรอบนั้น `parseShowFilesInput` ใน `packages/core/src/show-files.ts` รับ list ที่เขียนเป็นสตริง JSON ได้ด้วย
รอบที่ 3 ของรายการเดียวกันส่ง `files` เป็นสตริงแบบเดิมและรูปขึ้นในแชตได้ นี่คือตัวอย่างของ harness ที่ปรับให้เข้ากับนิสัยของ model

## โหมดปฏิเสธตอนรัน ไม่ใช่ตอนส่ง

Geno มีสามโหมดที่คุณเลือกในแผง

- **Ask** ถามคุณก่อนคำสั่งเสี่ยง
- **Auto** รันสิ่งที่ปลอดภัยเอง และให้ classifier (การเรียก model แยก) ตัดสินคำสั่งที่เหลือ
- **Plan** อ่านอย่างเดียว

ทุกโหมดได้ `tools` ชุดเดียวกันและ system prompt เดียวกัน
โหมด Plan บอก model ผ่านโน้ต `[Geno]` ว่าแก้อะไรไม่ได้ และถ้า model ยังเรียก `edit` Geno ปฏิเสธตอนรัน
ผลที่ได้คือ `tool_result` ที่บอกเหตุผล ไม่ใช่ tool ที่หายไปจากรายการ ดูทัวร์ [โหมด Plan ปฏิเสธคำสั่งและการแก้ไฟล์](/scenarios/perm/plan-refuses/)
